# 統計検定1級 解法定跡カードWeb教材 — 編集規約 v2

## 0. 目的

統計検定1級の

- 統計数理
- 統計応用（理工学）

で、問題を見たときに必要な知識・計算・解法を短時間で再生するための**静的カード型Web教材**を作る。

この教材は百科事典、公式集、用語集、過去問解答集ではない。

最終目標は、

> **頻出する局面 → 打つべき一手 → 実際の数式**

を高速に再生できる「解法定跡集」である。

公式・定義・定理を網羅する正本は `anki/formulae.md`、記法の正本は `references/` および `anki/notation.md` とする。`anki/cards/` は、**本番で能動的に思い出す価値がある解法単位だけ**を収録する。

Anki / AnkiDroid 固有機能、`.apkg`、spaced repetition、Anki専用TSVは実装しない。Markdownを single source of truth とし、静的HTMLを機械生成する。

# 1. 最重要原則

## 1.1 1カード = 本番で1回想起すべき解法単位

旧規約の「1カード = 1単一論点」は次の意味で運用する。

> **1カード = 統計検定1級の小問で、ひとまとまりとして発火させる知識・判断・計算操作**

細かく分けられること自体は、別カードにする理由にならない。

特に、

- formula
- theorem
- condition
- recognition
- reverse
- pitfall

というカード種別の違いだけを理由に、同じ知識を別カードへ分割してはならない。

同じ問題状況を見て同じ一手を使うなら、原則として1つの **canonical card** に統合する。

### 例：変数変換

次を別カードに増殖させない。

- Jacobian の定義
- Jacobian を使う場面
- Jacobian の絶対値
- 逆変換を書く
- support を求める
- Jacobian 忘れが典型ミス

原則として1枚のカードで、

```text
変数変換
↓
逆変換
↓
support
↓
|Jacobian|
↓
元の密度へ代入
```

を具体例で一度動かし、絶対値忘れは「注意」に含める。

---

## 1.2 同じ trigger → 同じ move は1枚

カード作成前に必ず次を問う。

> **このカードの問題を見たとき、既存カードと同じ一手を発火するか？**

YES なら、分野・出典・具体例・カード種別が異なっていても統合を第一候補とする。

過去問で同じ操作が10回現れても10枚作らない。canonical card を1枚残し、頻度・出典を metadata に集約する。

---

## 1.3 1カード1論点。ただし具体例で最後まで一度動かす

カードは単なる用語当てや手法名当てにしない。

悪い例：

```text
和の分布 → 畳み込み
最大値 → CDF
MLE → logを取る
```

良いカードは、単一の解法単位について最低限、

```text
状況を認識する
↓
式を立てる
↓
本質的操作を1回実行する
↓
結論まで到達する
```

ところまで簡単な具体例で確認する。

原則として30秒～数分で復習できる長さとする。

# 2. カード数の設計予算

## 2.1 通常カード総数は 580～620 枚

`anki/cards/` に置く canonical card は、全体で **580～620枚**を正常範囲とする。中心目標は約600枚。

620枚を超えてカードを追加する場合は、原則として既存カードとの

- 統合
- 置換
- archive 移動

のいずれかを同時に行う。

> **カード数を増やすことは coverage の改善ではない。**

カードを増やさずに複数の公式用語・出題パターンを1枚で覆えるなら、その方を優先する。

## 2.2 分野別の初期予算

現行1373枚からの編集監査では、まず次を目安にする。

| 分野 | 目安 |
|---|---:|
| 確率と確率変数 | 70 |
| 種々の確率分布 | 75 |
| 統計的推測（推定） | 110 |
| 統計的推測（検定） | 95 |
| データ解析法の考え方と各種分析手法 | 80 |
| 統計応用（共通事項） | 70 |
| 統計応用（理工学） | 100 |
| **計** | **600** |

これは機械的な quota ではない。分野間で20～30枚程度の移動は許容し、全体の演習価値を優先する。

# 3. `formulae.md` とカードの役割分担

## 3.1 `formulae.md` は知識の網羅

次は原則として `anki/formulae.md` が受け持つ。

- 定義
- 公式
- 定理
- 使用条件
- 分布の基本形
- 参照用の公式一覧

「知っているべきだから」という理由だけでカード化しない。

## 3.2 `cards/` は本番で再生する操作

カード化するのは、主として次のいずれかを満たすもの。

- 問題を見た瞬間に解法選択が必要
- 典型的な計算を素早く再生する価値が高い
- 証明・導出の主要な一手
- 条件を誤ると典型的に失点する
- 過去問で独立した小問として問われる
- 知らないと本番で大きく時間を失う

単なる公式再掲でも、その公式を**即時再生すること自体が得点上重要**ならカード化してよい。ただし短い適用例を含める。

---

# 4. 公式シラバス coverage

公式シラバスは coverage の基準とするが、

> **公式用語1個 = カード1枚**

とはしない。

1枚の canonical card が複数の公式用語を cover してよい。

例：中央値・分位点・四分位範囲を、試験上同じ操作単位として扱えるなら1枚に統合してよい。

`syllabus/coverage.yaml` は「その用語をどのカードで扱うか」を追跡するために使い、カード増殖の根拠にはしない。

各カテゴリー・サブカテゴリーに最低1枚を機械的に置くことより、公式の「ねらい」に対応する**到達行動**が全体として満たされていることを優先する。

---

# 5. カード種別

metadata として次を使用してよい。

```text
formula
theorem
condition
proof_step
calc_step
expansion
recognition
strategy
reverse
pitfall
```

ただし `type` は**分類ラベルであってカード生成単位ではない**。

原則として独立カードにしやすいのは、

- strategy
- calc_step
- expansion
- proof_step
- 高頻度 formula

である。

`condition`, `recognition`, `reverse`, `pitfall` は、canonical card の「条件」「なぜ」「注意」に吸収できないかを先に検討する。

# 6. canonical card の標準構造

すべての欄を機械的に必須化しないが、基本形は次とする。

```markdown
---
id: convolution-independent-sum
title: 独立な連続確率変数の和と畳み込み
category: math-probability
subcategory: math-transformations
topic: convolution
type: strategy
difficulty: 2
priority: S
hashtags:
  - 畳み込み
  - 変数変換
frequency:
  past_exam: 0
  textbook: 0
  independent_problems: 0
  source_confirmations: 0
sources: []
---

## 問題
...

## 答え
...

## なぜ
...

## 計算例
...

## 重要な一手
...

## 条件・注意
...
```

### 具体例の原則

具体例は、そのカードの本質的操作を最低1回実行する。

- 畳み込み：support から積分区間を決める
- 変数変換：逆変換と Jacobian を計算する
- MLE：尤度または対数尤度を立て、必要な微分をする
- CLT：中心化・標準化する
- CRLB：Fisher情報を代入する
- Delta法：$g'(\theta)$ を求めて漸近分散へ入れる
- OLS：係数を実際に計算する

原則10行程度を目安とするが、本質を示すための必要な途中式は省略しない。

# 7. 統合・削除・archive 判定

全カード監査では次の順で判定する。

## 7.1 同じ trigger → 同じ move か

YESなら統合候補。

## 7.2 数値・分布・分野だけを変えた類題か

同じ一般技能を確認するだけなら、代表例1～2枚へ統合する。

例：Delta法を平方根、対数、工学指標ごとに無制限に増やさない。

## 7.3 公式を思い出すだけか

`formulae.md` で十分なら `reference_only` として archive 候補。

## 7.4 condition / reverse / pitfall の派生か

canonical card 本文へ吸収できるなら別カードを削る。

## 7.5 独立小問として自然か

「この内容だけが統計検定1級の小問として出ても自然か？」が NO なら、カード化価値を厳しく見る。

## 7.6 その場で容易に復元できるか

既知の定義から30秒程度で自力復元でき、かつ過去問頻度が低いなら削除・archive 寄り。

## 7.7 他カードを理解すれば自動的に答えられるか

YESなら独立カードにしない。

---

# 8. archive 方針

削減対象を無理に完全削除する必要はない。必要に応じて次へ隔離する。

```text
anki/archive/
├─ duplicates/
├─ low_priority/
├─ too_specific/
└─ reference_only/
```

archive は通常ビルド・通常 coverage・通常カード数に含めない。

可能なら移動したカードに、

```yaml
archive_reason: duplicate
canonical_card: asym-delta-method
```

のように理由と統合先を残す。

Git履歴があるため、明白な完全重複は削除してもよい。

---

# 9. priority の定義

priority はカードを増やす理由ではなく、**600枚の中で残す優先度**を表す。

- **S**：異なる年度の過去問で反復、または本番答案で非常に高頻度のボトルネック。削りにくい。
- **A**：過去問で直接確認できる、または1級で極めて標準的な得点操作。
- **B**：シラバス・教科書上の標準重要論点。残す価値は高いが統合対象になり得る。
- **C**：特殊・低頻度・発展。原則として600枚の余裕を見て採否判断。
- **D**：通常デッキには原則入れず archive 候補。

「他論点の前提」「重要そう」という理由だけで S に昇格させない。

同一 priority 内では、過去問頻度、複数ソース確認、他問題への再利用性、試験時間短縮効果を重視する。

---

# 10. 過去問からの抽出

過去問解答は、

```text
問題設定
↓
step 1
↓
step 2
↓
step 3
```

に分解する。

各 step について、

1. なぜこの一手を選ぶのか
2. 何を見て発火するのか
3. 別問題でも再利用できるか
4. 独立小問として自然か
5. 既存 canonical card で既に cover していないか

を確認する。

**5を通過しない限り新規カードを作らない。**

過去問固有の

```text
2021年問3(2)の答えは？
```

のようなカードは原則禁止し、一般化する。

---

# 11. 重複検出

重複検出は文字列類似だけでは不十分。

比較単位として次を使う。

- trigger：何を見たら発火するか
- move：最初の一手は何か
- target：何を求めるカードか
- 使用公式・定理
- 本質的な式変形
- title / 問題 / 答え / 数式 / hashtags

次のような**意味的重複**を検出する。

```text
一般のDelta法
平方根へのDelta法
工学指標へのDelta法
```

```text
最大値のCDF
最大順序統計量の分布
一様分布の最大値
```

具体例が違うだけなら、代表例へ統合する。

自動削除はせず、`reports/reduction_audit_*.md` に

- keep
- merge
- archive
- delete
- review

の判定を残す。

---

# 12. 頻度と provenance

同じ過去問を複数ブログが解説していても出題回数を増やさない。

```yaml
frequency:
  past_exam: 4
  textbook: 5
  independent_problems: 9
  source_confirmations: 12
```

- `past_exam`：異なる実過去問での登場回数
- `source_confirmations`：同じ事実を確認した独立ソース数

出典は `sources` に追跡可能な形で残す。

---

# 13. 数式・記法・品質

Markdown + KaTeX の共通規約はリポジトリの `CONTENT_GUIDELINES.md` と `references/` を継承する。

最低限、次を確認する。

- support
- パラメータ化
- $n$ / $n-1$
- 自由度
- Jacobian の絶対値
- 条件付き確率の分母
- Fisher情報の正則条件
- 漸近分散
- 行列次元と転置
- 独立と無相関
- 確率収束と分布収束
- MLE の境界解

可能な数値例・積分・行列積・微分は自動検算する。

# 14. Web教材のアーキテクチャ

```text
Markdown cards
      ↓
parser
      ↓
validator
      ↓
数式レンダリング
      ↓
静的HTML生成
      ↓
親ページ + category/search/filter
```

生成HTMLは手編集しない。

理想的な閲覧時依存は、

```text
HTML + CSS + 少量の vanilla JavaScript
```

のみとする。

オフライン閲覧可能であること。数式はビルド時レンダリングを基本とし、外部CDN依存を避ける。

# 15. 編集監査モード

2026-08-29 時点で、既存正本は1373枚まで増加している。

ここからは**新規大量生成フェーズを終了し、編集・統合フェーズへ移行する**。

監査完了までの原則：

1. 新規カード追加を原則停止する。
2. 既存カードを priority 順に600枚へ単純ランキング切りしない。
3. まず意味的重複を canonical skill 単位で統合する。
4. 次に reference-only / too-specific / low-priority を archive する。
5. 580～620枚へ収まった後、公式シラバス coverage と過去問 coverage を再監査する。
6. 欠落が見つかった場合のみ既存 archive の復帰または新規カード作成を行う。

削減中は「1373枚中上位600枚」ではなく、

> **1373枚を素材として約600個の解法単位へ編集する**

と考える。

# 16. カード品質チェック

各 canonical card について最終的に確認する。

```text
[ ] 本番で1回想起すべき単位になっているか
[ ] 同じ trigger → same move の別カードがないか
[ ] 単なる用語当てになっていないか
[ ] formulae.md だけで十分な参照事項ではないか
[ ] 本質的操作を最低1回具体例で実行しているか
[ ] 具体例が別の難問になっていないか
[ ] 条件・support・自由度などを省略していないか
[ ] 数式が正しいか
[ ] provenance が追跡できるか
[ ] priority が過大評価されていないか
[ ] 複数シラバス用語を無意味に別カードへ分割していないか
```

最重要評価基準は次の4点。

### A

> これは統計検定1級の小問または小問中の主要な一手として自然か？

### B

> これを覚えることで、本番で「次に何をすればよいかわからない」時間が減るか？

### C

> このカードを読めば、類題で実際の数式を数行書き始められるか？

### D

> 既存カードを理解していてもなお、このカードを独立して反復する価値があるか？

D が NO なら統合・archive を優先する。

---

# 17. 完成像

```text
問題を見る
    ↓
構造を認識する
    ↓
必要な公式・定理・解法を発火する
    ↓
具体的な式を立てる
    ↓
小問を処理する
```

この目的に寄与しないカードは、内容が正しくても通常デッキから外してよい。

本プロジェクト全体を貫く原則は、

> **1カード1解法単位。具体例で一度動かす。同じ一手は増殖させない。約600枚に編集する。**

とする。

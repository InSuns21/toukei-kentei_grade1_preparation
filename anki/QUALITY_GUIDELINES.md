# Anki canonical card 品質規約

この規約は `../memo/anki.md` のカード編集規約を補足し、特に **計算例・導出・途中式の追いやすさ** を定義する。

削減監査では、カード数を減らすだけでなく、最終的に残す canonical card をこの基準へ揃える。

## 1. 「計算例がある」の意味

`## 計算例` という見出しが存在するだけでは合格としない。

計算例は、そのカードの trigger から move を発火し、少なくとも1回は本質的操作を実行して、結論まで到達する必要がある。

次は計算例として不十分である。

- `n=10 なら自由度9` のように答えへ数値を代入しただけ
- `ν=3 なら χ^2_3` のように定義を言い換えただけ
- `上式へ代入すれば答えを得る` で計算を省略
- `計算すると`、`整理すると`、`同様に` の一言で主要な式変形を飛ばす
- `使用公式・定理` に導出を書き、`計算例` では結果だけ再掲する

定義・recognitionカードでは短い例を認める。ただし、その定義を**判定・照合・適用する行為**を最低1回含める。

## 2. 目で追える数式展開

難度2以上の計算・導出では、読者が前の行だけを使って次の行を再現できる粒度を基本とする。

原則として、**概念上の1操作を1行**にする。

例えば

```latex
\begin{aligned}
\ell(\lambda)
  &= n\log\lambda-\lambda\sum_i x_i,\\
\ell'(\lambda)
  &= \frac{n}{\lambda}-\sum_i x_i,\\
\ell'(\lambda)=0
  &\Longleftrightarrow \widehat\lambda=\frac{n}{\sum_i x_i}
   =\frac1{\overline x}.
\end{aligned}
```

のように、

1. 式を立てる
2. 微分・積分・変形する
3. 方程式を解く
4. 結論を書く

を分ける。

1つの長い表示式に「代入 → 展開 → 約分 → 解く」を4段階以上詰め込まない。

## 3. 省略してよいもの / 省略してはいけないもの

### 省略してよい

- 単純な四則演算
- 既に同じカード内で示した同型計算の反復
- 1級受験者が前行からほぼ機械的に補える整理

### 省略してはいけない

- support・積分範囲が変わる理由
- Jacobian の計算
- 尤度から対数尤度への変形で母数依存項を残す過程
- 微分して尤度方程式を得る過程
- Fisher情報量で期待値を取る過程
- CRLBへ情報量を代入する過程
- CLT の中心化・標準化
- Delta法の導関数と漸近分散への代入
- 自由度が減る理由
- 回帰の正規方程式・平方和分解の主要部分
- AR/MA の自己共分散方程式、特性方程式、定常性判定の主要部分
- 条件付き分布で分母が何になるか

これらはそのカードの move 自体なので、`計算すると` で隠してはならない。

## 4. 手法別の最低ライン

### 畳み込み

```text
support の共通範囲
→ 積分区間
→ 畳み込み積分
→ 積分
→ 得られた密度の support
```

### 変数変換

```text
逆変換
→ Jacobian
→ 変換後 support
→ 元密度へ代入
→ 必要なら周辺化
```

### MLE

```text
尤度または対数尤度
→ 微分
→ 尤度方程式
→ 解
→ 母数空間・境界・最大性の確認
```

### CLT / 正規近似

```text
平均・分散
→ 中心化
→ 標準化
→ 極限分布
→ 確率問題なら元の不等式へ対応
```

### Delta法

```text
元の漸近分布
→ g'(θ)
→ 漸近分散へ {g'(θ)}^2 を掛ける
→ 変換後の漸近分布
```

### Fisher情報量 / CRLB

```text
score または対数尤度2階微分
→ 期待値
→ 1観測から n 観測へ
→ CRLBへ代入
→ 必要なら等号達成を確認
```

### 回帰

```text
目的関数・正規方程式または必要な平方和
→ 代入・解法
→ 推定値
→ 問われていれば標準誤差・検定・区間
```

### 時系列

```text
モデル式
→ 期待値 / 自己共分散 / 特性方程式
→ 必要な連立関係を解く
→ 定常性・ACF・予測などの結論
```

## 5. 難度ごとの期待粒度

- 難度1: 1～3行の適用でもよい。単なる答え再掲は不可。
- 難度2: 少なくとも「式を立てる → 1回操作 → 結論」が見える。
- 難度3: 主要な変形を行単位で追える。暗黙の2段飛ばしを避ける。
- 難度4: 証明・導出の分岐点を文章で補い、式だけのワープを避ける。

行数を増やすこと自体が目的ではない。**迷う箇所だけを省略しない**ことが目的である。

## 6. merge-first の品質規則

重複カード A, B を1枚へ統合するときは、単純に片方を archive する前に次を確認する。

1. A にしかない有益な条件・導出・注意がないか
2. B にしかない追いやすい計算例がないか
3. canonical に両方の長所を吸収できているか
4. 吸収後の canonical がこの品質規約を満たすか

**弱い方を消した結果、残した方も弱い**という統合を禁止する。

## 7. 品質監査の優先度

自動監査では次を目安にする。

- **P0**: 計算例が実質空、または計算カードなのに本質的操作が確認できない
- **P1**: 答えの再掲、長い1行式、主要な式変形の飛躍など、学習上明確な問題がある
- **P2**: 一手・条件・説明の不足など、改善すると追いやすくなる

監査移行中は P0/P1/P2 を report に出し、既存負債のため直ちに全件を CI hard error にはしない。

一度 canonical として品質修正したカードは、以後この規約を満たすことを前提とする。

## 8. 最終チェック

canonical card を残すとき、最低限次を目視する。

```text
[ ] 計算例は答えの再掲ではなく、本質的操作を実行している
[ ] 前の式から次の式を目で追える
[ ] 主要な変形を「計算すると」で隠していない
[ ] support・条件・自由度など結論を左右する情報を落としていない
[ ] 使用公式・定理と計算例の役割が分離されている
[ ] 類題で同じ一手を書き始められる
[ ] そもそも独立カードとして残す価値がある
```

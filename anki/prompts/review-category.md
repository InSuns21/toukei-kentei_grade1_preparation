# Ankiサブカテゴリー作業の独立査読

対象の1〜2サブカテゴリー全体を一つの実施単位として査読する。カード1枚ごとに担当を分けず、別の作業IDの査読記録へ追記しない。

## Anki固有の範囲境界

これはAnkiカードの査読テンプレートである。Ankiは1カード1論点の再生・計算・条件判定を反復する教材なので、次の要件をカード本文や作業成果物に求めてはならない。また、欠けていることを査読指摘にしてはならない。

- 同一設定の4〜6小問をつなぐ連結演習
- 20〜30分で完答する論述演習
- 詳細解答から本番答案への答案圧縮
- 部分点の取り方、部分点構造、撤退基準
- 90分・5問提示・3問選択の問題選択戦略

これらは通常章のLevel C/D、30分ドリル、模試で検証する。Ankiの試験適合性は、公式のねらいに対するカードID単位の対応、1カード1論点性、公式・条件・計算・適用・判定技能の充足、重複・過不足・優先度、配信品質で判定する。

通常教材の「読者粒度監査」をそのままAnkiへ持ち込まない。Ankiでは、**数学的完全性**と**カード粒度・自己完結性**を別軸で判定する。数学上必要な条件を補うことと、1カードへ複数論点を詰め込むことは同じではない。

## 共通確認

- `references/notation-guide.md`、`references/distribution-notation-guide.md`、`references/terminology-guide.md`、`CONTENT_GUIDELINES.md`、`anki/notation.md`、`anki/formulae.md`、`anki/syllabus/syllabus.yaml`、`anki/syllabus/coverage.yaml`、対象サブカテゴリー群の追加カードを読む。
- `anki/notation.md` はAnki固有の差分であり、共通記号・分布・用語の正本を再定義するファイルではない。一般記号は `references/notation-guide.md`、分布の台・母数化・確率質量関数・確率密度関数は `references/distribution-notation-guide.md`、用語・略語は `references/terminology-guide.md` を正本とする。
- 各カードが1論点で、そのカードの論点に必要な公式・定理・条件をカード内へ再掲し、具体例を結論まで計算しているか確認する。共通正本へのリンクだけでカードを成立させない。
- 分布記号を使うカードでは日本語の分布名が書かれているか確認する。
- 非自明な式展開を目で追え、結果だけを突然提示していないか確認する。ただし、そのカードの標的技能でない既習の反復計算まで無制限に展開するよう要求しない。
- サブカテゴリーがWeb上で日本語表示されるか確認する。
- `npm run anki:validate` と `npm run validate` を実行する。

## 監査軸の分離

### 数学的完全性

- 全カードの定義、公式、数値、微分、積分、行列計算、確率、条件を独立に再計算する。
- 台、母数範囲、存在条件、可逆性、正定値性、次元、近似条件、検定の帰無分布など、式が成立するために必要な条件を確認する。
- 「公式シラバスの用語例にない」「専門的に見える」という理由だけで数学用語を削除しない。共通正本、`anki/formulae.md`、前提となる既存カード群で定義・定着済みなら使用を認める。
- 数学的欠落を見つけても、1枚のカードへ一般論を大量追加することだけを修正案にしない。対象カード内の最小補足、前提カードの追加・修正、`anki/formulae.md`、共通リファレンスのどこに置くべきかを判断する。

### カード粒度・自己完結性

- 1カード1論点を守りつつ、そのカード単体で問われた操作を再生できるか確認する。
- 既習の用語そのものは使ってよいが、そのカードを解くために必要な式・条件まで外部参照へ追い出さない。
- 未修概念をカード内で新たに導入する場合は、意味または定義 → 必要最小限の式 → 具体的操作、の順で追えるか確認する。
- 数理査読から説明追加要求が出た場合、カード内に足すと2論点化するなら、前提カードや共通正本へ分離する。
- 正しいが短すぎて補完を強いるカードと、説明過多で複数論点化したカードを別の指摘として扱う。

## 試験適合性査読

公式範囲との対応、カード粒度、定跡としての有用性、重複、検索・フィルター、カテゴリー単位の配信、1ページ200枚以下、9インチ級タブレット表示を確認する。

### ねらい適合性

- 対象サブカテゴリーに対応する `syllabus.categories[].aims[]` の公式「ねらい」全文を明記し、その「理解する」「計算できる」「適用できる」「出力結果を解釈できる」などの到達行動ごとに、対応するカードIDと学習者が実行する操作を示す。
- 公式用語を掲載しただけで、ねらいが要求する計算・選択・適用まで練習できない場合は不足として指摘する。
- 対象作業だけではカテゴリー全体のねらいを完結できない場合、今回が担う部分と後続サブカテゴリーが担う部分を区別する。後続予定を、今回必要な基礎技能の欠落を許す理由にはしない。

### 知識充足性

- 対象サブカテゴリーの `syllabus.items[].terms` を一つずつ取り上げ、単なる語の掲載ではなく、合格に必要な定義再生・公式選択・計算・条件判定のどれをどのカードIDが担うか対応表を作る。
- 代表カードがない公式用語は、隣接カードや `anki/notation.md`、`anki/formulae.md`、共通リファレンスだけで試験時の操作まで再生できるか判定する。できなければ不足として指摘する。
- 公式用語外でも過去問の小問に不可欠な橋渡し技能が欠けていないか確認する。枚数が目安内であることだけを合格根拠にしない。

### 過不足

- `progress.yaml` の `target.min`〜`target.max` と実際の新規枚数を比較する。
- 同じ問い・公式・計算を言い換えただけの重複、試験合格への寄与が低い過剰な細分化、1枚への詰め込みすぎをカードID付きで示す。
- 目安外、または目安内でも知識不足・過剰がある場合は major とし、必要な追加・統合・削除案を示す。

### 優先度根拠

## 優先度の意味

- **S**：最優先。過去問対応・他論点の前提として先に固める
- **A**：重要。Sの次に完成させたい
- **B**：標準～周辺。S/A完成後に進める
- **C**：低頻度・発展寄り。最後でよい

- 対象カードを全件確認し、`priority` が一律の仮置きになっていないか、S/A/B等の差が過去問対応、他論点の前提性、完成順序、出題の反復、後続問題への依存度に対応しているかをカードID単位で示す。新しい優先度の判断だけを理由に、具体的な出典を必須としてはならない。
- `past_exam` sourceがある場合は、その具体的な過去問IDと `frequency.past_exam` が `references/past-exam-index.yaml` に一致するか確認する。テーマ名が近いだけの場合は直接出題された操作と推測を区別する。
- 全件同一優先度でもよいのは、全件を比較した根拠を示せる場合だけとし、仮置きや根拠なしの一律指定は major とする。

単一カテゴリーが200枚を超える場合、まずサブカテゴリー境界で意味的に分割され、単一サブカテゴリー自体が200枚を超える場合だけ内部で分割されるか確認する。

指摘は fatal / major / minor に分類し、監査種別（数学的完全性／カード粒度・自己完結性／試験適合性）、場所、根拠、再計算または再現手順、修正案を書く。修正後は同じ担当が対象作業単位全体を再査読し、最終行を `fatal: 0 / major: 0 / minor: 0` とする。

査読記録には次の機械可読な行を置き、初回指摘と修正確認の見出しを設ける。同じ担当が再査読し、2つの担当IDを一致させる。

```text
initial_reviewer_id: <担当ID>
initial_reviewed_at: <ISO 8601日時>
final_reviewer_id: <担当ID>
final_reviewed_at: <ISO 8601日時>
```

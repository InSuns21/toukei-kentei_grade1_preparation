# Ankiカテゴリー作業の独立査読

対象カテゴリー作業全体を一つの実施単位として査読する。カード1枚ごとに担当を分けず、別の作業IDの査読記録へ追記しない。

## 共通確認

- `anki/notation.md`、`anki/formulae.md`、`anki/syllabus/syllabus.yaml`、`anki/syllabus/coverage.yaml`、対象カテゴリーの追加カードを読む。
- 各カードが1論点で、使用公式・定理を再掲し、具体例を結論まで計算しているか確認する。
- 分布記号を使うカードでは日本語の分布名が書かれているか確認する。台・母数化・確率関数の正本は `anki/notation.md` とする。
- 非自明な式展開を目で追え、結果だけを突然提示していないか確認する。
- サブカテゴリーがWeb上で日本語表示されるか確認する。
- `npm run anki:validate` と `npm run validate` を実行する。

## 数理査読

全カードの定義、公式、数値、微分、積分、行列計算、確率、条件を独立に再計算する。

## 試験適合性査読

公式範囲との対応、カード粒度、定跡としての有用性、重複、検索・フィルター、カテゴリー単位の配信、1ページ200枚以下、9インチ級タブレット表示を確認する。

単一カテゴリーが200枚を超える場合、まずサブカテゴリー境界で意味的に分割され、単一サブカテゴリー自体が200枚を超える場合だけ内部で分割されるか確認する。

指摘は fatal / major / minor に分類し、場所、根拠、再計算または再現手順、修正案を書く。修正後は同じ担当が対象カテゴリー全体を再査読し、最終行を `fatal: 0 / major: 0 / minor: 0` とする。

査読記録には次の機械可読な行を置き、初回指摘と修正確認の見出しを設ける。同じ担当が再査読し、2つの担当IDを一致させる。

```text
initial_reviewer_id: <担当ID>
initial_reviewed_at: <ISO 8601日時>
final_reviewer_id: <担当ID>
final_reviewed_at: <ISO 8601日時>
```

# DREAM THEATER 証明偏重・教材導線監査

この文書は、証明補完によって本文が「定理 → 証明 → 定理 → 証明」に偏っていないかを継続監査するための一次スクリーニングです。**数学的正しさの監査とは別に、読者が証明を後回しにしても意味・具体例・使い道を追えるか**を対象にします。

機械判定は、人間の教材レビューを置き換えません。証明本数、例・直感・演習の見出し数、折りたたみ対象の本文比率から、優先的に読み直すページを抽出します。P0/P1は人手で必ず本文を読み、単純な見出し追加で解消扱いにしません。

## 監査基準

証明を持つ講義は、原則として次の順序を目標にします。

```text
何が問題か / なぜ必要か
  ↓
最小の具体例・反例
  ↓
定義・定理
  ↓
証明の見取り図（本文に表示）
  ↓
完全証明（折りたたみ）
  ↓
何が分かったか / 何に使うか
  ↓
その場で使う例・演習
```

完全証明は削除しません。ただし、証明を読まないと「その定理が何を言っているか」「なぜ欲しいか」「どう使うか」が分からない構成は教材監査NGです。

### 人手監査からの優先順位

1. **P0: C1** — 証明の量そのものが本文を支配している。
2. **P1: C2 / D1 / D2D / F** — 証明または抽象一般論が具体例・意味付けより先行している。
3. **WATCH: D2C** — 折りたたみだけでかなり改善するが、例の配置をさらに改善できる。
4. **現状OK: B / C / D / D2 / D2A / D2B / D2E / P4** — 完全証明を閉じれば通常本文だけで学習サイクルが成立する。

この結果から、**「証明を追加したページが一律に悪化した」のではなく、証明補完によって弱点が露出したページと、元から導入・例が十分で折りたたみだけで回復するページに分かれる**と判断します。

## 人手レビュー時の判定語

- **FIX-NARRATIVE**: 証明の前に動機・具体例・直感を追加し、証明後に使い道を回収する。
- **FIX-EXAMPLE**: 定理が抽象的なままなので、数値・低次元・有限集合など最小例を追加する。
- **FIX-ORDER**: 定義・定理・証明の順序は正しいが、教材としては一般論が先行しすぎている。具体例から一般化する順へ組み替える。
- **FIX-FOLD**: 実質的な完全証明なのに折りたたみ対象として識別されていない。
- **OK**: 証明を閉じたままでも本文だけで学習サイクルが成立する。

## CIとの役割分担

`npm run validate:proof-folding` は、本文中の明示的な「証明」節が `<!-- proof-start -->` / `<!-- proof-end -->` の外へ露出していないこと、マーカーが対応していること、**次の定理・定義まで誤って証明折りたたみの中へ巻き込んでいないこと**、Pages側に折りたたみレンダラが存在することをブロッキング検証します。

一方、この監査のP0/P1/P2判定は文章の質を完全には機械判定できないため、`npm run audit:proof-pedagogy` で非ブロッキングのレビュー候補を出し、最終判定は人手で行います。

# 通常教材：証明の見せ方と教材導線

この文書は、証明を補完した結果、本文が「定理 → 証明 → 定理 → 証明」の列になってしまうことを防ぐための通常教材向けガイドです。

数学的な厳密さは維持します。ただし、**完全証明を読まないと定理の意味・必要性・使い方が分からない構成にはしません。**

## 1. 基本順序

証明を持つ主要論点は、原則として次の学習サイクルで書きます。

```text
何が問題か / なぜ必要か
  ↓
最小の具体例・反例
  ↓
定義・定理
  ↓
証明の見取り図・核心
  ↓
完全証明（折りたたみ）
  ↓
何が分かったか / 何に使うか
  ↓
その場で使う具体例・演習
```

すべての節に同じ見出し名を機械的に置く必要はありません。重要なのは、証明を閉じた状態でも本文のストーリーが成立することです。

## 2. 完全証明は折りたたむ

教材本文の完全証明は、MarkdownにHTMLを直接書かず、次のマーカーで囲みます。

```md
### 証明の見取り図

ここでは、証明で何を使うか・どこが核心かを本文側で説明する。

<!-- proof-start -->
### 証明

完全証明を書く。
<!-- proof-end -->
```

GitHub Pagesでは `proof-start` / `proof-end` の間が「証明を表示」という折りたたみになります。

演習の `solution-start` / `solution-end` 内は解答全体がすでに折りたたまれるため、さらに `proof-start` / `proof-end` を入れません。

## 3. 折りたたまないもの

次は完全証明そのものではなく、本文の理解に必要なので原則として表示したままにします。

- 証明の見取り図
- 証明の考え方
- 証明の核心
- 1〜3行程度の、その場の簡単な確認
- 定理を使うための仮定確認
- 反例や具体例から得られる直感

したがって「証明を全部隠す」のではなく、**長い論理確認だけを後回しにできる**構造にします。

## 4. 監査NGの典型

次は教材導線としてNGです。

- 定理を述べた直後に完全証明へ入り、その定理が何に必要かを後でしか説明しない。
- 1ページに複数の定理と完全証明が続くのに、具体例がほぼない。
- 抽象定義を一般形で置き、低次元・有限集合・数値例を一度も触らない。
- 「証明したから説明も済んだ」扱いにする。
- 証明の中にしか直感・使い道・重要な例が書かれていない。

## 5. CIと人手監査

`npm run validate:proof-folding` は次をブロッキング検証します。

- 明示的な `証明` / `Proof` 節が `proof-start` / `proof-end` の外に露出していない。
- proof marker が対応しており、入れ子になっていない。
- solution block 内へ不要な proof block を入れていない。
- Pages側に proof marker を折りたたむランタイムが存在する。

文章の教育的な順序は完全には機械判定できないため、`npm run audit:proof-pedagogy` で証明偏重の候補を抽出し、人手で読み直します。

## 6. 判定の最終基準

ページを開き、すべての完全証明を閉じた状態で読んだときに、読者が次へ答えられることを完成条件とします。

1. この定理は何を言っているか。
2. なぜこの定理が欲しいか。
3. 最小の具体例では何が起きるか。
4. どの仮定が重要か。
5. この後どこで使うか。

この5点が証明を開かないと分からないなら、証明の有無とは別に教材化が不足しています。

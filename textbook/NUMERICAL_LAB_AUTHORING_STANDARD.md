# NUMERICAL LAB AUTHORING STANDARD

この文書は、PYNUM1 / NUMLAB0–NUMLAB5 のブラウザ内 Python ラボを執筆・改稿するときの正本である。

NUMLAB0 は実行基盤の読者向け説明、本文書は執筆規約を担当する。

---

## 1. 適用範囲

- **PYNUM1**: Python / NumPy のクイックスタート。完成コードを自由編集する `free` ラボを許す。
- **NUMLAB0**: ランタイム・保存・timeout・描画・自動判定の smoke test。完成コードを自由編集する `free` ラボを許す。
- **NUMLAB1–NUMLAB5**: 理論章に対応する数値実験。**`experiment` mode（完成済みコードを条件変更して実行）を基本とし、コード実装を学習目標に明記した場合のみ `exercise` mode（穴埋め）も選べる。**

NUMLAB1–NUMLAB5 は **Python のコードを書く能力を必須の学習目標としない**。完成コードを単に眺める `free` mode は、理論対応の数値実験としては使用しない。読者が理論を使って予測し、条件変更・数値誤差・収束・反例を調べられる `experiment` を採用する。既存の `exercise` ラボは移行中も利用可能とし、全数を無検証で一括置換しない。

## 2. 標準ブロック構成

### 2.1 条件変更型 `experiment`（基本）

学習者は完成済みコードを編集せず、数値条件を変更して結果・図・誤差を比較する。本文に **予測する問い→条件の変更→観測する数値・グラフ→理論に基づく考察・詳細な説明**を配置する。実験コードは理論的な核心計算を実際に行い、単なる固定値の表示にしない。

~~~text
```python-lab
# lab-id: NUMLAB1-NA1-CANCELLATION
# lab-title: 桁落ちの数値検算
# lab-mode: experiment
# timeout-ms: 5000
# lab-param: max_power | 最大の指数 | 16 | 8 | 16 | 1
# lab-param: power_step | 指数の刻み | 4 | 1 | 4 | 1

... 最初から完成している Python の数値計算コード ...
```

```python-test
assert ... 変更可能な条件下でも成立する数値的な性質 ...
```
~~~

- `lab-param` は `Python変数名 | 読者向けラベル | 初期値 | 最小値 | 最大値 | 刻み` の6要素。1〜8個、数値は有限で `min <= 初期値 <= max`、`刻み > 0` とする。条件には問題の定義域や安定性・計算負荷を守る妥当な範囲を設ける。
- 変数は実行時に数値としてコードへ渡し、完成コードは編集不要・参照表示のみとする。`python-test` は隠し、計算結果の構造・恒等式・収束性等を評価する。条件を変えても成立すべき判定を、初期値だけのハードコード値で決めない。
- `python-solution` は置かない。**詳細解答に相当するものは Python コードではなく、本文の「何を観測し、なぜそうなるか」の数理的な説明**とする。
- 自動判定成功は正しい観測を意味しても、実験の解釈の理解や論証力の採点ではない。予測・実験の比較と文章による考察を促す。
- matplotlib を含む計算でも、図だけで判定せず数値結果を併記する。高度な依存を不要に増やさず、実行可能性と負荷を確認する。

### 2.2 コード穴埋め型 `exercise`（コード作成が目的の場合）

コードを補完すること自体が明確な learning objective に含まれる場合は、次の3ブロックを連続させる。

~~~text
language: python-lab
# lab-id: ...
# lab-title: ...
# lab-mode: exercise
# timeout-ms: ...

# ヒント: この空欄の役割・使う理論・作る量を、答えを直接書かずに示す。
... ___ ...
~~~

~~~text
language: python-solution
... 完成コード ...
~~~

~~~text
language: python-test
assert ...
~~~

役割は次の通り。

- `python-lab`: 学習者が編集する穴埋め初期コード。
- `python-solution`: 模範解答。穴埋め記号を残さない。
- `python-test`: 読者画面では隠す自動判定。学習者コードと同じ実行環境で評価する。

問題文・数式・理論 stable anchor・何を検算するか（`experiment`）または何を埋めるか（`exercise`）の説明は、コードフェンスの直前に通常 Markdown で書く。

## 3. 穴埋めの教育的役割（exercise mode の場合のみ）

穴埋め記号は `___` とする。

穴埋めはコードの機械的な写経ではなく、**理論を数値計算へ翻訳する核心操作**に置く。

良い例:

- Newton 法の更新式
- CG 法の step length / residual / search direction
- CFL 条件を含む時間刻み
- 有限要素の局所剛性行列
- Monte Carlo 標準誤差・制御変量・レベル間結合

避ける例:

- `import numpy as np` の `np`
- 図のタイトルや凡例文字列
- 本質でない配列長
- 単に本文から数字をコピーするだけの箇所
- 1ラボのほぼ全行を穴埋めにして、プログラム再構成が主課題になる構成

目安として1ラボあたり **1–5箇所程度**とし、learning objective をコードへ移す最小限の穴埋めにする。教育上必要ならこの範囲を超えてよいが、題数・空欄数の水増しはしない。

### 3.1 空欄の直前に局所ヒントを置く

各 `___` の**直前行**には、同じ字下げで `# ヒント:` コメントを必ず置く。

ヒントは、学習者がその空欄へ到達した時点で「何を考える場所か」を局所的に復元するためのものとする。次のいずれかを短く示す。

- その変数・式の役割
- 使う定理・数値計算法・性質
- 作る量の意味
- 行列・ベクトル・残差・誤差などの対象
- 安定側 / 不安定側、更新前 / 更新後など比較の向き

一方、完成式そのもの、数値解そのもの、右辺をほぼ写した擬似解答は書かない。

良い例:

~~~python
# ヒント: Newton 法の一段更新。現在の近似値から次の近似値を作る。
x = ___

# ヒント: 二次収束ならほぼ一定になる誤差比を、連続する誤差列から作る。
quadratic_ratio = ___
~~~

避ける例:

~~~python
# ヒント: x - f(x) / f_prime(x) を入れる。
x = ___
~~~

章冒頭の「穴埋め課題」説明だけでは局所ヒントの代わりにならない。空欄が離れていても、各 `___` の直前で出題意図を読める状態にする。

## 3.2 手動構築と実務 API を分離する

学習対象となるアルゴリズム・構成そのものを NumPy / SciPy 等の高水準 API が1呼び出しで代行できる場合、**ライブラリ直呼びだけを理論対応ラボにしてはいけない**。

原則として次の順に分ける。

1. **手動構築**：理論章で学んだ公式・漸化式・更新則・行列構成を自前で実装する。
2. **実務編**：標準ライブラリの API を使い、手動構築と同じ対象をより短く・堅牢に処理する。
3. 両者の出力・誤差・残差・性質を照合する。

手動構築側が learning objective を担い、実務編は API の使い方と検算を担う。**`experiment` mode では手動構築コードは教材側が完成させる。学習者にそれを書き直させず、入力を変えたときの行列・収束・誤差を検証させる。**

### 分離が必要な例

- Cholesky 分解を学ぶ章で `np.linalg.cholesky` だけを呼ぶ
- 補間公式を学ぶ章で `scipy.interpolate.BarycentricInterpolator` だけを呼ぶ
- Gauss 求積の構成を学ぶ章で `leggauss` だけから節点・重みを得る

### 分離しなくてよい例

学習対象の**下位処理**や**検算**としてライブラリを使う場合は、手動再実装を強制しない。

- Newton 法の各反復で Jacobian 線形系を `np.linalg.solve` で解く
- FEM の時間発展で既に組み立てた線形系を `np.linalg.solve` で解く
- 固有値反復の結果を `np.linalg.eigvalsh` で検算する
- 高次 QMC の桁交互配置を学ぶ実験で、入力点列だけを `scipy.stats.qmc.Sobol` から得る

判断基準は「その API 呼び出しを消すと、learning objective の主要アルゴリズムを自分で再構成する必要が生じるか」である。生じるなら手動構築を先に置く。

## 4. コード穴埋め型の模範解答

`exercise` に限り、`python-solution` はそのままブラウザで実行可能な完成コードとする。`experiment` ではこれを使わず、実験の数理的な解答・解釈を本文に書く。

- starter と同じ数値実験を解く。
- `___` を残さない。
- hidden test を通すだけの別解・ハードコードへすり替えない。
- 本文で説明していない高度な API を模範解答だけに突然導入しない。
- 同じ章の他ラボで Python / NumPy の基礎説明を重複させず、必要なら PYNUM1 へリンクする。

---

## 5. 自動判定

`python-test` は両モードで最終数値だけでなく、可能なら**理論上の構造や性質**を確認する。実験型では可変の入力全域に対して正しい判定か検算する。

優先する判定:

- 構成した節点・行列・離散化が正しい
- 収束次数が理論値へ近い
- 残差・誤差・エネルギーが期待する性質を持つ
- 安定性条件の成立 / 破綻を再現する
- 分散減少・レベル差分散など、比較したい量が実際に改善する

浮動小数点値には `np.isclose` / `np.allclose` など、問題に応じた tolerance を使う。

乱数を使うテストは再現可能な固定乱数生成器を使う。

## 6. UI と進捗

`experiment` mode は読者画面で **数値条件の入力欄 → 実行 → 数値・図の結果**を基本とし、計算用 Python ソースは折りたたみ表示の参照資料にする。コード編集や模範コード貼り付けは要求しない。条件を変更して再実行でき、初期条件に戻せる。条件・実行済み状態は `lab-id` とソースハッシュに結び付けて保存する。入力値の有限性・範囲・刻みをクライアントでも検査し、Python コードへ安全な数値として渡す。

`exercise` mode は読者画面で

~~~text
[穴埋め] [模範解答] [実行結果]
~~~

の3タブへ変換する。

- `___` が残っている間は Python を起動しない。
- 模範解答はシンタックスハイライトして表示する。
- 模範解答を穴埋め欄へ反映できる。
- 実行後は結果タブへ移る。
- 編集内容・完了状態は既存の localStorage 契約を使う。
- `lab-id` は保存キー・台帳キーでもあるため、意味なく変更しない。

## 7. 理論との対応

NUMLAB1–NUMLAB5 の各実験は `textbook/numerical-lab-links.yaml` に登録する。

各レコードは少なくとも、

- theory chapter
- theory stable anchor
- lab chapter
- lab stable anchor
- experiment ID

を持つ。

理論章の見出しだけへ曖昧にリンクせず、canonical stable anchor を使う。

## 8. CI 完成条件

Pages validation では少なくとも次を blocking にする。

- `lab-id` の全ページ一意性、`timeout-ms` の範囲、`python-test` の最低1個の `assert`、理論 stable anchor と experiment ID の台帳整合
- `experiment` / `exercise` の正しいモードとブロック順序。NUMLAB1–NUMLAB5 はこのいずれかを使う（`free` は不可）
- **`experiment`**: `python-lab -> python-test`。初期コードが完成済みで `___` がないこと。解答コードブロックがないこと。1〜8個の `lab-param` の変数名・表示名・数値範囲が妥当であること
- **`exercise`**: `python-lab -> python-solution -> python-test`。穴埋め `___` が1個以上、各 `___` の直前行に `# ヒント:` が存在し、模範解答に `___` が残っていないこと
- starter・solution（ある場合）・test が Python として構文解析できること、および変更した数値実験の代表入力で数学的性質が再現すること

CI green は教育品質の十分条件ではない。特に `experiment` のレビューでは「読者が予測できる問いがあるか」「数値・グラフ・誤差が理論へ結び付いているか」「入力を変えても検算が適切か」「観測と論証を混同していないか」を確認する。コード穴埋め型では従来どおりヒント・模範解答の教育的妥当性を確認する。

## 9. 既存 Python ファイルのブラウザ再現実験

MFL5・MFL7–MFL13 のように、独立した検算済み Python スクリプトが先にある章では、`python-file-lab` を使って**元ファイルそのもの**をブラウザ内で実行する。これは `experiment` の数値観察と目的を共有するが、Markdown に埋め込んだコードではなく公開済みの Python ファイルとプリセット引数を使う別実装である。`python-lab` の `experiment` mode と `python-file-lab` は同時に使えるが、数学的な計算の正本を重複作成しない。

~~~text
```python-file-lab
# lab-id: MFL9-ISOMAP-FILE
# lab-title: Isomap・半径と埋め込み
# lab-file: textbook/volumes/dream_thater/応用系/MFL/MFL9/isomap_lab.py
# lab-dependency: textbook/volumes/dream_thater/応用系/MFL/MFL8/classical_mds_lab.py
# timeout-ms: 15000
# lab-preset: 円弧・近傍半径0.5 | --case arc --radius 0.5 --dim 2
# lab-preset: U字・shortcut | --case u --radius 1.1 --dim 2
```
~~~

- `lab-file` は公開する `.py` のリポジトリルート相対パス、`lab-dependency` は必要なローカル import のファイルパスで、複数行を記述できる。`../` や外部 URL は指定しない。
- `lab-preset` は表示名と引数を `|` で区切る。読者はプリセット選択後、引数欄を自由に調整できる。shell は起動せず、引数は `sys.argv` として渡される。
- `lab-id` はページをまたいで一意にする。`timeout-ms` は 250–60000 とし、無限ループ等は Worker を停止して回復できるようにする。
- 本文には「何を変えると何が分かるか」を記載する。CLI の例はローカル実行用として残してよいが、読者がブラウザで結果を確認できることを先に示す。
- 元の `.py` とテストを正本とし、Markdown へ同じ実装をコピーしない。Pages build の `validate-python-file-labs.mjs` は全プリセットを Python で実行し、ファイルの存在・依存ファイル・メタデータを確認する。
- 出力が JSON の場合、点群・辺・復元座標等の既知フィールドは描画される。それ以外は標準出力のまま表示する。図の有無で数値的正しさを判定しない。
- MFL14以降のスカラー系列図は、`plots: [{title, x_label, y_label, series: [{name, points: [[x, y], ...]}]}]` をJSON出力する。各系列は有限な数値対を2〜500個とし、実測値と理論値は別系列・別凡例にする。折れ線は離散計算点の補助表示で、数値表の代わりにしたり、連続範囲の証明と見せかけたりしない。色だけでなく線種・系列名でも識別可能にする。

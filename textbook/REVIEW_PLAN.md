# 通常教材 粒度・構成レビュー計画

## 目的

通常教材 `textbook/` の既存章を、統計検定1級を独習する読者が**途中を自力で再現できる粒度**へ揃える。

比較基準は文字数ではなく、次の正本に従う。

- `EXERCISE_GUIDELINES.md`: 問題文・詳細解答・本番答案・採点基準
- `textbook/style-guide.md`: 通常教材の読者粒度・説明順
- `references/terminology-guide.md`: 用語
- `references/notation-guide.md`: 記号
- `references/distribution-notation-guide.md`: 分布表記
- `statistical-mathematics/core/40_fisher_information_delta_mle_efficiency.md`: 導出再現性の比較基準

同時に、既存の分割章を `index.md` 1枚へ段階移行し、GitHub Pagesでは1単元1ページで表示する。

## 判定ラベル

- **PASS**: 初見の受験者が意味・定義・仮定・途中計算・結論を追え、問題単体でも必要な記号と設定を読める。
- **EXPAND**: 数学的には正しいが、主要な微分・積分・行列計算・母関数導出などに飛躍がある。
- **REWRITE**: 問題と解答の対応不足、暗記前提、定義不足、用語の過剰な専門化、問題文の記号不足などが章全体にあり、局所追記では直しにくい。

`chapter.yaml` が `reviewed`、または独立数理査読が fatal / major / minor = 0 / 0 / 0 でも、それだけではPASSにしない。**数学的正しさと通常教材としての読みやすさは別判定**とする。

## 1章ごとの確認項目

1. **導入**: なぜ必要か、前提知識、到達点が分かるか。
2. **説明順**: 意味 → 最小の具体例 → 一般式 → 必要な導出、の順になっているか。
3. **定義**: 記号、取り得る範囲、母数範囲、存在条件が明記されているか。
4. **定理**: 定理名だけでなく、必要条件と本問での条件確認があるか。
5. **例題**: 非自明な微分・積分・平方完成・行列計算を飛ばしていないか。
6. **演習配置**: 問題の直後に対応する解答があり、GitHub Pagesでは折りたためるか。
7. **問題文の自己完結性**: 問題だけを切り出しても、確率変数・母数・分布のパラメータ化・新しい統計量・必要な密度式・使用可公式が分かるか。章頭の一括定義だけを理由に省略しない。
8. **詳細解答**: 各小問について「出発点 → 条件 → 途中計算 → 結論」が追えるか。
9. **本番答案**: 詳細解答との差が明確で、得点の核を残しているか。
10. **採点基準**: 主要な導出へ点が割り当てられているか。
11. **通常教材の語彙**: 数学監査・プログラミングの都合だけで専門語を増やしていないか。たとえば変数変換で「逆像・像・枝」を主語彙にしたり、極座標で `atan2` を持ち込んだりしない。
12. **数式・用語**: KaTeX strictで表示でき、共通用語・記号ガイドと一致するか。

## 実行コマンド

```bash
npm run validate
npm run audit:textbook-granularity
npm run audit:terminology
npm run validate:pages
```

粒度監査・用語監査は候補抽出であり、検出件数だけで章を不合格にしない。

## 1ページ移行

- GitHub Pages: 全既存章をビルド時に1ページへ合成する。
- 新規章: `npm run new:chapter -- <ID>` で `index.md` 1枚を作る。
- 既存章: 粒度レビュー時に `index.md` へ内容を統合し、確認後に旧 `00_...md`〜`09_...md` を削除する。
- 旧ファイルへの既存リンクは移行中に確認し、削除前にリンク監査を通す。

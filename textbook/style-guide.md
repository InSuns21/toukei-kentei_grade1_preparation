# 通常教材の執筆スタイルガイド（差分）

通常教材は次の共通正本を継承する。

- 全教材共通規約：[`../CONTENT_GUIDELINES.md`](../CONTENT_GUIDELINES.md)
- 演習・詳細解答・本番答案・採点基準：[`../EXERCISE_GUIDELINES.md`](../EXERCISE_GUIDELINES.md)
- 一般記号：[`../references/notation-guide.md`](../references/notation-guide.md)
- 分布規約：[`../references/distribution-notation-guide.md`](../references/distribution-notation-guide.md)
- 用語・略語：[`../references/terminology-guide.md`](../references/terminology-guide.md)

このファイルには**通常教材だけに必要な構成・表示・運用上の差分**だけを書く。数式記法、用語、分布表記、詳細解答の行間、定理適用、電卓利用などの共通規則はここで再定義しない。

## 1. 読者と到達点

読者は大学初年度の微積分・線形代数を履修済みで、統計検定1級を独習する受験者とする。通常教材は、概念の導入から演習へ段階的につなぎ、最終的に本番で採点可能な答案を書ける状態へ導く。

### 1.1 通常教材本文の説明粒度

通常教材の本文は、統計数理100や理工80の詳細解答とは役割が異なる。数学的に正確であることは必要だが、**厳密性のための専門語を先に置いて読者へ定義を解読させない**。

本文では原則として次の順序を使う。

1. 何を表す量・分布なのかを日本語で説明する。
2. まず2変量・1母数・具体的な数値例など最小の例を置く。
3. その例を一般式へ広げる。
4. 必要なら導出を示す。
5. 公式出題範囲を超える厳密な条件や名称は、必要性に応じて後置または前提章へリンクする。

専門語を使ってよいかは、語感や公式シラバスの用語例だけで決めない。**まず `chapter.yaml` の `prerequisites` と `textbook/dependency-graph.md` を確認し、その概念が前提章で定義・説明済みかを判定する。** 前提章で学習済みの用語は通常教材でも既知として使ってよく、初出箇所では前提章へのリンクを置く。たとえば F0-00 で定義・判定法を学ぶ「正定値」「半正定値」は、後続の多変量正規・重回帰・二次形式で通常語彙として使う。

一方、前提章で未導入の「二乗可積分」「零集合」「退化分布」「特異分布」「精度行列」「行列の平方根」などを、数学監査の都合だけで本文の前提語彙にしない。必要なら、(a) その章で意味から導入する、(b) 共通基礎章へ追加して依存関係を明示する、(c) 発展補足へ退避する、のいずれかを選ぶ。

**統計問題を解くために不要な数学・プログラミング側の専門語も主語彙にしない。** たとえば変数変換では、通常教材の本文を「逆像を列挙する」「像の領域を求める」「各枝を足す」と始めず、「`g(x)=y` を満たす元の `x` を全部求める」「元の範囲を変換後の変数の不等式へ直す」と説明する。極座標は `x=r cos(theta), y=r sin(theta)` と角度範囲を定義すれば足り、`atan2` のようなプログラミング関数名を導入しない。専門名称を補足する場合も、解法を理解した後の括弧書きまたは発展補足へ回す。

**本文には、執筆者側の取捨選択を説明するメタコメントを書かない。** 「〜を覚える必要はない」「試験では〜で十分」「本章の目的ではない」「通常教材では〜まででよい」のような文は置かず、不要な事項は単に本文へ出さない。必要な式・条件・注意点だけを内容として直接記述する。

**問題文の自己完結性も読者粒度の一部とする。** 章頭に分布・記号をまとめて書いたことを理由に、各演習から計算の出発点を消さない。問題だけを切り出しても、確率変数・母数・分布のパラメータ化・新しく定義する統計量・必要な確率密度関数や使用可公式が追える状態を原則とする。詳細は `EXERCISE_GUIDELINES.md` の「問題文の最低記載水準」に従う。

**公式と名称も分けて監査する。** ある公式が統計検定1級の解法上必要でも、その名称暗記まで必須とは限らない。ただし、統計数理100など別教材で同じ式を名前付きで継続利用する場合は、共通基礎で名称を一度定義して教材間の表記を揃える。Schur補はこの扱いとし、F0-00で定義した後、P3-03の条件付き分散共分散行列と統計数理100の対応箇所で同じ名称を使う。

数学監査と読者粒度監査は目的を分離する。数学監査は誤り・仮定漏れ・導出欠落を見つけるが、**監査を通すためだけに通常教材へ一般論を展開しない**。読者粒度監査は「その概念が既習か」「説明順が意味→具体例→一般式になっているか」を見る。数学監査で追加が必要と判定された内容も、本文・前提章・補足のどこへ置くかは読者粒度監査と合わせて決める。

## 2. 1単元1ページ

新規章は `index.md` 1枚を本文の正本とし、導入・定義・定理・例題・演習・詳細解答・本番ドリルを別Markdownへ分離しない。

演習は原則として次の順に置く。

1. 問題
2. `<!-- solution-start -->`
3. 詳細解答・本番答案・採点基準
4. `<!-- solution-end -->`
5. 次の問題

GitHub Pagesではsolution marker間を折りたたみ表示する。Markdown自体には通常のMarkdown・KaTeXとして解答を書き、折りたたみのためだけに本文へHTMLを手書きしない。

旧 `00_overview.md`〜`09_past_exam_practice.md` 形式は移行期間中のみ許容する。Pagesでは1ページへ合成し、既存章は粒度レビュー時に `index.md` へ統合する。

## 3. 章の標準構成

通常の統計章は、冒頭を次の順序で統一する。

1. `# 章ID 章名`
2. 章の役割を1〜2段落で説明する。
3. 共通スタイル・演習・記号・用語・分布ガイドへの参照を置く。
4. `## この章で解けるようになる問題`
5. `## 公式出題範囲との対応`
6. `## 前提知識チェック`
7. `---`
8. 本文の最初の節

「この章の到達点」「学習目標」「学習順序」など、同じ役割の見出しを章ごとに別名で増やさない。「この章で解けるようになる問題」に統合する。学習進捗用の合格基準は本文導入へ置かない。

Markdownの見出し階層は、章タイトルだけをH1 (`#`) とし、本文の主要節をH2 (`##`)、その下をH3 (`###`) とする。主要節ごとにH1を繰り返さない。

本文全体は原則として次の流れを使う。

1. 概念の意味と最小の具体例
2. 定義と記号
3. 定理・公式と意味
4. 導出または証明
5. 典型例題
6. 演習
7. 本番ドリル
8. 章末チェック

定義・一般式・証明を連続して先に並べるのではなく、読者が式の意味を具体例で確認できるようにする。同じ説明を複数章へコピーせず、共通の基礎事項は正本となる章へまとめてリンクする。

F0-00のような数学速習・案内章は通常の統計章と役割が異なるため、この冒頭テンプレートの例外としてよい。レビュー済み章を再確認するときは、本文だけでなくこの冒頭構成の有無・順序・見出し階層も確認する。

## 4. 問題レベル

通常教材では次のレベルを使う。

- Level A：5〜10分の単一技能。
- Level B：10〜15分の2〜3小問。
- Level C：20〜30分、4〜6小問の本番標準。
- Level D：30〜45分、理解を深める発展問題。

標準配分は A 20%、B 25%、C 45%、D 10% とする。Level Cは原則として公式過去問の大問より少し短い計算量にする。

解答そのものの粒度、途中式、定理適用、採点基準は `EXERCISE_GUIDELINES.md` に従う。

## 5. 過去問との接続

Level C/Dと30分ドリルは、可能な範囲で一つの設定を複数小問へ連結し、単発技能だけに切り縮めない。

各章の `chapter.yaml` に `past_exam_alignment` を置き、年度・科目・大問ID、テーマ、現在の章で担当する技能、後続技能を記録する。実過去問は問題文・図表を転載せず、公式公開PDFまたは公式問題集を参照させる。

未修単元へ接続する小問は「先取り」または「後続章で再挑戦」と明示する。

## 6. 通常教材固有のメタデータ

各問題には、通常教材の検索・進捗管理に必要な範囲で安定ID、Level、目安時間、主題、使用技術、計算量を付ける。

過去問由来の構造を使う場合は、出典の年度・問題番号、確認元、確度、変更点を記録する。第三者サイトのテーマ一覧は `third_party_topic_index`、公式問題・公式問題集を直接確認した場合だけ `official_problem` とする。

## 7. validation と audit

通常教材の機械検証は次を使う。

```bash
npm run validate
npm run validate:pages
```

粒度・用語の改善候補は次で抽出する。

```bash
npm run audit:textbook-granularity
npm run audit:terminology
```

validationは壊れた数式・リンク・構造など機械的に判定できる問題を扱い、auditは人間の判断を要する改善候補を非ブロッキングで扱う。共通の判定方針は `CONTENT_GUIDELINES.md` に従う。

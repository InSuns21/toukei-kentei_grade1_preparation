# LVT5-03 直列化・正規化・一致判定の監査

前提講座：[LVT5-02 Lean実行可能仕様のJSON Linesオラクル化](../LVT5-02/index.md)、[LVT5-01 Differential Testing・オラクルの設計](../LVT5-01/index.md)、[LVT3-01 要求を事前条件・事後条件へ](../LVT3-01/index.md)。

前講の [行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) で、Leanの仕様を外部から呼べるようになりました。しかし正しい応答を作っても、比較する側が数値を丸めたり、欠損値を0に置き換えたりすれば、違う結果を同じと判定してしまいます。本講では、比較器自身を検査対象にします。

**ブラウザで実行：** [本講の実行ラボ](../browser-lab.html?chapter=LVT5-03)。Lean Webで純粋な符号化の証明、CodespacesでPythonのJSON比較器を試します。

## 1. 文字列と意味を分ける

直列化は構造化された値を通信・保存可能な文字列やバイト列に変換する操作です。その逆向きに値を取り出す操作が復号です。本講で受理するJSONでは、オブジェクトのキー順や文字列の外側にある構文上の空白は意味を変えません。文字列の中の空白は文字列の一部です。一方、配列の順序、文字列の内容、数値、成功・拒否・エラーの区別は意味を変える場合があります。

例えば次の二行は同じ成功応答を表します。

~~~json
{"id":"a","status":"ok","rest":3}
{ "rest":3, "status":"ok", "id":"a" }
~~~

比較のために表現上の違いを取り除き、意味を保った一つの値へ写す操作を正規化として扱います。どの違いを消してよいかは仕様に依存します。今回の在庫引当では、識別子を大文字化してはいけません。id=a と id=A は別の要求です。配列を並べ替えることも、前講の応答順契約を破ります。

## 2. 意味を失わない符号化

応答を値として扱う前に、成功時の残数と拒否を区別する小さな模型を考えます。残数は非負整数です。$\mathbb N_0=\{0,1,2,\ldots\}$ と書き、Lean の `Nat` に対応させます。既習の [Option型](../LVT1-03/index.md#def-lvt1-03-option) を使い、成功を `some r`（残数 $r$ は非負整数）、拒否を `none` と表します。前講のJSON応答では status がこの区別を担います。some r と none は異なる構成子から作られる値であり、成功して残数0の場合と拒否は異なります。

元の値の集合を $X$、受理する符号の集合を $Y$ とし、符号化の関数 $E:X\to Y$ と復号の関数 $D:Y\to X$ の組を用意します。$x$ は元の値、$E(x)$ はその符号、$D(E(x))$ は復元した値です。符号化した値から必ず元の値が得られることを要求します。ここで復号は受理された符号の集合上の関数であり、通信上の不正な文字列は受理される前に拒否します。

<a id="def-lvt5-03-roundtrip"></a>

<!-- formal-statement-start -->
### 定義（意味保存往復条件）

値の集合 $X$、受理可能な符号の集合 $Y$、関数 $E:X\to Y$ と $D:Y\to X$ を取る。任意の $x\in X$ に対して次が成立するとき、意味保存往復条件を満たすという。

$$
D(E(x))=x.
$$
<!-- formal-statement-end -->

<!-- definition-example-start: def-lvt5-03-roundtrip -->
**定義の確認**　$X$ は `Option Nat` の値全体、$Y$ は成功かどうかを表す真偽値と残数の組のうち、拒否時には残数を0とした集合です。組の第1成分が状態、第2成分が数を表します。

$$
X=\{\text{none}\}\cup\{\text{some}\ r\mid r\in\mathbb N_0\}
$$

$$
Y=\{(\text{false},0)\}\cup\{(\text{true},r)\mid r\in\mathbb N_0\}
$$

符号化 $E$ と復号 $D$ を次のように定めます。

$$
\begin{aligned}
E(\text{none})&=(\text{false},0),\\
E(\text{some}\ r)&=(\text{true},r).
\end{aligned}
$$

$$
\begin{aligned}
D((\text{false},0))&=\text{none},\\
D((\text{true},r))&=\text{some}\ r.
\end{aligned}
$$

$E$ は $X$ の二種類の構成子を尽くし、どちらの符号も $Y$ に入ります。$D$ は $Y$ の互いに重ならない二種類の組を尽くし、結果は $X$ に入ります。したがって両者は指定された集合上の関数です。往復を確認すると、

$$
D(E(\text{none}))=D((\text{false},0))=\text{none},
$$

$$
D(E(\text{some}\ r))=D((\text{true},r))=\text{some}\ r.
$$

後者は任意の $r\in\mathbb N_0$ について成立し、$X$ の全要素を尽くしたので条件を満たします。
<!-- definition-example-end -->

この条件が成り立てば、符号化して比較しても意味の違いを失いません。逆に、区別を落とした符号から元の値を復元することはできません。以下では $z$ も $X$ の任意の値とし、$\iff$ は左右が互いに従うことを表します。

<a id="prop-lvt5-03-roundtrip"></a>

<!-- formal-statement-start -->
### 命題（意味保存往復条件による一致判定）

集合 $X,Y$ と関数 $E:X\to Y$, $D:Y\to X$ が [意味保存往復条件](#def-lvt5-03-roundtrip) を満たすとする。任意の $x,z\in X$ に対し次が成立する。

$$
E(x)=E(z)\iff x=z.
$$
<!-- formal-statement-end -->

**証明の見取り図**　符号が等しければ、両方を同じ関数で復号しても等しい。[意味保存往復条件](#def-lvt5-03-roundtrip) によって元の値を取り戻せます。

<!-- proof-start -->
### 証明

任意の $x,z\in X$ を固定する。$E(x)=E(z)$ を仮定する。$E(x),E(z)$ はともに $Y$ の要素で、$D$ は $Y$ 上の関数なので、等しい引数に同じ値を返す。従って

$$
D(E(x))=D(E(z)).
$$

[意味保存往復条件](#def-lvt5-03-roundtrip) を左辺と右辺にそれぞれ適用すると

$$
x=D(E(x))=D(E(z))=z.
$$

$x=z$ を逆に仮定すると、$E$ は $X$ 上の関数だから $E(x)=E(z)$。両方向が成立する。
<!-- proof-end -->

拒否を0、成功を残数だけで符号化する変異を考えます。none と some 0 はどちらも0になります。もし復号 D が往復条件を満たすなら D(0)=none かつ D(0)=some 0 が必要ですが、二つは異なる値なので不可能です。証明のうち元の値を復元する等号が壊れました。

ここで示したのは模型についての定理です。JSONの解析器、UTF-8の復号、外部の比較プログラムまで証明したことにはなりません。それらも別に検査します。

## 3. JSONの受理範囲を決める

JSONでは整数も小数も数値として書けます。JavaScriptの通常の Number は2進浮動小数点数であり、すべての整数を区別できるわけではありません。安全整数の上限を M=9007199254740991 とし、本講の言語間比較では0から M までの整数だけを受理します。これは前講のLeanの Nat の上限ではなく、比較器で採用する相互運用プロファイルです。

通常の Number は、2進で先頭の1も含めて有効桁を53桁持つ倍精度浮動小数点数です。

$$
M=2^{53}-1=9007199254740991.
$$

$2^{53}$ 以上 $2^{54}$ 未満では、整数部分の2進表示は54桁なので、最下位の1桁を保持できません。この区間で表現可能な整数は2刻みになります。$2^{53}+1$ は $2^{53}$ と $2^{53}+2$ の中間で、最近接・偶数丸め（同距離なら保持される最下位ビットが0の候補を選ぶ）では $2^{53}$ に丸められます。つまり 9007199254740993 と 9007199254740992 は Number へ変換すると同じ値になります。受信後に丸められた値を見ても元の値を判別できません。数値の字句を整数のまま解析してから範囲を検査するか、最初から整数文字列を採用する必要があります。本講のPythonでは整数を浮動小数点数へ変換せず解析します。

応答の受理条件を固定します。キー順は無視しますが、キー名の集合は正確に一致させます。

| status | 必須キー | 各値の条件 |
|---|---|---|
| ok | id, status, rest | id は文字列、rest は0以上M以下の整数 |
| rejected | id, status | id は文字列 |
| error | id, status, code | id は null、code は invalid_request |

さらに、UTF-8は厳密に復号し、重複キー、単独サロゲート（Unicodeの正しい文字を表さない符号位置）、小数・指数表記、NaN、Infinity を拒否します。JSONの数値として合法な 1.0 や 1e0 も、この限定した形式では拒否します。エスケープされた文字と同じ文字の直接表記は、復号後の文字列として比較します。異なるUnicode文字列の正規化や大文字化は行いません。負のゼロは整数値0として許容します。

| 入力の違い | 比較結果 |
|---|---|
| キー順だけ異なる | 一致 |
| rest が0と1 | 不一致 |
| rest が0と false | 後者は形式不正 |
| rest が0と null | 後者は形式不正 |
| rest が0と欠損 | 後者は形式不正 |
| id が a と A | 不一致 |
| 同一キーが2回 | 形式不正 |

Pythonでは bool が int の派生型なので、isinstance(value,int) だけで整数を受理すると true が1として扱われます。型が正確に int であることを検査します。欠損値も辞書の get で0や None に置き換えず、キー集合を検査してから取り出します。

## 4. 比較器を検査する

[観測付き差分検査](../LVT5-01/index.md#def-lvt5-01-observed) で、どの値を比較するかはすでに学びました。本講では、解析・型検査後の全応答を観測値にします。例えば成功応答は (ok,id,rest)、拒否は (rejected,id)、エラーは (error,null,invalid_request) として表せます。先頭の状態が異なれば不一致、状態が同じなら残りの成分が一致するか確認します。ここで $X$ は第3節の形式に適合した解析後の応答値（キー順や空白を区別しない）、$Y$ は上記の三種類のタプルの集合です。$E$ は各応答から状態と必要な成分を取り出す関数、$D$ はタプルから応答値を組み立て直す関数です。例えば識別子 a の残数0の応答は次の往復になります。

~~~text
{"id":"a","status":"ok","rest":0}
  → ("ok","a",0)
  → {"id":"a","status":"ok","rest":0}
~~~

拒否の場合は `("rejected", id)` から id と status の二つだけを、エラーの場合は `("error", null, "invalid_request")` から id、status、code を復元します。各状態で必須キー集合が固定されていて、余分なキーも許されないため、これで全成分が戻ります。三種類は先頭の状態で区別でき、$D$ は $Y$ 全体で一意に定まります。したがって [意味保存往復条件](#def-lvt5-03-roundtrip) が成立し、[意味保存往復条件による一致判定](#prop-lvt5-03-roundtrip) を解析後の応答値に適用できます。元の文字列の空白やキー順を復元する必要はありません。

比較結果は一致・不一致・形式不正の3種類に分けます。形式検査で検出した不正とは別に、予期しない比較器内部の例外、タイムアウト、プロセスの異常終了はハーネスの失敗として扱います。例えば Python の解析器が深すぎる入れ子で停止できず例外を送出した場合は、業務上の拒否に読み替えません。[行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) に従い、応答列では長さと位置ごとの応答の両方を比較します。本講の実装では、まず両列の応答を解析・検査します。形式不正があれば長さの違いより優先して報告し、すべて有効なら正規化したリスト全体の等しさを判定します。Python のリストが等しいためには、長さが等しく、同じ位置の要素がすべて等しい必要があります。`zip` は同じ位置の要素を組にしますが、短い方の列が終わった時点で終了するため、それだけで照合すると欠落が見逃されます。

検査用の期待結果は比較器の出力をコピーせず、手計算と仕様から作ります。次の失敗を意図的に注入すると、どの区別が失われたか分かります。

| 変異 | 反例 |
|---|---|
| 浮動小数点数に変換 | 9007199254740992 と 9007199254740993 |
| 欠損 rest を0にする | 残数0の成功と rest のない成功 |
| 状態を捨てる | 拒否と残数0の成功 |
| id を無視する | a と b の同じ残数 |
| zipだけで比較 | 応答2件と先頭1件だけ |
| キーの重複を許す | rest が0と1の両方を含むオブジェクト |

## 5. LeanとPythonで実験する

[Leanの模型](lab/LvtSerialization.lean) では符号化・復号の往復と一致判定を証明します。コードの `encode`、`decode` は $E,D$ に対応します。ただしコードの復号は第2節の $Y$ より広い `Bool × Nat` 全体に定義され、`(false, r)` は $r$ によらず `none` に写ります。`p.1` と `p.2` は組 `p` の第1・第2成分です。$E$ の出力は常に第2節の $Y$ に属するので、広い定義域でも往復証明は成立します。符号を $y$ とすると、反対向きの $E(D(y))=y$ は、例えば `y = (false, 1)` では成立しません。往復条件が要求する方向と区別しましょう。拒否と残数0の成功を混同する符号化も計算します。[Pythonの監査スクリプト](lab/audit.py) は厳密なJSON比較器を実装し、正しい比較器と6種類の変異に対して、手で決めた反例を実行します。

~~~bash
cd "textbook/volumes/dream_thater/計算系/LVT/LVT5-03/lab"
lake build
lake test
lake env lean LvtSerialization.lean
python3 audit.py
# 意図的に誤った証明
lake env lean Failure.lean
~~~

Leanの固定版は4.35.0です。Lean Webでは純粋な模型を動かせます。Codespacesでは同じソースを固定版で実行し、Pythonの検査も行えます。ログインと利用枠が必要です。正常なPython実行は「LVT5-03: strict comparison and 6 mutants OK」と表示します。誤った証明では、状態を捨てた符号化で衝突する none と some 0 を等しいと主張して失敗します。前講のオラクルを実際に構築して照合するには、同じ lab ディレクトリから次も実行します。

~~~bash
(cd ../../LVT5-02/lab && lake build)
python3 audit.py ../../LVT5-02/lab/.lake/build/bin/lvtOracle
~~~

残数0、最大安全整数から1を引いた値、日本語と改行を含む識別子、拒否、解析エラーを含む4応答を照合し、正常なら LVT5-03: Lean oracle boundary responses OK と表示します。

既習の [在庫引当関数の契約充足](../LVT3-01/index.md#prop-lvt3-01-correct) は業務関数に関する保証でした。本講の往復条件は符号の模型に関する保証です。Pythonの検査は選んだ具体的な境界・変異を検出する証拠です。次講ではこの区別を保ったまま、多数の共通入力に対する差分テストを自動生成します。入力生成器が許容範囲外の整数を作らないようにするだけでなく、範囲外を意図して作る検査も別に設けます。正常な要求と不正な要求の期待結果を混同しないことが重要です。

## 6. 演習と詳細解答

### Level A

### LVT5-03-A01 空白と順序

次の二つのJSON応答を本講の形式で比較せよ。{"id":"a","status":"ok","rest":0} と {"rest":0,"status":"ok","id":"a"}。

- Level: A

<!-- solution-start -->
#### 詳細解答

どちらもキー集合は id, status, rest。id は同じ文字列 a、status は ok、rest は整数0で許容範囲内である。両方を (ok,a,0) に写せるので一致する。キー順は意味に含めない。
<!-- solution-end -->

### LVT5-03-A02 数値境界

残数9007199254740991、9007199254740992、true、1.0 の四つについて受理可否を判定せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

上限 M は9007199254740991。第1値は上限に等しい整数なので受理する。第2値は M+1 なので拒否する。true は真偽値であって整数の型ではない。1.0 は数学的には1に等しいが、本プロファイルが受理する整数字句ではないので拒否する。
<!-- solution-end -->

### LVT5-03-A03 欠損値と状態

{"id":"a","status":"ok"} と {"id":"a","status":"rejected"} を分類せよ。rest が欠けているから同じと考えてよいか。

- Level: A

<!-- solution-start -->
#### 詳細解答

前者の status は ok なのでキー集合に rest が必要である。欠損のため形式不正。後者の status は rejected であり、id と status のみが必要なので正しい拒否応答である。欠損だけを見て同じ状態と判定してはならない。
<!-- solution-end -->

### LVT5-03-A04 エスケープと識別子

JSON上で id が "\u0061"、"a"、"A" の三つについて、他の項目が同一の成功応答である場合の一致関係を求めよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

16進の符号位置 U+0061 は小文字 a を表す（U+0041 は大文字 A）。最初の二つは復号後に同じ文字列となる。A は大文字で異なる文字列なので残りのどちらとも不一致。字句の違いは消すが、識別子の意味の違いは消さない。
<!-- solution-end -->

### Level B

### LVT5-03-B01 別の符号化で往復する

$X$ を `Option Nat` の値全体、$Y=\mathbb N_0$ とする。$E(\text{none})=0$、$E(\text{some}\ r)=r+1$ と定める。$Y$ 全体で復号を定め、符号の一致と元の値の一致が同値であることを示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

復号する符号を $n\in Y$ とし、$D(0)=\text{none}$、$n>0$ では $D(n)=\text{some}(n-1)$ と定める。正の $n$ なら $n-1\in\mathbb N_0$ なので $D$ は $Y$ 全体で $X$ の値を返す。$E$ も両構成子に対して非負整数を返す。

拒否の場合、

$$
D(E(\text{none}))=D(0)=\text{none}.
$$

成功の場合、任意の $r\in\mathbb N_0$ について $r+1>0$ なので、

$$
\begin{aligned}
D(E(\text{some}\ r))
&=D(r+1)\\
&=\text{some}((r+1)-1)\\
&=\text{some}\ r.
\end{aligned}
$$

全要素で [意味保存往復条件](#def-lvt5-03-roundtrip) が成立した。よって [意味保存往復条件による一致判定](#prop-lvt5-03-roundtrip) をこの E,D に適用し、符号が等しい場合も元の値が等しい場合も互いに他方が従う。
<!-- solution-end -->

### LVT5-03-B02 欠落と順序の反例

期待応答列を [(ok,a,3),(ok,b,3)] とする。実際の列が [(ok,a,3)] の場合と [(ok,b,3),(ok,a,3)] の場合について、zipだけの比較と残数だけの比較の欠陥を示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

第1の実際列は長さ1、期待列は長さ2である。zipは第1位置だけを組にして終了する。この位置では全成分が等しいので全組が一致するという誤判定が起きる。両列の応答が形式に適合すると確認した上で長さを調べれば、$1\ne2$ なので検出できる。第2の実際列の長さは2だが、残数列だけを取ると両方 [3,3] になる。全応答では第1位置の id は期待 a、実際 b、第2位置も逆なので不一致である。[行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) は各位置の対応を要求する。

### LVT5-03-B03 数値変換と復号不能

整数 $u=9007199254740992$, $v=9007199254740993$ を最近接・偶数丸めで2進倍精度浮動小数点数へ変換すると同じ値になる。$X=\{u,v\}$、$Y$ をこの変換で得られる値の集合とし、変換を $E:X\to Y$ とする。元の整数を復号する $D:Y\to X$ で、両方の整数を正確に復元するものが存在しないことを示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

$u=2^{53}$、$v=u+1$ である。第3節の53桁の有効桁数から、$v$ の両隣の表現可能な整数は $u$ と $u+2$ であり、$v$ はちょうど中間である。最近接・偶数丸めでは、候補を間隔2の単位で数えると、

$$
\frac{u}{2}=2^{52},\qquad \frac{u+2}{2}=2^{52}+1
$$

であり、左は偶数、右は奇数なので、$v$ は $u$ に丸められる。$u$ 自身は正確に表現できる。従って

$$
E(u)=u=E(v),\qquad v-u=1\ne0.
$$

[意味保存往復条件](#def-lvt5-03-roundtrip) を満たす $D$ があると仮定すると [意味保存往復条件による一致判定](#prop-lvt5-03-roundtrip) により $u=v$ が従い矛盾する。受信後に比較するだけではこの差は回復できない。

### Level C

### LVT5-03-C01 比較器の監査計画

在庫2、数量2、id=a の要求の正しい応答を計算せよ。残数の欠損、型が false、拒否応答、id=b、後続の応答欠落をそれぞれ比較器が検出することを確認する検査を設計せよ。さらに、この検査で保証できる範囲を述べよ。

- Level: C

<!-- solution-start -->
#### 詳細解答

在庫を $s=2$、要求数量を $k=2$、残数を $r$ とする。$0<k$ かつ $k\le s$ なので成功する。[在庫引当関数の契約充足](../LVT3-01/index.md#prop-lvt3-01-correct) の成功時条件は $r+k=s$。代入して

$$
r+2=2,\qquad r=2-2=0.
$$

$r$ は非負整数で、第3節の上限以下でもある。従って正しい応答は {"id":"a","status":"ok","rest":0} である。

1. rest を削除した成功応答はキー集合の相違で形式不正になる。
2. rest を false にした応答は真偽値であり整数でないため形式不正になる。
3. {"id":"a","status":"rejected"} は有効な拒否応答だが、先頭成分 ok と rejected が違うため不一致になる。
4. id=b の成功応答は状態と残数が同じだが文字列 a≠b で不一致になる。
5. 別の要求（在庫2、数量2、id=b）を追加する。この要求も成功して残数0なので、期待列は `[("ok","a",0),("ok","b",0)]`、実際列は `[("ok","a",0)]` とする。両列の全応答は有効だが、長さ2と1が異なるので不一致になる。

対照としてキー順を交換しただけの正しい応答を受理し、一致と判定することも確かめる。[監査スクリプト](lab/audit.py) を実行し、欠損の補完、型混同、状態の削除、idの削除、zipだけの比較を用いた場合にそれぞれ誤判定が起こる理由を追う。

本検査はこれらの具体的反例に関して比較器を検査するものであり、全JSON文字列に対する解析器の正しさや製品の全入力に対する適合性を証明してはいない。[意味保存往復条件による一致判定](#prop-lvt5-03-roundtrip) は抽象的な条件を満たす関数の全称的な結果で、比較器がその条件を満たすかは別の課題である。
<!-- solution-end -->

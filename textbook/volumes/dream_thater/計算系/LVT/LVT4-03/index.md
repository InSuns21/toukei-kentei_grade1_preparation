# LVT4-03 Plausibleによる反例探索

前提講座：[LVT4-02 Property-Based Testingの原理](../LVT4-02/index.md)、[MC2 乱数生成とサンプリング](../../MC/MC2/index.md)（乱数の初期状態と再現性）。

前講では入力列を自分で作り、要求と実装の結果を比較しました。今度は Lean の命題そのものを渡し、命題を偽にする入力を探す Plausible を使います。反例を見つけた後は、同じ失敗を説明できる、より小さな入力を探しましょう。

**ブラウザで実行：** [本講の実行ラボ](../browser-lab.html?chapter=LVT4-03)。反例の再現と証明は Lean Web で、Plausible 固定版を使う探索は Codespaces の端末で実行します（ログイン・利用枠が必要です）。Lean Web の版は固定版と異なる場合があります。

## 1. 証明を始める前に反例を探す

本講では Lean の `Nat` に合わせ、自然数を0を含む非負整数（$\mathbb N_0=\{0,1,2,\ldots\}$）として扱います。$P(n)$ は入力 $n$ に対する命題、$\neg P(n)$（Leanでは `¬ P n`）はその否定を表します。反例とは $P(n)$ が偽となる具体的な入力です。

自然数 $n$ のすべてで $n\le8$ が成り立つと誤って主張したとします。入力0では真、8でも真ですが、9では偽です。Plausible は [性質ベーステスト](../LVT4-02/index.md#def-lvt4-02-pbt) を Lean の命題に対して実行するライブラリです。次の三つを組み合わせます。

- 入力生成：自然数などの型から値を作る。Plausible では `SampleableExt` のインスタンスが生成・表示・縮小可能な代理表現と、それを対象の型の値に変換する方法を提供する。自然数では数値を生成して検査できる。
- 判定：具体的な入力で命題の真偽を調べる。[Leanの決定可能性](../LVT2-01/index.md#def-lvt2-01-decidable) を表す `Decidable` の計算可能な項を用いて、真なら命題の証明、偽なら否定の証明を得られる。
- 命題の検査：Testable のインスタンスが全称量化や条件付き命題などを検査する方法を組み立てる。

例えば $n=9$ を生成すると、$9\le8$ は偽です。任意の自然数について真という主張が成立するなら9に代入しても真になるはずなので、この一つの入力で主張を否定できます。Lean の証明では次のように、全称命題を仮定し、[全称量化の除去規則](../LVT2-02/index.md#def-lvt2-02-forall) によって9を代入して矛盾を導きます。

~~~lean
theorem not_all_small : ¬ (∀ n : Nat, n ≤ 8) := by
  intro h
  have h9 := h 9
  omega
~~~

この定理には乱数がありません。探索は反例を発見する工程で、発見した具体値を使って否定を証明する工程とは異なります。

## 2. Plausible を実行する

Lean 4.35.0 と、同じ版に対応する [Plausible v4.35.0](https://github.com/leanprover-community/plausible/tree/dfa4f38190d07c37e315953e08b90fe2d95b3c24) を使用します。Lake の依存関係はコミットを固定しています。

[SearchPass.lean](lab/SearchPass.lean) には以下の命令があります。

~~~lean
import Plausible

#eval Plausible.Testable.check
  (∀ n : Nat, n < n + 1)
  { randomSeed := some 42, numInst := 100 }
~~~

100は検査の反復回数の設定値（反例発見時は早く終了し、条件付き命題では再試行・棄却もある）、42は乱数生成器の初期状態を決める入力、すなわち [シード](../../MC/MC2/index.md#def-mc2-seed) です。同じ版・生成設定・初期状態・消費順序を固定すれば、[固定された生成契約の再現性](../../MC/MC2/index.md#prop-mc2-reproducibility-contract) により同じ生成列を得られます。自然数は無限集合なので、100件の検査が全件成功しても全自然数の検査にはなりません。表示される Unable to find a counter-example は反例を発見しなかったという報告です。条件付き命題では、これだけで100件すべてが条件を満たしたとは判断できません。上の性質自体を証明するには、任意の自然数を取って次の一行を検査します。

~~~lean
theorem next_larger (n : Nat) : n < n + 1 := by omega
~~~

[SearchFail.lean](lab/SearchFail.lean) は誤った主張を探索します。自然数 $n$ について $n+1=n$ はどの入力でも偽なので、生成に成功した入力は必ず反例です。

~~~lean
import Plausible

example (n : Nat) : n + 1 = n := by
  plausible (config := { randomSeed := some 42, numInst := 100 })
~~~

Found a counter-example! とともに入力と失敗条件を観察します。これはわざと失敗するファイルです。依存パッケージがないというエラーとは区別してください。

重要なのは、固定版の `plausible` タクティクが `Testable.check` の正常終了後に証明ゴールを `admitGoal` で処理することです。固定版の実装では反例発見時はエラーになりますが、反例なしの場合は情報表示、生成不足（Gave up）の場合は警告表示で戻るため、どちらの場合も未証明のゴールが受理され得ます。未証明の主張を証明済みとして使ってはいけません。探索には #eval を優先し、正式な定理には探索と独立した証明を与えます。[Leanの公理依存](../LVT2-08/index.md#def-lvt2-08-axioms) を調べるには、定理名を #print axioms に渡します。sorryAx が含まれる主張は未証明の仮定に依存しています。

生成・判定に必要なインスタンスが不足すれば検査自体ができません。また条件付き命題で条件に合う入力を十分生成できなければ、Gave up という報告になる場合があります。反例なし、生成不足、反例発見、検査不能の四つを区別して記録しましょう。

## 3. 失敗を保存したまま入力を小さくする

例えば12で $n\le8$ が失敗したとき、値を10へ、さらに9へ変更しても失敗します。8へ変更すると成功するので、その変更は失敗の説明には使えません。失敗を保持する小さい入力を探索する操作を反例の縮小と呼びます。ここでは自然数の通常の大小関係で小ささを測ります。$n_i$ は $i$ 回の縮小を受理した直後の値（$n_0$ は初期値）、$k$ は受理した縮小の回数です。候補を試して棄却するだけでは添字を進めません。$k=0$ なら初期値だけの列です。

<a id="def-lvt4-03-shrink-chain"></a>

<!-- formal-statement-start -->
### 定義（反例縮小列）

自然数上の真偽を判定可能な命題を $P(n)$ とする。長さ $k+1$（$k\ge0$）の自然数列 $n_0,\ldots,n_k$ が次の条件を満たすとき、反例縮小列と呼ぶ。

1. 最初の入力について $\neg P(n_0)$ が成立する。
2. 各添字 $0\le i<k$ について $n_{i+1}<n_i$ かつ $\neg P(n_{i+1})$ が成立する。
<!-- formal-statement-end -->

<!-- definition-example-start: def-lvt4-03-shrink-chain -->
**定義の確認**　$P(n)$ を $n\le8$ として列 $(12,10,9)$ を調べます。この命題の否定 $\neg P(n)$ は $n>8$ と同値です。従って条件1は $12>8$ で、条件2は各遷移の厳密な減少と反例の保存を別々に確認します。

$$
10<12,\quad 10>8,
\qquad 9<10,\quad 9>8.
$$

二つの遷移とも条件2を満たします。一方、最後に8を加えると $8\le8$ が真なので条件2を破ります。
<!-- definition-example-end -->

<a id="prop-lvt4-03-shrink-bound"></a>

<!-- formal-statement-start -->
### 命題（反例縮小列の長さの上界）

自然数上の判定可能な命題 $P(n)$ に対する [反例縮小列](#def-lvt4-03-shrink-chain) $n_0,\ldots,n_k$ の任意の添字 $0\le j\le k$ について $\neg P(n_j)$ および次が成立する。

$$
n_j+j\le n_0.
$$

特に縮小の回数は $k\le n_0$ である。
<!-- formal-statement-end -->

**証明の見取り図**　[反例縮小列の定義](#def-lvt4-03-shrink-chain) により、自然数が真に小さくなるたびに少なくとも1減ります。初期値 $n_0$ と列の長さを固定し、添字 $j$ を0から $k$ まで進めながら、失敗の保存と減少量の下界を確認します。

<!-- proof-start -->
### 証明

列と $k$ を固定する。[反例縮小列の定義](#def-lvt4-03-shrink-chain) に従い、$0\le j\le k$ の範囲で帰納法を用いる。

$j=0$ では定義の条件1から反例であり、$n_0+0=n_0$ である。

$j<k$ として $n_j+j\le n_0$ が成り立つと仮定する。定義の条件2より $n_{j+1}<n_j$ で、自然数の差は少なくとも1である。従って $n_{j+1}+1\le n_j$ である。また条件2から $\neg P(n_{j+1})$ が成り立つ。帰納仮定を使うと

$$
n_{j+1}+(j+1)
=(n_{j+1}+1)+j
\le n_j+j
\le n_0.
$$

[Leanの自然数の帰納法](../LVT2-05/index.md#principle-lvt2-05-nat) の有限範囲への適用により、0から $k$ までのすべての添字で成立する。$k=0$ の場合は基底だけで十分である。$j=k$ とすると $n_k+k\le n_0$ であり、$n_k\ge0$ なので $k\le n_0$ となる。
<!-- proof-end -->

実際の縮小器は、型に応じた候補を生成して失敗を再検査します。自然数の例のような尺度を用意すれば、受理した縮小の回数の上界を論じられます。ただし一回の候補生成・判定が終了することは別途必要で、上の命題は Plausible の任意の型に対する実行時間の定理ではありません。ラボの `shrink_step` は帰納段階の不等式、`shrink_bound` は最後の不等式から回数の上界を導く部分を検査します。列全体についての帰納法と反例の保存は上の数学的証明で確認しています。

## 4. 小さい反例と最小反例

$P(n)$ が $n\le8$ のとき、9は反例で、9より小さい自然数はすべて8以下です。従ってこの例では9が全自然数の中で最小の反例です。

しかし縮小器が調べる候補を制限すると、もっと小さい反例が残っていても止まることがあります。例えば10に対して候補を8と6に限定すると、両方で命題が真なので受理できません。それでも9は反例です。候補内でこれ以上縮められないことと、入力全体で最小であることを区別しましょう。

[SearchShrink.lean](lab/SearchShrink.lean) は $n\le8$ の反例探索で、縮小中の候補のトレースを有効にします。実際に表示された反例、縮小回数、シードを記録し、手計算の列 $(12,10,9)$ と同一の順序になるとは仮定しません。得られた値を $n\le8$ に代入して偽であることを再確認します。

前講の [独立一様抽出での反例の見逃し](../LVT4-02/index.md#prop-lvt4-02-uniform-miss) の式は、0〜15のように候補が有限個で、復元して独立一様に選ぶときに使えます。Plausible のサイズ付き生成器に対してその仮定を確認していないなら、100件という数字から見逃し確率を計算することはできません。

## 6. 演習と詳細解答

### Level A

### LVT4-03-A01 具体的な反例

全自然数について $n+1=n$ という主張を、入力0を使って否定せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

0を代入すると左辺は $0+1=1$、右辺は0である。$1\ne0$ なのでこの入力で偽となる。全自然数で等式が成立すると仮定すれば、[全称量化の除去規則](../LVT2-02/index.md#def-lvt2-02-forall) によって0でも成立するはずであり、矛盾する。従って全称命題は偽である。
<!-- solution-end -->

### LVT4-03-A02 反例縮小列

$P(n)$ を $n\le8$ とする。列 $(13,11,9)$ は反例縮小列か。さらに8を付けた場合も判定せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[反例縮小列の定義](#def-lvt4-03-shrink-chain) に従う。13は8より大きいので反例である。11は13より小さく8より大きい。9は11より小さく8より大きい。従ってすべての条件を満たす。8を追加すると $8\le8$ が真であり、最後の遷移で反例を保存できないので反例縮小列ではない。
<!-- solution-end -->

### LVT4-03-A03 生成と判定

自然数の生成器が入力3、8、12を供給した。命題 $n\le8$ の判定結果と反例を答えよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

3と8は8以下なので真、12は8を超えるので偽となる。判定結果は真、真、偽。反例は12である。値の供給は生成器の役割、各値が8以下か調べることは判定器の役割である。
<!-- solution-end -->

### LVT4-03-A04 最初の値と回数

最初の反例が7であり、自然数の通常の大小で厳密に減る反例縮小列を作る。縮小回数が8回になることは可能か。

- Level: A

<!-- solution-start -->
#### 詳細解答

[反例縮小列の長さの上界](#prop-lvt4-03-shrink-bound) に $n_0=7$ を代入すると $k\le7$ である。各縮小は少なくとも1減らすので、8回縮小すると $n_8+8\le7$ が必要だが、$n_8\ge0$ なので $8\le n_8+8\le7$ となり矛盾する。従って不可能である。
<!-- solution-end -->

### Level B

### LVT4-03-B01 反例なしの意味

生成器が0から8までしか供給しないとする。$n\le8$ の検査を100件行うとどうなるか。全自然数についての結論を述べよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

生成された任意の値 $n$ は0以上8以下なので $P(n)$ が真となる。[生成入力列の全件成功条件](../LVT4-02/index.md#prop-lvt4-02-all-pass) により100件の検査は全件成功する。しかし9を代入すると $9\le8$ は偽である。従って全自然数で成立するという結論は誤りであり、成功の理由は生成器の範囲に反例が含まれなかったことである。
<!-- solution-end -->

### LVT4-03-B02 局所停止

$P(n)$ は $n\le8$ とする。初期反例14から候補10を受理した後、10の候補が8と5だけであった。この縮小器はどこで止まるか。全自然数で最小の反例も求めよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

[反例縮小列の定義](#def-lvt4-03-shrink-chain) に従い、14と10は8より大きく、10は14より小さいので最初の遷移は受理できる。8と5は10より小さいが、どちらも8以下なので反例ではない。従ってこの候補集合では10で停止する。一方9は8より大きいので反例であり、9未満の自然数はすべて8以下だから反例ではない。従って大域的な最小反例は9である。候補集合に9が含まれていなかったことが両者の差の理由である。
<!-- solution-end -->

### LVT4-03-B03 上界の適用

$P(n)$ を $n\le8$ とする。初期反例12からの反例縮小列で縮小回数は最大何回か。上界を達成する列も示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

[反例縮小列の長さの上界](#prop-lvt4-03-shrink-bound) を $n_0=12,j=k$ に適用すると $n_k+k\le12$ である。最後の値も反例なので $n_k>8$、自然数であるため $n_k\ge9$ となる。従って

$$
9+k\le n_k+k\le12,\qquad k\le3.
$$

列 $(12,11,10,9)$ は各値が8より大きく、各遷移で1減る。従って3回を達成する。
<!-- solution-end -->

### Level C

### LVT4-03-C01 探索から証明へ

誤った仕様「全自然数の着手番号は8以下」と、正しい命題「任意の自然数 $n$ が9未満であることと8以下であることは同値」を考える。前者が生成範囲0〜8では反証されない理由、縮小後に9が得られた場合の反証、後者の全入力での証明を述べよ。

- Level: C

<!-- solution-start -->
#### 詳細解答

生成範囲0〜8では各入力で前者の命題が真となり、有限検査は成功する。9が生成・縮小で得られた場合は $9\le8$ が偽なので、全称命題を仮定して[全称量化の除去規則](../LVT2-02/index.md#def-lvt2-02-forall) により9に適用すると矛盾する。

後者では任意の自然数 $n$ を固定する。$n<9$ なら、整数の大小関係から $n+1\le9$ なので $n\le8$ となる。逆に $n\le8$ なら $n\le8<9$ より $n<9$ である。両方向を示したので

$$
n<9\iff n\le8
$$

がすべての自然数で成立する。これは [範囲判定の全入力正当性](../LVT4-02/index.md#prop-lvt4-02-correct-range) の根拠になった自然数の境界比較である。前者の探索と後者の証明は別の工程であり、後者はテスト件数に依存しない。
<!-- solution-end -->

次講では条件を満たす入力と満たさない入力をどのように作るかを扱います。

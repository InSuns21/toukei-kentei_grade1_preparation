# LVT5-05 TypeScript：fast-check差分テスト

前提講座：[LVT5-04 Python：pytest + Hypothesis差分テスト](../LVT5-04/index.md)、[LVT5-03 直列化・正規化・一致判定の監査](../LVT5-03/index.md)、[LVT5-02 Lean実行可能仕様のJSON Linesオラクル化](../LVT5-02/index.md)。

前講では在庫引当をPythonで独立実装し、Leanの応答と比較しました。今回はTypeScriptで同じ仕様を実装します。Web APIのような非同期処理では、計算結果そのものが正しくても、別の要求に応答を返すと誤りになります。生成・計算・応答の対応付けを一つずつ調べましょう。

**ブラウザで実行：** [本講の実行ラボ](../browser-lab.html?chapter=LVT5-05)。Lean Webで応答交換の命題を、Codespacesの端末で実際のNode.jsとLean CLIの接続を試します。

## 1. TypeScriptの在庫引当

TypeScriptはJavaScriptに静的な型検査を加えた言語です。Node.jsはJavaScriptをサーバーや端末で実行する環境です。ここでは型注釈を除去して実行できるNode.js 22.16.0を使います。型の注釈だけで外部から届くJSONの値を検査できるわけではないので、実行時にも数値範囲を確認します。

要求は文字列idと自然数stock、qtyを持ちます。在庫を $s$、注文数量を $q$ とし、前講の相互運用範囲に従って $0\le s,q\le M$ とします。

$$
M=2^{53}-1=9007199254740991.
$$

成功条件は $q>0$ かつ $q\le s$ です。[在庫引当関数の契約充足](../LVT3-01/index.md#prop-lvt3-01-correct) に従い、成功時の残数は $s-q$、数量0と在庫不足は拒否です。

Leanでは条件を先に判定します。TypeScriptでは差 $d=s-q$ を先に計算し、$q=0$ または $d<0$ なら拒否し、それ以外なら成功を返します。これはLean関数を呼び出す実装ではありません。数値範囲から $-M\le d\le M$ となり、この範囲の全整数はNumberで正確に表現可能です。従ってこの減算は丸めで符号や残数を変えません。例えば $s=M,q=1$ なら $d=9007199254740990$、$s=1,q=M$ なら $d=-9007199254740990$ となります。

応答には必ずidとstatusを含め、成功時だけrestを付けます。形式不正やプロセス異常を業務上の拒否に変換してはいけません。[意味保存往復条件による一致判定](../LVT5-03/index.md#prop-lvt5-03-roundtrip) に基づく前講の厳密な比較器を、今回もPythonの小さな橋渡しを経由して利用します。JSON.parseだけでは重複キーや整数字句の違いが失われるためです。

## 2. fast-checkで入力を組み立てる

fast-checkは生成した入力に対して性質を反復検査するライブラリです。入力を生成し、失敗を保つように縮小する仕組みをarbitraryと呼びます。fc.integerで安全整数を生成し、fc.recordで要求オブジェクトを作ります。mapは生成済みの値から別の値を構成する操作です。

通常の整数対だけでなく、等号境界、数量0、在庫不足1の枝を作ります。例えば在庫不足1の枝では $0\le s<M$ を生成して $q=s+1$ と置くので、生成結果は必ず範囲内です。正の等号境界は正の整数を生成して両成分へ同じ値を代入します。これは[生成領域と実行集合](../LVT5-04/index.md#def-lvt5-04-generated-domain)の区別を踏まえ、訪れたい領域を構造で指定する方法です。idは空文字列・日本語・絵文字・改行・引用符を含む有限文字集合から構成します。

[実装](lab/differential.ts) の生成器は有限範囲の整数対を作りますが、全組合せを列挙しません。生成枝の選択も独立一様抽出とは限りません。重要な境界は乱数任せにせず固定例でも検査します。

## 3. 非同期実行と応答の対応

Promiseは後で得られる値または失敗を表すオブジェクトです。async関数はPromiseを返し、awaitはその解決を待って値を取り出し、失敗なら例外を伝えます。fc.asyncPropertyを使っても、内部で開始した処理の完了を待たずにtrueを返せば、実際の比較より先に性質が成功してしまいます。fc.assert自体のPromiseも待つ必要があります。

二つの要求を並行して送っても、Promise.allは結果を渡したPromiseの順序で返します。完了順に配列へ追加した結果を入力順として使うと、要求と応答の対応が崩れることがあります。

そこで、二つの入力に対する期待応答を順序付きの組として扱います。応答はid・状態・必要な残数が一致して初めて等しいと判定します。正しい組と交換した組の比較を考えます。

<a id="def-lvt5-05-paired-observation"></a>

<!-- formal-statement-start -->
### 定義（要求順の応答照合）

入力集合 $X$、応答値の集合 $Y$、参照応答関数 $a:X\to Y$ を取る。入力の順序付き組 $(x_1,x_2)$ に対し、実装から得られた応答の順序付き組を $(y_1,y_2)\in Y^2$ とする。要求順の応答照合が成功する条件は

$$
y_1=a(x_1),\qquad y_2=a(x_2)
$$

である。各応答が有効な形式に復号され、同じ意味の値として比較されることを前提とする。
<!-- formal-statement-end -->

<!-- definition-example-start: def-lvt5-05-paired-observation -->
**定義の確認**　入力を id=a, stock=5, qty=2 と id=b, stock=4, qty=1 とする。いずれも正の数量で在庫以下だから成功し、残数はそれぞれ $5-2=3$、$4-1=3$。期待する応答は (ok,a,3), (ok,b,3) の順である。実際にこの順に有効な応答が返れば二つの等式が成立する。逆順なら第1位置でidが a ではなく b となり、第2位置でも b ではなく a となるので失敗する。残数だけを観測すると両方3であり、交換を見落とす。
<!-- definition-example-end -->

<a id="prop-lvt5-05-swap-detection"></a>

<!-- formal-statement-start -->
### 命題（応答交換の検出条件）

任意の集合 $Y$ と二つの値 $u,v\in Y$ に対し、順序付き組の交換を検出できる条件は

$$
(u,v)\ne(v,u)\quad\Longleftrightarrow\quad u\ne v.
$$
<!-- formal-statement-end -->

**証明の見取り図**　順序付き組が等しければ第1成分が等しい。逆に二つの値が等しければ、交換しても組は変わりません。

<!-- proof-start -->
### 証明

まず $u\ne v$ とする。もし $(u,v)=(v,u)$ なら、第1成分を取り出す関数を両辺へ適用すると $u=v$ となり仮定に矛盾する。よって $(u,v)\ne(v,u)$。

逆に $(u,v)\ne(v,u)$ とする。もし $u=v$ なら両方の組は $(u,u)$ になり等しい。これは仮定と矛盾する。従って $u\ne v$ である。
<!-- proof-end -->

[要求順の応答照合](#def-lvt5-05-paired-observation) にこの命題を適用すると、正常な二応答を交換した変異は二応答が異なるとき、かつそのときに限って検出できます。異なるidを必ず作る生成器では応答も異なるので、交換変異の検出を乱数の偶然に任せる必要はありません。逆に完全に同じ応答を交換する例では、観測可能な違いがないため検出できません。

## 4. 実プロセスを比較する

[TypeScriptの実装とテスト](lab/differential.ts) は [行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) に沿い、要求を1行にしてLean CLIへ渡します。終了コード0、空の標準エラー、ちょうど1行の応答を確認します。[比較用スクリプト](lab/compare.py) は前講の厳密な比較器で二応答を検査し、一致か不一致かを返します。形式不正なら非ゼロ終了させます。

正常な性質では await したLean応答と独立のTypeScript応答を全て比較します。二要求は同時に起動しますが、それぞれのPromiseを入力順の配列で管理します。変異では製品側の応答を逆順にして同じ比較を実行します。fc.checkは失敗した入力とseed（乱数系列の初期値）、counterexamplePath（縮小された入力への経路）を返します。入力そのものも保存し、再実行時は両側を改めて計算します。ハーネスの例外を正しい変異検出として扱わないよう、最初の例外を別に保持して探索後に再送出します。

比較が早く成功してしまう誤りも再現します。実験では未解決のPromiseを作り、その後の処理で失敗を観測するようにします。待たずにtrueを返す性質では観測フラグはfalseのままです。Promiseを解決してからawaitすると失敗を観測します。この実験は実行時間の偶然に依存しません。

## 5. 実行と観察

[応答交換の検出条件](#prop-lvt5-05-swap-detection) は [Leanソース](lab/LvtTypeScriptDrt.lean) で検査できます。Lean側は任意の型の順序付き組について命題を証明します。TypeScriptプロセスや外部ライブラリ全体を証明したものではありません。

Codespacesの端末で以下を実行します。ログインと利用枠が必要です。Lean 4.35.0、Node.js 22.16.0、Python 3を使用します。Node.jsは型注釈を除去して実行するため、静的型検査とは別の実験です。[依存指定](lab/package.json) ではfast-checkとその乱数依存の版を固定しています。

~~~bash
cd "textbook/volumes/dream_thater/計算系/LVT/LVT5-05/lab"
lake build
lake test
lake env lean LvtTypeScriptDrt.lean
(cd ../../LVT5-02/lab && lake build)
npm install --ignore-scripts
npm test
npm run discover -- /tmp/lvt-ts-counterexample.json
npm run replay -- /tmp/lvt-ts-counterexample.json
~~~

正常テストは成功し、発見・再実行では異なるidを持つ二応答の交換が報告されるはずです。反例の値や経路は生成器・ライブラリの版に依存するので、保存した具体入力も使います。生成回数と乱数seedを固定しても、別バージョンで同じ経路が得られるとは限りません。

~~~bash
lake env lean Failure.lean
~~~

このコマンドは意図的に誤った等式の証明を拒否します。テストが成功した場合に保証されるのは実際に比較した入力での一致です。全入力の同値性とは区別しましょう。さらに次講では単一入力・独立な二入力だけでなく、前の状態が次の操作に影響する操作列を扱います。

参考：[fast-checkの実行器](https://fast-check.dev/docs/core-blocks/runners/)、[失敗報告と再現](https://fast-check.dev/docs/tutorials/quick-start/read-test-reports/)。

## 6. 演習と詳細解答

### Level A

### LVT5-05-A01 安全整数の減算

$s=M,q=2$ と $s=2,q=M$ の差、応答を求めよ。idはaとする。

- Level: A

<!-- solution-start -->
#### 詳細解答

第1入力では $d=M-2=9007199254740989$、数量は正で差は非負だから成功し、id=a、残数9007199254740989を返す。第2入力では $d=2-M=-9007199254740989$。差が負なので拒否し、id=aを返す。両差の絶対値はM以下であり、安全整数として正確に表現できる。
<!-- solution-end -->

### LVT5-05-A02 境界の生成

在庫不足1の枝で、在庫の上限をMではなくM−1にする理由を説明せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

$q=s+1$ と構成する。$s=M$ なら $q=M+1$ となり相互運用範囲から外れる。$0\le s\le M-1$ なら $1\le s+1\le M$ なので数量は必ず範囲内であり、同時に $q>s$ で必ず在庫不足になる。
<!-- solution-end -->

### LVT5-05-A03 応答の成分

入力が (a,3,1) と (b,3,1) のとき、期待応答と逆順の応答を比較せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

数量1は正で在庫3以下。残数は両方 $3-1=2$。期待する順は (ok,a,2), (ok,b,2)。逆順は (ok,b,2), (ok,a,2)。[要求順の応答照合](#def-lvt5-05-paired-observation) では第1位置のid a と b が異なるので失敗する。第2位置も異なる。残数列だけならどちらも [2,2] なので交換を検出できない。
<!-- solution-end -->

### LVT5-05-A04 待たない性質

比較のPromiseを開始した直後にtrueを返す性質は、比較結果がfalseの場合にも成功するか。

- Level: A

<!-- solution-start -->
#### 詳細解答

成功し得る。async関数であっても比較のPromiseをawaitもreturnもせずtrueを返すと、その関数が返したPromiseはtrueで解決する。比較のPromiseが後からfalseで解決しても、既に返したtrueは変化しない。比較の結果をawaitし、その真偽を性質の結果として返す必要がある。
<!-- solution-end -->

### Level B

### LVT5-05-B01 応答交換の必要十分条件

二つの要求がともに拒否され、idも同じ場合、応答交換を検出できるか。idだけ異なる場合はどうか。

- Level: B

<!-- solution-start -->
#### 詳細解答

同じid=aなら両応答は (rejected,a) である。$u=v$ なので交換前後の組は等しく、[応答交換の検出条件](#prop-lvt5-05-swap-detection) により検出できない。idがa,bと異なるなら $u=(rejected,a)$、$v=(rejected,b)$ である。第2成分が異なるので $u\ne v$。同命題から交換前後の組は異なり、検出できる。
<!-- solution-end -->

### LVT5-05-B02 生成枝と縮小

異なるidを生成するために、同じ文字列tから ta と tb を作る設計を考える。tを空文字列に縮小しても交換変異を検出できることを示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

a,bは異なる一文字なので、共通の接頭辞tを付けても末尾が異なり、taとtbは異なる。tを空文字列にするとidはa,bとなり、依然として異なる。有効な応答は要求のidを保持するため、応答値も異なる。[応答交換の検出条件](#prop-lvt5-05-swap-detection) より交換で不一致になる。従ってこの縮小候補は変異検出を保存する。ただしライブラリが全入力の中から任意の評価関数に関する最小値を必ず返すことまでは従わない。
<!-- solution-end -->

### LVT5-05-B03 失敗の分類

Leanが1行でなく2行を出力した場合、変異検出の証拠にしてよいか。正常な1行を返したがidが期待値と違う場合と比較せよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

前者は[行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) に違反し、どの応答を要求に対応させるか確定できない。ハーネスの異常として例外を報告する。後者は応答が有効な形式であるなら比較を実行できる。例えば期待 (ok,a,2) に対し実際 (ok,b,2) はidが異なるため意味上の不一致となる。ただしその原因が意図した変異か参照モデルのバグかは追加診断が必要である。
<!-- solution-end -->

### LVT5-05-B04 完了順と入力順

要求aを開始した後、要求bを開始し、bが先に完了した。結果を完了時に配列へ追加する方式と、入力順のPromise.allで集約する方式を比較せよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

完了時に追加すると最初にbの応答、次にaの応答が入るため、配列は [bの応答,aの応答] となる。一方 Promise.all([aのPromise,bのPromise]) は各Promiseの結果を元の配列位置に置くため、[aの応答,bの応答] を返す。両要求の応答が異なるなら[応答交換の検出条件](#prop-lvt5-05-swap-detection) により前者の順序誤りを検出できる。なおPromise.allは片方の失敗を拒否として伝えるので、呼び出し側がそれを業務拒否に置換しないことも必要である。
<!-- solution-end -->

### Level C

### LVT5-05-C01 非同期差分検査の設計

idが「日」と「😀」の要求を、それぞれ $s=q=1$ と $s=2,q=3$ で並行実行する。正常応答、逆順変異、生成と再現、例外の扱いを説明せよ。

- Level: C

<!-- solution-start -->
#### 詳細解答

第1入力は数量1が正で在庫1以下だから成功し、$1-1=0$ より応答は (ok,日,0)。第2入力は $2-3=-1$ なので拒否し、応答は (rejected,😀)。入力順の正常な組はこの順に並ぶ。交換変異では第1位置が (rejected,😀) となり、状態とidの両方が異なる。第2位置も違う。[要求順の応答照合](#def-lvt5-05-paired-observation) の二等式は成立しない。

生成器は正の等号境界と在庫不足を構造で作り、idは異なるようにする。asyncProperty内で双方の応答の到着をawaitし、入力順を保って比較する。探索に失敗したときはseed・pathに加え、二入力をJSONで保存する。再実行は保存した入力をLeanとTypeScriptへ再度送り、正常な組が一致し、交換した組が不一致になることを検査する。タイムアウト・形式不正・異常終了は例外として区別する。これは実行された入力の検査であり、全ての非同期スケジュールに対する正当性の証明ではない。
<!-- solution-end -->

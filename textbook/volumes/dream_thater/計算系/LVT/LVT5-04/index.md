# LVT5-04 Python：pytest + Hypothesis差分テスト

前提講座：[LVT5-03 直列化・正規化・一致判定の監査](../LVT5-03/index.md)、[LVT5-02 Lean実行可能仕様のJSON Linesオラクル化](../LVT5-02/index.md)、[LVT4-05 Shrinkingと最小反例](../LVT4-05/index.md)、[LVT3-01 要求を事前条件・事後条件へ](../LVT3-01/index.md)。

前講では、同じ応答を同じと判定できる比較器を用意しました。しかし、人間が選んだ数件だけでは境界条件の誤りを見落とします。今回は Python の実装と Lean の実行可能仕様へ同じ入力を送り、pytest で結果を検査し、Hypothesis に入力生成と反例の縮小を任せます。発見した反例をファイルに保存すれば、次回は乱数を使わずに同じ不具合を再現できます。

**ブラウザで実行：** [本講の実行ラボ](../browser-lab.html?chapter=LVT5-04)。Lean Web では境界の命題を確認し、Codespaces では本物の Lean CLI と Python テストを接続します。

## 1. 同じ仕様を別の計算で実装する

在庫を $s$、注文数量を $q$ と書きます。両者は非負整数（Lean の Nat、すなわち $\mathbb N_0=\{0,1,2,\ldots\}$）です。相互運用のため上限を $M=2^{53}-1=9007199254740991$ とします。

識別子 id は UTF-8 で表現できる Unicode 文字列です。入力は id, stock, qty の三つのキーを持つ JSON オブジェクトで、stock が $s$、qty が $q$ に対応します。

業務上の成功条件と成功時の残数はそれぞれ

$$
0<q\le s,\qquad \mathrm{rest}=s-q
$$

です。数量0や在庫不足は業務上の拒否です。これは [在庫引当関数の契約充足](../LVT3-01/index.md#prop-lvt3-01-correct) と数量0の拒否規則を再利用しています。

Lean 側は数量が正か、数量が在庫以下かを順に判定してから自然数の減算を行います。Python 側では符号付き整数として差 d=s−q を先に計算し、q=0 または d<0 なら拒否し、そうでなければ成功とします。減算が負になる入力でも Python の整数は負の値を表せます。ここで Python の差 $d$ は符号付き整数の差であり、Lean の Nat の減算とは不足時の値が違います。例えば $s=2,q=3$ では Python の $d=-1$ に対し Nat の差は0です。ただし Python が成功する条件は

$$
q\ne0,\quad d=s-q\ge0
$$

です。

$q$ は非負整数なので $q\ne0$ は $0<q$ と同値で、整数の順序で $s-q\ge0$ は $q\le s$ と同値です。

成功時には差が非負なので Lean の Nat の減算とも一致します。拒否時にはどちらも残数を返しません。この順序の違いによって別の実装経路を持ちます。独立実装とは同一関数の呼び出し結果を二度比較することではありません。

例えば id=a, s=3, q=3 では Lean 側は 0<3≤3 を満たすので成功し、残数は3−3=0。Python 側も d=0、q≠0、d<0 は偽なので成功します。どちらも {"id":"a","status":"ok","rest":0} となります。

## 2. 生成する入力の範囲

pytest はテスト関数を収集して実行し、assert が偽なら失敗として報告します。Hypothesis は値を生成する戦略（strategy）を指定し、テスト関数へ多様な入力を渡すライブラリです。@given は戦略から入力を生成して関数を反復実行します。失敗時には入力をより単純な候補へ変えて、失敗が残るかを試します。この縮小の考え方は [失敗の識別条件](../LVT4-05/index.md#def-lvt4-05-failure-signature) と対応します。

[観測付き差分検査](../LVT5-01/index.md#def-lvt5-01-observed) で実行する入力を、どのように選ぶかを考えます。生成器が取り得る入力の集合を、その生成器の生成領域として扱います。生成領域と、有限回のテストで実際に訪れた入力集合を分けます。

以下では $X$ を許容入力全体、$G$ を生成器の出力候補の集合とします。

$n$ を比較回数、$x_i$ を第 $i$ 回（$1\le i\le n$）の入力とします。

$T$ は重複を除いた実行集合です。$\subseteq$ は等しい場合も許す包含関係です。

<a id="def-lvt5-04-generated-domain"></a>

<!-- formal-statement-start -->
### 定義（生成領域と実行集合）

入力集合 $X$ と、生成器が出力可能な入力の集合 $G\subseteq X$ を取る。ある実行で比較された入力を有限列 $(x_1,\ldots,x_n)$（$n\ge0$）とし、全ての $x_i$ が $G$ に属するとする。このとき $G$ を生成領域、集合 $T=\{x_1,\ldots,x_n\}$ を実行集合という。

$$
T\subseteq G\subseteq X
$$

が成り立つ。比較回数が0なら $T=\varnothing$ である。
<!-- formal-statement-end -->

<!-- definition-example-start: def-lvt5-04-generated-domain -->
**定義の確認**　id を a に固定し、一つの入力を数値対 $(s,q)$ で表します。両成分を0,1,2から選ぶ模型では

$$
X=\{0,1,2\}\times\{0,1,2\}
$$

は9組です。生成器が $q=s$ の3組だけを返すなら

$$
G=\{(0,0),(1,1),(2,2)\}.
$$

各組の両成分が0から2の範囲に入るので $G\subseteq X$ です。実際の入力列が $((0,0),(2,2),(2,2))$ なら、第1回は $(0,0)\in G$、第2回と第3回は $(2,2)\in G$ なので、全入力が $G$ に属するという仮定を満たします。重複を除くと

$$
T=\{(0,0),(2,2)\}\subseteq G\subseteq X.
$$

$T$ の要素数は2であり、実行回数3とは異なります。
<!-- definition-example-end -->

在庫と数量を独立な一様乱数で選ぶだけでは、大きな整数範囲で等号境界を引く機会が少なくなります。Hypothesis の生成は一様乱数抽出とは限りません。本講では通常の整数対に加え、s=q、q=0、q=s+1（s<M）を構成して境界を直接生成します。これらの枝に加え、`@example` で重要な境界を明示的に実行するよう指定します。このデコレータは戦略からの抽出とは別に入力を指定します。本講の `test_generated` の明示例はすべて生成領域に入るので、それらを含めた実行集合も生成領域の部分集合です。一般には生成領域外の明示例を追加できるため、その場合は明示例と生成領域の和集合を比較対象の候補集合に取ります。構文不正などを送る別のテストは、この業務入力の実行集合には含めません。

| 分類 | 例 (s,q) | 期待される業務応答 |
| --- | --- | --- |
| 数量0 | (5,0) | 拒否 |
| 正の数量で在庫に余裕 | (5,2) | 成功、残数3 |
| 正の数量で在庫と等しい | (2,2) | 成功、残数0 |
| 在庫不足 | (2,3) | 拒否 |
| 上限 | (M,M) | 成功、残数0 |

生成する id は英字、日本語、改行、引用符、絵文字を含む有限の文字集合から長さ8以下で作ります。長さ0の空文字列も含みます。全Unicode文字列を尽くす生成器ではありません。JSON の構文エラーや負の数量は業務入力とは別の検査として送ります。Lean の復号器が受理するすべてのJSON表現をPython側が実装しているという主張ではありません。

## 3. 反例が生じる条件を計算する

比較の価値を測るため、製品側に意図的な誤り（変異）を一つ入れます。差 $d=0$ も在庫不足と扱うように条件を $d\le0$ に変更します。

数量0は引き続き拒否するので、変異が成功するのは $q\ne0$ かつ $d>0$ のときです。

第1節と同じ整数の比較により、これは $0<q$ かつ $q<s$ と同値です。成功・拒否の区別は [意味保存往復条件による一致判定](../LVT5-03/index.md#prop-lvt5-03-roundtrip) の動機にもなった重要な観測です。

<a id="prop-lvt5-04-boundary-mutant"></a>

<!-- formal-statement-start -->
### 命題（等号境界変異の検出条件）

非負整数 $s,q$ に対し、正常な成功条件を $A(s,q)$、変異の成功条件を $B(s,q)$ とし、それぞれ次の命題とする。

$$
\begin{aligned}
A(s,q)&:\quad 0<q\ \text{かつ}\ q\le s,\\
B(s,q)&:\quad 0<q\ \text{かつ}\ q<s.
\end{aligned}
$$

両条件の真偽が異なることと、$0<q$ かつ $q=s$ であることは同値である。
<!-- formal-statement-end -->

**証明の見取り図**　厳密な不等式 q<s から q≤s が従うので、変異だけが成功することはありません。正常だけが成功する場合を調べます。

<!-- proof-start -->
### 証明

s,q を任意に固定する。B が真なら q<s と q>0 が成り立つ。q<s から q≤s が従うので A も真である。

従って真偽が異なるなら A が真で B が偽である。A より q>0, q≤s。もし q<s なら q>0 と合わせて B が真となり矛盾する。q≤s かつ q<s でないことから q=s を得る。

逆に q=s>0 とする。q≤s なので A は真である。一方 q<s は q<q となり偽なので B は偽である。従って真偽が異なる。以上で同値が成立する。
<!-- proof-end -->

両者が成功するときは同じ id と残数 $s-q$、両者が拒否するときは同じ id と拒否状態を返します。一方だけ成功するときは status が異なるため、前講の [意味保存往復条件による一致判定](../LVT5-03/index.md#prop-lvt5-03-roundtrip) のように状態の区別を保つ比較では異なる値になります。したがってこの応答模型では、成功条件の真偽の不一致と全応答の不一致は同値です。実際のプログラムの入出力処理がこの模型に一致するかは別途検査します。

正の等号境界の中で s+q を最小化すると、q=s≥1 より s+q=2s≥2、等号は s=q=1 で達成します。従って数値対の最小の反例は (1,1) です。Hypothesis が必ず任意の評価関数について大域的最小値を返すという主張ではありません。ここでは縮小候補の結果をこの手計算と比較できます。

## 4. 実際のプロセスを比較する

[Python実装とテスト用ハーネス](lab/differential.py) は前講の [厳密な比較器](../LVT5-03/lab/audit.py) を読み込みます。Python の応答をJSONに変換し、同一入力を Lean CLI の標準入力に送ります。[行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) に従い、標準出力の応答は1件だけ、終了コードは0、標準エラーは空でなければなりません。タイムアウト・件数不正・形式不正は業務上の拒否と区別して失敗にします。

[テスト関数](lab/test_differential.py) は次の三層に分かれます。

- 手で選んだ境界例と期待値を照合する例示テスト。
- @given が生成した入力について正常なPython実装とLean CLIの全応答を比較するテスト。
- find で変異とLean CLIの不一致を探索し、保存・再実行した結果が不一致であることを検査するテスト。

find は指定した戦略の中から条件を満たす入力を探索し、その入力を縮小します。プロセス異常や形式不正な応答は、変異を発見したという真偽値に置き換えず例外として伝えます。ただし形式上正しい `status=error` が業務入力に対して返る場合など、オラクル自体の誤りも不一致を生み得ます。[不一致が示す少なくとも一方の誤り](../LVT5-01/index.md#prop-lvt5-01-disagreement) のとおり、不一致だけでは誤った側は決まりません。`test_discover_and_replay` では正の等号境界であること、Lean の成功・残数0、変異の拒否、正常な Python との一致も別々に確認します。CLI の `discover` 単独はこのすべてを保証するものではありません。探索中に何度も外部プロセスを起動するので、学習用の件数を抑え、各呼び出しにタイムアウトを設けています。

保存する JSON は入力 id, stock, qty に加え、実際に観測した Lean 応答と変異の応答を含みます。再実行では期待値をファイルからそのまま採用するのではなく、保存された入力から双方を再計算して保存時の応答とも照合します。製品の修正後は不一致が解消したことを確認する回帰テストへ転用できます。

[等号境界変異の検出条件](#prop-lvt5-04-boundary-mutant) の成功条件の差を [Leanソース](lab/LvtPythonDrt.lean) で証明します。[固定されたPython依存](lab/requirements.txt) と前講の Lean 4.35.0 を使い、次の手順で実行します。Codespaces ではログインと利用枠が必要です。

~~~bash

(cd ../../LVT5-02/lab && lake build)

~~~

正常なテスト群は成功します。発見・再実行では、正の等号境界で Lean が残数0の成功、変異が拒否を返す内容が表示されます。id の選択や探索順はライブラリの版などに依存し得るので、表示された入力そのものを保存します。テストでは再現しやすい設定 derandomize=True とデータベース無効化を使いますが、これは異なる版でも同じ探索順を保証する設定ではありません。

意図的に誤った Lean 命題は次のコマンドで別に検査します。

~~~bash
lake env lean Failure.lean
~~~

`Failure.lean` は `takeStock ⟨1, 1⟩ = none` の証明を要求しますが、提示する証明項は `takeStock ⟨1, 1⟩ = some 0` の証明です。成功と拒否は異なる値なので、要求された命題と証明項の型が一致せず、証明が拒否されます。正常実装との比較テストが成功しても、実行した集合 $T$ における一致を調べたという事実にとどまります。全入力での一致には、別途全称命題の証明が必要です。

## 6. 演習と詳細解答

### Level A

### LVT5-04-A01 境界の手計算

(s,q)=(0,0),(3,1),(3,3),(3,4) の正常・変異の応答を求めよ。id は a とする。

- Level: A

<!-- solution-start -->
#### 詳細解答

(0,0) は q=0 なので両者拒否。(3,1) は d=2>0 なので両者成功、残数2。(3,3) は d=0、q>0 なので正常は成功、残数0、変異は d≤0 で拒否。(3,4) は d=−1<0 なので両者拒否。全応答にはそれぞれ id=a が含まれる。不一致は第3入力だけである。
<!-- solution-end -->

### LVT5-04-A02 生成と実行

G={(1,1),(2,2),(3,3)} から (2,2),(2,2),(3,3) を実行した。T と実行回数を求めよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[生成領域と実行集合](#def-lvt5-04-generated-domain) より、実際に出た異なる入力の集合は T={(2,2),(3,3)}。T の要素数は2、実行回数は重複を含め3である。(1,1) は G に属するが T に属しない。
<!-- solution-end -->

### LVT5-04-A03 生成する枝

s=0,1,M−1,M のとき、q=s+1 の枝を作ることができるか。

- Level: A

<!-- solution-start -->
#### 詳細解答

q は M 以下である必要がある。s=0 なら q=1、s=1 なら q=2、s=M−1 なら q=M で全て許容範囲。s=M では q=M+1 となり範囲外なので作れない。生成時に s を0から M−1 に限定すればよい。
<!-- solution-end -->

### LVT5-04-A04 エラーと拒否

JSON が途中で切れた入力と、在庫1で数量2の入力を同じ失敗とみなしてよいか。

- Level: A

<!-- solution-start -->
#### 詳細解答

前者はJSONとして解析できず、id=null, status=error, code=invalid_request の応答となる。後者は正しく復号でき、2>1 なので id と status=rejected の業務応答となる。前講の [厳密な比較器](../LVT5-03/lab/audit.py) は status とキー集合を観測する。復号結果の先頭成分はそれぞれ `error` と `rejected` で異なるため、この二つを混同しない。さらにプロセスのタイムアウトなら応答値ではなく検査ハーネスの失敗である。
<!-- solution-end -->

### Level B

### LVT5-04-B01 不一致条件の再構成

正常な成功条件と変異の条件を用いて、s=0 の入力に不一致がないことと、s≥1 の各 s に対して不一致となる q がただ一つあることを示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

[等号境界変異の検出条件](#prop-lvt5-04-boundary-mutant) により、不一致は q=s かつ q>0 に限る。s=0 なら q=s は q=0 を要求し、q>0 と両立しない。s≥1 なら q=s は正なので不一致になる。q≠s なら同命題の必要条件を満たさないので不一致にならない。従って各正の s に対し q=s のただ一つである。
<!-- solution-end -->

### LVT5-04-B02 一様抽出との比較

s,q をそれぞれ0から9までの整数から独立に一様に選ぶ仮想的な生成器を考える。変異を一度の抽出で発見する確率と、独立な2回で少なくとも一度発見する確率を求めよ。Hypothesis の確率と同一視してよいか。

- Level: B

<!-- solution-start -->
#### 詳細解答

各成分の10通りが独立で一様なので、全部で $10\times10=100$ 組が等確率である。[等号境界変異の検出条件](#prop-lvt5-04-boundary-mutant) より $(1,1)$ から $(9,9)$ の9組が失敗する。

1回で発見する確率を $p$ と書くと、

$$
p=\frac9{100},\qquad 1-p=\frac{91}{100}.
$$

2回の抽出は独立なので、両方で発見しない確率は

$$
(1-p)^2=\frac{91^2}{100^2}=\frac{8281}{10000}.
$$

少なくとも一度発見する事象はその余事象であるから、

$$
1-\frac{8281}{10000}=\frac{1719}{10000}=0.1719.
$

これは独立一様抽出という仮定の結果であり、境界枝や縮小を持つHypothesisの生成過程にそのまま適用できない。
<!-- solution-end -->

### LVT5-04-B03 縮小の観測

変異を (8,8) で発見した。候補 (4,8),(4,4),(1,1),(0,0) について失敗を保存するものを判定し、s+q が最小の反例を示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

(4,8) は在庫不足で両者拒否。(4,4) は正の等号境界で失敗を保存。(1,1) も同条件で保存。(0,0) は数量0で両者拒否。[等号境界変異の検出条件](#prop-lvt5-04-boundary-mutant) によれば全ての不一致入力は s=q≥1 だから s+q=2s≥2。(1,1) で2となるので最小である。候補の順序や縮小器の具体的な実行順を指定したわけではない。
<!-- solution-end -->

### Level C

### LVT5-04-C01 再現可能な差分検査

id を改行を含む文字列 "a\nb" とし、s=q=1 の変異を検出するテストを設計せよ。入力、二つの期待応答、保存・再実行、形式不正の扱い、保証範囲を説明せよ。

- Level: C

#### 詳細解答

入力オブジェクトは id="a\nb", stock=1, qty=1。id の値には実際の改行文字が一つある。[行単位オラクル契約](../LVT5-02/index.md#def-lvt5-02-line-oracle) に沿って送信する際は JSON 直列化で改行をバックスラッシュと n の2文字に変換し、末尾に区切りの改行を一つ付けるので、物理行は1行である。正常側は 0<1≤1 より成功し、残数1−1=0。変異は差0を不足と扱うので拒否する。期待応答はそれぞれ {"id":"a\nb","status":"ok","rest":0} と {"id":"a\nb","status":"rejected"}。前講の [厳密な比較器](../LVT5-03/lab/audit.py) で復号したタプル（順序を保つ値の組）は ("ok","a\nb",0) と ("rejected","a\nb") となり、先頭成分が違うため不一致。

入力と両応答を保存する。再実行では入力を復号し、同じLean CLIへ送り、Python変異も再計算する。保存時の二つの応答と再計算結果をそれぞれ比較し、その上で不一致を確認する。たとえば Lean が2行出力した場合は行数契約に反するのでテストハーネスの失敗とし、正しい変異検出として数えない。

正常実装について同入力を実行すれば、Lean と Python の成功・id・残数が一致することを確認できる。これは実行した入力に対する証拠である。[等号境界変異の検出条件](#prop-lvt5-04-boundary-mutant) は抽象的な成功条件について全ての自然数で成立するが、任意のJSON復号や外部プロセスの全挙動、任意の製品バグの不存在は証明していない。

# LVT5-01 Differential Testing・オラクルの設計

前提講座：[LVT4-06 メタモルフィック・変異・カバレッジ](../LVT4-06/index.md)、[LVT3-01 要求を事前条件・事後条件へ](../LVT3-01/index.md)、[LVT1-01 テストと形式証明は何を保証するか](../LVT1-01/index.md)。

前講では一つの実装の変換関係や変異に対する検出能力を調べました。今度は、手で期待結果を一件ずつ用意する代わりに、別に作った実行可能な仕様から結果を得て製品と比べます。何を比較し、どの結果を信頼し、何を証明する必要があるのでしょうか。

**ブラウザで実行：** [本講の実行ラボ](../browser-lab.html?chapter=LVT5-01)。Lean の計算・証明と意図的な失敗を試せます。Python との比較は同じラボから Codespaces の端末を開いて実行します。

## 1. 同一入力で二つの実装を動かす

[差分テスト](../LVT1-01/index.md#def-lvt1-01-differential-test) は共通の入力で二つの関数を走らせ、結果が一致するか調べる手法でした。期待結果を供給する仕組み（テストオラクル）には、ここでは [実行可能仕様](../LVT1-01/index.md#def-lvt1-01-executable-spec) を使います。

例として在庫引当を使います。[在庫引当仕様](../LVT3-01/index.md#def-lvt3-01-order) では在庫 $s$ と数量 $k$ は非負整数（Lean の `Nat` は0を含みます）で、$k>0$ が有効入力です。成功時は k≤s かつ残数 r が r+k=s を満たし、不足時は拒否します。数量0も別途拒否と定めます。Lean の既習関数 takeStock は比較と減算で実行します。結果は [Option型](../LVT1-03/index.md#def-lvt1-03-option) の Option Nat（some r は成功、none は拒否）です。

独立の実装では、残数を一度の減算式で求める代わりに、在庫を一つずつ消費するか、条件 r+k=s を満たす r を0からsまで探索する方法を採用できます。例えば s=5,k=2 なら、候補 r=0,1,2,3 の和は順に2,3,4,5となり、r=3で成功します。s=1,k=2 なら候補0,1の和は2,3で、1と一致しないので拒否です。どちらも同じ業務要求から別のアルゴリズムを作ります。独立とは確率的な独立性ではなく、基準の実装をコピーせず異なる設計・コードで作ることです。仕様解釈まで共通に誤る可能性は残ります。

## 2. 比較する出力を設計する

成功の有無だけを比べるなら、some 3 と some 4 は同じ成功と見なされます。残数も重要なら区別しなければなりません。実装固有の返り値から、要求上比較したい値を取り出す写像を観測とします。決定的とは、同じ入力から常に同じ出力が得られることです。観測も各出力に対して一つの値を定めます。恒等写像は値をそのまま返す写像です。実際に比較するには、観測を計算でき、観測値の等しさを正しく判定できることも必要です。[Leanの決定可能性](../LVT2-01/index.md#def-lvt2-01-decidable) で学んだように、数学的に等式を述べることと、その真偽を計算できることは区別します。

<a id="def-lvt5-01-observed"></a>

<!-- formal-statement-start -->
### 定義（観測付き差分検査）

共通の入力集合 D、二つの実装の出力集合 A, B、観測値の集合 Y を固定する。各入力で終了し決定的な関数 f:D→A、g:D→B、および観測写像 u:A→Y、v:B→Y を取る。有限な共通入力集合 $T\subseteq D$ に対して（実行による検査では $T$ を列挙でき、$u,v$ を計算でき、$Y$ 上の等しさを正しく判定できるものとする）、

$$
u(f(x))=v(g(x))
$$

を各 $x\in T$ で検査する。成立しない入力の集合は

$$
M_T=\{x\in T\mid u(f(x))\ne v(g(x))\}
$$

である。添字 $T$ は検査対象の入力集合を指定する。
<!-- formal-statement-end -->

<!-- definition-example-start: def-lvt5-01-observed -->
**定義の確認**　$D=\mathbb N_0^2$ は非負整数の組 $(s,k)$ の集合、$A=B$ は `Option Nat` の値全体とします。$f$ は `takeStock`、$g$ は成功時に誤って `some s` を返し、拒否時は $f$ と同じ `none` を返す実装です。各入力で有限回の比較・算術で停止し、条件ごとに返す値が一意なので、両者は決定的な関数です。$T=\{(4,1),(1,2)\}$ は列挙可能な有限部分集合です。

まず $Y=A$ とし、$u,v$ を恒等写像にします。[Option型](../LVT1-03/index.md#def-lvt1-03-option) の `none` 同士は等しく、`some` 同士は中身の非負整数を比較します。異なる構成子なら不一致です。この比較は有限回で正確に行えます。[在庫引当仕様](../LVT3-01/index.md#def-lvt3-01-order) の成功条件から $1\le4$ かつ $3+1=4$、不足条件から $1<2$ を確認します。

| 入力 | 基準の観測 | 変異の観測 |
|---|---|---|
| (4,1) | some 3 | some 4 |
| (1,2) | none | none |

従って $M_T=\{(4,1)\}$ です。一方 $Y$ を [Leanの真偽値型](../LVT2-01/index.md#def-lvt2-01-bool) `Bool` とし、$u,v$ を `some` なら `true`、`none` なら `false` を返す写像にすると、構成子の判定だけで観測を計算でき、二つの真偽値の比較も実行できます。前者は `true` 同士、後者は `false` 同士なので $M_T=\varnothing$ です。後者は残数を比較していないため、成功時の残数の誤りを検出できません。
<!-- definition-example-end -->

## 3. 一致・不一致から何が言えるか

要求が一つの観測値を決める場合、入力 $x$ に対する要求値を $q(x)$ と書きます。基準の観測が q(x) と一致すると証明済みなら、製品の観測との一致を利用できます。

<a id="prop-lvt5-01-agreement"></a>

<!-- formal-statement-start -->
### 命題（正しい基準との一致による適合性）

[観測付き差分検査](#def-lvt5-01-observed) の設定で要求を q:D→Y とする。入力 x∈D について基準が $u(f(x))=q(x)$ を満たし、比較で $u(f(x))=v(g(x))$ が成立するなら、$v(g(x))=q(x)$ が成立する。両仮定が T の全入力で成立すれば結論も T の全入力で成立する。
<!-- formal-statement-end -->

**証明の見取り図**　比較の等式を逆向きにしてから、基準の正しさの等式とつなぎます。

<!-- proof-start -->
### 証明

$x$ を固定する。[等式の対称律と推移律](../LVT2-03/index.md#prop-lvt2-03-chain) の対称律から

$$
v(g(x))=u(f(x)).
$$

基準が正しいという仮定 $u(f(x))=q(x)$ と推移律でつなぐと

$$
v(g(x))=u(f(x))=q(x).
$$

従って結論を得る。仮定が T の全入力に対して成立するなら、任意に取った x∈T にこの推論を適用できるので全入力で結論が成立する。
<!-- proof-end -->

例えば (s,k)=(5,2) の要求は some 3 です。[在庫引当関数の契約充足](../LVT3-01/index.md#prop-lvt3-01-correct) と [在庫引当仕様の結果一意性](../LVT3-01/index.md#prop-lvt3-01-unique) により、有効入力で takeStock は要求する唯一の結果を返します。数量ゼロでは同じ契約充足命題の別条件が拒否を保証します。製品も some 3 ならこの入力の全結果は正しいです。成功の有無だけを比較した場合、上の命題の q も成功の有無だけを指します。

基準が正しいとまだ分からない場合でも、二つの異なる観測値が同一の要求値を同時に満たすことはありません。

<a id="prop-lvt5-01-disagreement"></a>

<!-- formal-statement-start -->
### 命題（不一致が示す少なくとも一方の誤り）

[観測付き差分検査](#def-lvt5-01-observed) の設定で要求を $q:D\to Y$ とし、古典論理の下で $x\in D$ を固定する。$u(f(x))\ne v(g(x))$ なら、$u(f(x))\ne q(x)$ または $v(g(x))\ne q(x)$ が成立する。
<!-- formal-statement-end -->

**証明の見取り図**　古典論理の排中律（任意の命題 $P$ について $P$ またはその否定が成り立つ）により、基準の観測が要求と等しい場合と等しくない場合に分けます。等しさの決定手続きがある場合も同じ場合分けができます。

<!-- proof-start -->
### 証明

$u(f(x))\ne q(x)$ なら最初の選言（「または」で結んだ二つの主張のうち左側）が成立する。排中律によるもう一方の場合は $u(f(x))=q(x)$ である。もし $v(g(x))=q(x)$ も成立するとすれば、[等式の対称律と推移律](../LVT2-03/index.md#prop-lvt2-03-chain) から

$$
u(f(x))=q(x)=v(g(x))
$$

となり、不一致という仮定に反する。よって $v(g(x))\ne q(x)$ であり、二番目の選言が成立する。二つの場合を尽くした。
<!-- proof-end -->

要求が複数の出力を許す場合（例えば同じ優先度の項目をどちらから返してもよい場合）、生の出力の不一致が直ちに誤りとはなりません。この命題は要求が一つの観測値を決める場合に限ります。要求が許容する違いを保ったまま比較するには、何を観測とするか改めて決めます。

## 4. 同じ誤りと有限入力の限界

数量が在庫と等しい場合を考えます。正しい比較は k≤s ですが、誤って k<s を要求する実装を厳密比較変異とします。残数変異は受理条件を正しく保つ一方、成功時に減算せず some s を返します。

| (s,k) | 基準 | 厳密比較変異 | 残数変異 |
|---|---|---|---|
| (5,0) | none | none | none |
| (1,2) | none | none | none |
| (2,2) | some 0 | none | some 2 |
| (5,2) | some 3 | some 3 | some 5 |

基準と厳密比較変異を比較すると (2,2) が不一致です。しかし二つとも厳密比較変異なら、全入力で一致しても (2,2) で両者は要求を破ります。違う言語を使うだけではこれを防げません。独立した要求、既知の境界例、[変異テストと変異スコア](../LVT4-06/index.md#def-lvt4-06-mutation) を組み合わせます。

有限集合 T で一致しても、未検査入力での一致はまだ分かりません。[有限な例示テストと全入力一致](../LVT1-01/index.md#prop-lvt1-01-test-boundary) と同じ理由です。たとえば T が在庫0〜3、数量0〜3の16組なら、在庫4かつ数量4だけを誤拒否する実装は検出できません。全入力がこの16組に限定されるなら完全列挙は意味を持ちますが、非負整数全体の契約には全称命題の証明が別に必要です。

## 5. Lean と Python で実験する

[Lean の実験ソース](lab/LvtDifferential.lean) は LVT3-01 の takeStock を再利用します。consume は数量と在庫を同時に1ずつ減らし、数量0に到達したら残数を返し、数量が残っているのに在庫0なら none を返します。candidate は最初の数量0だけ別に拒否します。比較に使う基準コードをコピーせずに作る例です。

[Python の比較スクリプト](lab/compare.py) は Lean が出力する在庫0〜3、数量0〜3の16組を読み、独立した探索で期待値を求めます。全結果を「拒否なら -、成功なら残数の十進表記」で比較します。この小さな実験の出力は行ごとに4種類の結果を含みます。次講では汎用的な JSON Lines の入出力を設計します。

~~~bash
cd "textbook/volumes/dream_thater/計算系/LVT/LVT5-01/lab"
lean --version
lake build
lake test
lake env lean LvtDifferential.lean
python3 compare.py
# 次のコマンドは意図的な失敗
lake env lean Failure.lean
~~~

固定版は Lean 4.35.0 です。正常系では LVT5-01 OK と表示します。Lean の集計は全結果比較で不一致3件と6件、受理だけの残数変異では0件と計算します。Python は16組の独立実装との一致を検査し、同じ件数を報告します。`Failure.lean` は在庫と数量が2の境界で、正しい `takeStock` が `none` を返すという誤った命題を `none = none` の反射律で証明しようとして拒否されます。実際の結果は `some 0` です。Lean Web の版は固定版と異なる場合があり、Codespaces の利用にはログインと利用枠が必要です。

Lean の agreeSound は第3節の等式の連鎖を証明します。disagreeNotBoth は不一致の場合に両方が要求を満たすことはないと証明します。コードでは $a=u(f(x))$、$b=v(g(x))$ と置き、引数 `q` は固定した入力での要求値 $q(x)$ に対応します。`hAgree.symm.trans hRef` は比較の等式を反転して基準の正しさへつなぐ操作です。`disagreeNotBoth` の `classical` は排中律を利用するための宣言で、証明中の選言はどちらが誤りかを計算する手続きではありません。16件の実験は candidate や Python の全非負整数入力での正しさの証明ではありません。

## 6. 演習と詳細解答

### Level A

### LVT5-01-A01 境界値の照合

在庫 s=3、数量 k=3 で基準と厳密比較変異の結果を求めよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

数量は正で k=s なので基準は some (3−3)=some 0。変異は k<s が偽なので none。両結果は異なり不一致になる。
<!-- solution-end -->

### LVT5-01-A02 不足と数量ゼロ

(s,k)=(1,2),(4,0) で基準と厳密比較変異の結果を求め、前者と後者の仕様上の違いを述べよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

(1,2) は k>0 かつ k>s なので両方 none。これは在庫不足であり有効入力の拒否である。(4,0) は k>0 が偽なので両方 none。これは事前条件外の入力に対する別途定めた拒否である。
<!-- solution-end -->

### LVT5-01-A03 観測の選択

(4,1) で基準は残数を返し、残数変異は在庫をそのまま返す。全結果と受理の有無で照合せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

基準は some (4−1)=some 3、変異は some 4。全結果では 3≠4 なので不一致。受理の有無はいずれも true なので一致する。残数の誤りが観測から消えている。
<!-- solution-end -->

### LVT5-01-A04 同じ誤り

基準と製品がともに厳密比較変異の場合、(2,2) の差分検査と要求との比較を行え。

- Level: A

<!-- solution-start -->
#### 詳細解答

両方とも 2<2 が偽なので none。差分検査は一致する。独立の要求では 2≤2 かつ 0+2=2 なので some 0 が正しい。両者の一致はこの誤りを検出しない。
<!-- solution-end -->

### Level B

### LVT5-01-B01 有限領域の検出集合

在庫と数量をそれぞれ0〜3とする16組について、厳密比較変異の全結果不一致と、残数変異の全結果不一致を列挙せよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

数量0では全実装が none、不足 k>s でも全実装が none。[在庫引当仕様](../LVT3-01/index.md#def-lvt3-01-order) に照らすと、残るのは $1\le k\le s\le3$。厳密比較変異では k=s の (1,1),(2,2),(3,3) だけ不一致。残数変異は成功時 `some s` と `some (s−k)` を比べる。$k\ge1$ かつ $k\le s$ より、$0\le s-k\le s-1<s$。従って (1,1),(2,1),(2,2),(3,1),(3,2),(3,3) の6件すべて不一致。受理だけなら後者の6件もすべて一致する。
<!-- solution-end -->

### LVT5-01-B02 比較器の仮定

出力集合を非負整数とする。要求する出力が2で基準も正しく2を返すとする。観測が偶奇だけの場合、基準の出力2と製品の出力4の観測値が一致する。この一致から出力値の正しさが従わない理由を述べ、正しい結論を書け。

- Level: B

<!-- solution-start -->
#### 詳細解答

観測は非負整数 $n$ を2で割った余り $n\bmod 2$ です。$2=2\cdot1+0$、$4=2\cdot2+0$ なので、どちらの余りも0です。2≠4 だが観測は同じであり、異なる値を同じ値に写さないという条件が欠けている。[正しい基準との一致による適合性](#prop-lvt5-01-agreement) から導けるのは製品の観測値0が要求する偶奇0に等しいことまで。この例のように同じ出力集合に同じ観測を使うなら、観測が異なる値を必ず区別する（単射である）ことは全値の一致を導く十分条件である。全結果比較はその一例である。
<!-- solution-end -->

### LVT5-01-B03 比較の左右を入れ替える

要求される観測値が y で一方の観測が a、他方が b、a≠b とする。一方が正しくないことを証明し、どちらかを特定できない例を与えよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

[不一致が示す少なくとも一方の誤り](#prop-lvt5-01-disagreement) と同じく古典論理で場合分けする。$a\ne y$ なら前者が誤りである。$a=y$ の場合、もし $b=y$ なら等式の対称律と推移律から $a=y=b$ となり、$a\ne b$ に反する。従ってこの場合は $b\ne y$ である。両方が正しいと矛盾することに加え、場合分けによって $a\ne y$ または $b\ne y$ が得られた。a=1,b=2 のとき、要求 y=1 なら後者、y=2 なら前者が誤り、y=3 なら両方が誤り。比較だけでは y を確定できない。
<!-- solution-end -->

### Level C

### LVT5-01-C01 検査設計と実行

在庫引当で (1,0),(1,2),(2,2),(3,1) の4件を使う。基準、厳密比較変異、残数変異の全結果を表にし、どの観測でどの変異を検出できるか判定せよ。実験の Python スクリプトを実行して16件の結果とも照合し、全入力保証に必要な追加条件を述べよ。

- Level: C

<!-- solution-start -->
#### 詳細解答

[在庫引当仕様](../LVT3-01/index.md#def-lvt3-01-order) に従い、数量ゼロと不足は拒否する。成功する二件は $2-2=0$、$3-1=2$ である。厳密比較変異は等号の境界を拒否し、残数変異は成功時の在庫を返す。

| 入力 | 基準 | 厳密比較変異 | 残数変異 |
|---|---|---|---|
| (1,0) | none | none | none |
| (1,2) | none | none | none |
| (2,2) | some 0 | none | some 2 |
| (3,1) | some 2 | some 2 | some 3 |

全結果比較では厳密比較変異を (2,2)、残数変異を (2,2),(3,1) で検出する。受理の有無では前者だけ (2,2) で検出し、後者は全4件一致する。python3 compare.py は16件の独立実装との一致、厳密比較変異3件、残数変異6件、受理のみ0件を表示する。4件はその部分集合である。[正しい基準との一致による適合性](#prop-lvt5-01-agreement) を全入力へ適用するには、全入力で正しい基準と、全入力での観測の一致の証明が必要である（有限領域なら完全列挙と領域外がない根拠）。さらに観測上の適合から元の要求への適合を主張するなら、観測の一致がその要求の成立を保証することも確認する。実際の入出力変換が同じ意味を保存することも別途確認する。

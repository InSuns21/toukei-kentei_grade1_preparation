# LVT3-08 Hoare論理・最弱事前条件・vcgen

前講の[操作結果の詳細化条件](../LVT3-07/index.md#def-lvt3-07-refinement)では、抽象仕様と具体実装の応答を一操作ずつ対応させました。今回は一つのプログラムの内部に注目します。入力から出力までの全体をいきなり証明する代わりに、命令の前後で何が真である必要があるかを調べます。特に繰り返しの回数が入力に依存するとき、各回の小さな証明を全体の保証へどうつなげるのでしょうか。

**ブラウザで実行：** [本講の実行ラボ](../browser-lab.html?chapter=LVT3-08)。配列を変えて加算ループを実行し、正常な証明、演習解答、誤った命題を比較できます。先に紙上で条件を導出してから Lean のゴールと照合します。

## 1. 命令の前後に条件を置く

自然数のカウンタ n に 2 を加える命令を考えます。終了後の値を 5 以上にしたいなら、開始時に n が 3 以上であることを要求すれば十分です。ここで開始時に要求する性質を事前条件、終了時に要求する性質を事後条件とします。性質は状態を入力として真偽を表す命題を返す関数（述語）です。

[LVT3-02 の部分正当性](../LVT3-02/index.md#def-lvt3-02-partial)では、計算が成功したときの性質と停止することを分けました。本節ではまず必ず終了し、入力状態ごとに一つの出力状態を返す命令だけを扱います。開始時と終了時の状態が異なる集合に属してもよいことにします。

<a id="def-lvt3-08-hoare"></a>

<!-- formal-statement-start -->
### 定義（Hoare三つ組）

状態の集合を $S,T$、全域関数を $f:S\to T$ とする。開始時の述語 $P:S\to\mathrm{Prop}$ と終了時の述語 $Q:T\to\mathrm{Prop}$ について、Hoare三つ組 $\{P\}\,f\,\{Q\}$ が成立するとは、次の命題が成立することである。

$$
\forall s\in S,\quad P(s)\Longrightarrow Q(f(s)).
$$

本講の全域関数のモデルでは停止性は関数の仮定に含まれる。
<!-- formal-statement-end -->
<!-- definition-example-start: def-lvt3-08-hoare -->
**定義の確認**　$S=T=\mathbb N$、$f(n)=n+2$、$P(n)$ を $n\ge3$、$Q(r)$ を $r\ge5$ とする。任意の n に対して P(n) を仮定すれば n + 2 ≥ 3 + 2 = 5 なので Q(f(n)) が成立する。全称条件を確認したので三つ組が成立する。n = 2 では P が偽で、この三つ組はその入力での出力を保証しない。
<!-- definition-example-end -->

事前条件はテストに使う一つの入力ではありません。任意の入力について条件が成立するときの約束です。一方、事前条件を常に偽にすれば三つ組は何も要求しなくなるので、仕様として意味があるかは別に確認します。

## 2. 必要な入力を結果から逆算する

上の命令なら n ≥ 4 でも n ≥ 100 でも十分です。しかし必要以上に入力を制限したくありません。条件 A が条件 B を含意するなら、B の方が弱い（許す状態が少なくとも同じだけ多い）といいます。十分な条件の中で最も弱い条件を求めます。

<a id="def-lvt3-08-wp"></a>

<!-- formal-statement-start -->
### 定義（最弱事前条件）

全域関数 $f:S\to T$ と事後条件 $Q:T\to\mathrm{Prop}$ を固定する。述語 $W:S\to\mathrm{Prop}$ が最弱事前条件であるとは次の二条件を満たすことをいう。

1. [Hoare三つ組](#def-lvt3-08-hoare) $\{W\}\,f\,\{Q\}$ が成立する。
2. $\{P\}\,f\,\{Q\}$ が成立する任意の述語 P について、任意の $s\in S$ で $P(s)\Rightarrow W(s)$ が成立する。

この条件を満たす述語を $\operatorname{wp}(f,Q)$ と書く。論理的に同値な述語は同じ条件として扱う。
<!-- formal-statement-end -->
<!-- definition-example-start: def-lvt3-08-wp -->
**定義の確認**　f(n) = n + 2、Q(r): r ≥ 5 とする。W(n): n ≥ 3 なら n + 2 ≥ 5 なので第一条件が成立する。任意の十分な P と P(n) を取れば、三つ組から n + 2 ≥ 5 が従う。整数として 2 を引けば n ≥ 3、つまり W(n)。第二条件も成立する。逆に n ≥ 4 は十分だが n = 3 を許さないので最弱ではない。
<!-- definition-example-end -->

命令が全域関数の場合、出力が Q を満たす入力をそのまま集めればよいはずです。

<a id="prop-lvt3-08-wp"></a>

<!-- formal-statement-start -->
### 命題（最弱事前条件の特徴付け）

任意の全域関数 $f:S\to T$ と述語 Q に対して、[最弱事前条件](#def-lvt3-08-wp)は点ごとに

$$
\operatorname{wp}(f,Q)(s)\ \Longleftrightarrow\ Q(f(s))
$$

で与えられ、任意の二つの最弱事前条件は点ごとに論理的に同値である。
<!-- formal-statement-end -->
**証明の見取り図**　出力を代入した述語が十分であり、どんな十分な事前条件からも従うことを確認します。

<!-- proof-start -->
### 証明

$W(s)=Q(f(s))$ と置く。任意の s で W(s) を仮定すると定義そのものから Q(f(s)) が成立し、三つ組の条件を満たす。

次に十分な P を任意に取る。P(s) を仮定すると [Hoare三つ組](#def-lvt3-08-hoare)より Q(f(s))、従って W(s)。これは任意の s について成立する。よって W は [最弱事前条件](#def-lvt3-08-wp) の二条件を満たす。

別の最弱事前条件 V があれば、V が十分であることと W の最弱性から V(s) ⇒ W(s)。逆に W が十分であることと V の最弱性から W(s) ⇒ V(s)。従って論理的に同値である。
<!-- proof-end -->

Lean のコードでは `Holds f P Q` を三つ組、`wpF f Q s` を出力代入の述語に対応させます。最弱性の二方向を `wp_sufficient` と `wp_weakest` で検査します。

## 3. 複数の命令を組み合わせる

入力 n に 1 を加え、その結果を 2 倍する二命令を考えます。最終結果を 8 以上にしたければ、2 倍する直前に 4 以上が必要です。次に、1 を加える直前には 3 以上が必要です。命令は前から実行しますが、条件は後ろから計算します。

条件による分岐も扱います。状態 s に対して b(s) が true または false を返し、true なら f、false なら g を実行します。ここで b は判定を実行できる真偽値関数です。

<a id="prop-lvt3-08-seq"></a>

<!-- formal-statement-start -->
### 命題（逐次実行と分岐の逆向き計算）

全域関数 $f:S\to T$、$g:T\to U$、述語 $Q:U\to\mathrm{Prop}$ を取る。f の後に g を実行する関数を $g\circ f$ とする。このとき

$$
\operatorname{wp}(g\circ f,Q)(s)
\Longleftrightarrow
\operatorname{wp}(f,\operatorname{wp}(g,Q))(s).
$$

また $f_1,f_2:S\to T$、$b:S\to\mathrm{Bool}$、述語 $R:T\to\mathrm{Prop}$ を取る。b が true なら f₁、false なら f₂ を選ぶ関数を c とすると、

$$
\operatorname{wp}(c,R)(s)
\Longleftrightarrow
\begin{cases}
\operatorname{wp}(f_1,R)(s)& b(s)=\mathrm{true},\\
\operatorname{wp}(f_2,R)(s)& b(s)=\mathrm{false}.
\end{cases}
$$
<!-- formal-statement-end -->
**証明の見取り図**　いずれも最弱事前条件を出力代入に戻し、実行順または分岐を展開します。

<!-- proof-start -->
### 証明

[最弱事前条件の特徴付け](#prop-lvt3-08-wp)により、逐次実行の左辺は Q((g ∘ f)(s)) と同値である。合成の定義でこれは Q(g(f(s)))。一方、同じ特徴付けを g と Q に適用すると、任意の中間状態 t について wp(g,Q)(t) は Q(g(t)) と同値である。t = f(s) を代入し、さらに f と述語 wp(g,Q) に特徴付けを適用すると右辺が得られる。

分岐では b(s) = true のとき c(s) = f₁(s)。左辺は R(c(s)) と同値なので R(f₁(s))、再度特徴付けを適用して wp(f₁,R)(s) を得る。b(s) = false なら c(s) = f₂(s) となり、R(c(s)) は R(f₂(s)) と同値、従って wp(f₂,R)(s)。Bool の二値で全場合を尽くした。
<!-- proof-end -->

例えば n ≥ 3 なら n + 1、そうでなければ n + 2 を返す命令に対し、結果が 4 以上という条件を考えます。前者では n ≥ 3 が十分、後者では n < 3 と n + 2 ≥ 4 が必要なので n = 2 です。二つの枝を合わせると最弱事前条件は n ≥ 2 です。条件を真偽値にしてから、選ばれた枝だけを確認する点が重要です。

## 4. ループを分解して検証する

何回も加算するプログラムでは、入力の長さによって命令数が変わります。全ての命令を展開する代わりに、各回の前後に共通して成立してほしい性質を考えます。[帰納的不変量](../LVT3-05/index.md#def-lvt3-05-inductive)と同じ考え方ですが、ここでは開始、更新、終了を区別して、最後に要求する結果へつなぎます。

元の有限列 L の処理済み部分を p、残りを s、累積値を a とします。空列を []、先頭 x と残り t からなる列を x :: t、連結を ++ と書きます。常に p ++ s = L であるように、次の一要素 x を残り列から処理済み列の末尾へ移します。更新は全域関数 u(a,x) に従って a を変更するものとします。ループの途中状態について成立してほしい述語 I を用意します。

<a id="def-lvt3-08-vc"></a>

<!-- formal-statement-start -->
### 定義（有限走査のループ不変量と検証条件）

有限列 L、初期累積値 $a_0\in A$、全域更新関数 $u:A\times X\to A$ を固定する。状態は $(p,s,a)$ とし、p,s は X の有限列、a は A の元である。初期状態を $([],L,a_0)$、s が空なら終了、それ以外なら $s=x::t$ として次状態を $(p++[x],t,u(a,x))$ とする。

このループに対する述語 I と終了時に要求する述語 Q に関し、次の三条件を検証条件とする。

- 初期化：$I([],L,a_0)$。
- 保存：任意の p,x,t,a に対して

$$
I(p,x::t,a)\Longrightarrow I(p++[x],t,u(a,x)).
$$

- 終了：任意の p,a に対して

$$
I(p,[],a)\Longrightarrow Q(a).
$$

初期化と保存を満たす I をこのループの不変量とする。終了条件は I から事後条件を得るための追加責務である。
<!-- formal-statement-end -->
<!-- definition-example-start: def-lvt3-08-vc -->
**定義の確認**　L = [2,5]、a₀ = 0、u(a,x) = a + x とし、I を p ++ s = L かつ a = sum(p)、Q を a = 7 とする。sum は空列で 0、先頭と残り列の和を足す関数である。初期は [] ++ L = L、a = 0 = sum([])。任意の保存条件の入力で L = p ++ (x :: t) なら (p ++ [x]) ++ t = L、また sum(p ++ [x]) = sum(p) + x（次節で導出）なので更新後にも I が成り立つ。終了時 s = [] なら p = L、従って a = sum([2,5]) = 7。三条件を満たす。実際に状態は ([],[2,5],0) → ([2],[5],2) → ([2,5],[],7) と変化する。
<!-- definition-example-end -->

保存だけでは不十分です。例えば a = 0 を不変量候補にすると初期化は通りますが、x = 2 の回で保存が失敗します。また常に真という候補なら初期化と保存を通りますが、a が正しい和であることを終了時に導けません。

<a id="prop-lvt3-08-loop"></a>

<!-- formal-statement-start -->
### 命題（有限走査の検証条件の十分性）

[有限走査のループ不変量と検証条件](#def-lvt3-08-vc)の三条件が成立するなら、同定義の有限走査は終了し、その最終累積値 a は Q(a) を満たす。
<!-- formal-statement-end -->
**証明の見取り図**　回数に関する帰納法で I を保ち、残り列の長さが毎回1減ることから停止も示します。

<!-- proof-start -->
### 証明

初期状態は I([],L,a₀) を満たす。k 回の更新を実行した状態で I が成立すると仮定する。その状態の残り列が空でなければ s = x :: t と書ける。保存条件に現在の p,x,t,a を代入すると I(p ++ [x],t,u(a,x)) を得る。従って帰納法で、実行中の全状態に I が成立する。

初期の残り列の長さを m とする。k 回更新した時の残り列の長さは m − k である（0 ≤ k ≤ m）。k = 0 では m。k < m の場合、m − k > 0 なので次の要素が存在し、先頭を除くため長さは m − k − 1 = m − (k + 1) となる。k = m では残り列の長さが 0 なので空列となり終了する。各更新 u は全域と仮定しているため更新途中で停止不能になることもない。

最終状態を (p,[],a) とすると、前段の帰納法から I(p,[],a)。終了条件を適用して Q(a) を得る。従って有限回で終了することと結果が正しいことの両方を確認した。
<!-- proof-end -->

一般の while ループでは残り列のような有限の回数が最初から分からないことがあります。その場合、初期化・保存・終了から導くのはまず終了した場合の保証です。例えば while true do skip は状態を変えないため任意の I を保存し、終了時の条件（I かつガードが偽）からはどんな結論も含意されますが、終了しません。停止性を別に示す必要があるという [LVT3-02 の全正当性](../LVT3-02/index.md#def-lvt3-02-total) の区別がここで効きます。

## 5. 加算ループの検証条件を手で導く

配列を先頭から末尾まで走査する順序で有限列 L と見なします。各要素は自然数で、累積値も自然数とします。sum([]) = 0、sum(x :: t) = x + sum(t) と和を定めます。任意の列 p と要素 x について、末尾に x を追加した和は元の和に x を加えたものです。これは [リストの帰納法](../LVT2-05/index.md#principle-lvt2-05-list)で直接確認できます。

<a id="prop-lvt3-08-sum"></a>

<!-- formal-statement-start -->
### 命題（配列の加算ループの正当性）

自然数の有限配列 L に対して、累積値を 0 で初期化し、各要素 x を順に一回ずつ $a\leftarrow a+x$ により加算するループは終了し、最終値が $\operatorname{sum}(L)$ に等しい。
<!-- formal-statement-end -->
**証明の見取り図**　処理済み部分の和が累積値に等しいことを I とし、初期化・保存・終了を順に検証します。

<!-- proof-start -->
### 証明

まず任意の列 p と自然数 x について

$$
\operatorname{sum}(p++[x])=\operatorname{sum}(p)+x
$$

を示す。p = [] なら左辺は sum([x]) = x + 0 = x、右辺は 0 + x = x。p = y :: q の場合は q に対して等式を仮定し、連結と sum の再帰規則を順に使う。

$$
\operatorname{sum}((y::q)++[x])
=\operatorname{sum}(y::(q++[x]))
$$

$$
=y+\operatorname{sum}(q++[x])
=y+(\operatorname{sum}(q)+x)
$$

$$
=(y+\operatorname{sum}(q))+x
=\operatorname{sum}(y::q)+x.
$$

第三の等号で帰納仮定、次で自然数の加算の結合性を使った。よって任意の p に対し等式が成立する。

次に I(p,s,a) を、p ++ s = L かつ a = sum(p) とする。初期状態では p = []、s = L、a = 0。[] ++ L = L、sum([]) = 0 なので両条件が成立する。

保存では I(p,x :: t,a) を仮定する。次状態は p' = p ++ [x]、s' = t、a' = a + x。連結の結合性により

$$
p'++s'=(p++[x])++t=p++(x::t)=L.
$$

また先ほどの和の等式により

$$
a'=a+x=\operatorname{sum}(p)+x
=\operatorname{sum}(p').
$$

従って二条件とも保存される。終了時に s = [] なら p ++ [] = p = L であり、

$$
a=\operatorname{sum}(p)=\operatorname{sum}(L).
$$

これは要求する Q(a)。以上三条件を [有限走査の検証条件の十分性](#prop-lvt3-08-loop) に適用して停止と結果の等式を得る。L = [] の場合も初期状態が終了状態で、出力 0 = sum([]) である。
<!-- proof-end -->

ここではループ中の値 a に加えて p と s を証明のために用いました。実装が別途二つの配列を保持する必要はありません。p と s は走査位置が決める情報です。例えば [2,0,5] では累積値は 0 → 2 → 2 → 7 です。0 を処理した回にも残り列は一要素短くなるので停止性は失われません。

## 6. Lean 4 の vcgen に同じ証明を渡す

`vcgen` はプログラムの意味に基づいて、命令列に関する証明責務（検証条件）を生成するタクティクです。Lean 4.35 から利用でき、従来の `mvcgen` の後継です。本講では [公式 vcgen チュートリアル](https://lean-lang.org/doc/tutorials/4.35.0/vcgen/) の有限配列を走査する方法を参照し、固定版 4.35.0 で加算ループと初期値を一般化した加算ループを検査します。`Id.run` は外部状態や例外を持たない計算を実行して結果を取り出します。`let mut` は局所的に更新できる変数、`for x in xs` は配列の各要素を順に処理する構文です。

[実ソース](lab/LvtHoare.lean)の `sumLoop` が上の加算ループを表し、`sumLoop_correct` は全ての自然数配列について結果が配列の和に等しいことを示します。証明では、まず実行結果を r と置き、その等式を h とします。`Id.of_run_eq_wp h` は結果についての目標を、結果が条件を満たすことを保証する最弱事前条件の目標へ移します。`vcgen` によってループの検証条件が生成されます。

不変量の引数は pref（処理済み列）、suff（残り列）、acc（現在の累積値）です。Lean のループの検証規則には元の配列が処理済み列と残り列に分かれる情報が含まれるため、不変量として `pref.sum = acc` を与えます。これは紙上で与えた I のうち累積値の条件に当たります。

- 初期化：空の pref の和が 0 になること。
- 保存：pref の末尾に x を追加した和と、acc + x が一致すること。
- 終了：pref が配列全体となったとき、acc がその和に一致すること。

`vcgen invariants` は不変量を指定し、`with finish` は生成された各目標を自動化で処理します。自動化が成功する理由は前節の等式と場合分けであり、誤った不変量を指定すれば未解決ゴールが残ります。Lean の標準ライブラリで用いる WP の枠組みはより一般的ですが、本講の全域的で副作用のない計算では、出力が条件を満たすという意味と対応します。

[実行ラボ](../browser-lab.html?chapter=LVT3-08)の Inspect では空配列で 0、[2,0,5] で 7、初期値 4 の一般化で 11、加算に余分な 1 を加える変異を [2] に適用して 3 を観察します。Main では具体的な入力を検査し、ExerciseSolutions では8題の命題を検査します。Failure では変異に対して正しい和の等式を rfl で証明しようとすると拒否されます。Inspect では二つのループ証明と最弱事前条件の補題の公理依存も確認します。

固定版は [lean-toolchain](lab/lean-toolchain) の Lean 4.35.0 です。Lean Web の版が異なる場合は Codespaces の端末で以下を実行してください。Codespaces には GitHub アカウントと利用枠が必要です。

~~~bash
cd "textbook/volumes/dream_thater/計算系/LVT/LVT3-08/lab"
lake build
lake test
lake env lean Inspect.lean
lake env lean ExerciseSolutions.lean
lake env lean Failure.lean
~~~

最後だけ意図的な失敗です。通常の証明がコンパイルされること、意図的失敗が拒否されること、具体例の計算結果が正しいことは区別して確認します。本講は自然数の全域的な加算を扱います。固定幅整数のオーバーフローや IO を含む製品では、それらを表す状態と命令の意味を別に定める必要があります。

## 7. 演習と詳細解答

### Level A

### LVT3-08-A01 事前条件の判定

自然数の命令 f(n) = n + 2 に対し、事前条件 n ≥ 3、事後条件 r ≥ 5 の Hoare三つ組が成立するか。境界 n = 3 も調べよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[Hoare三つ組](#def-lvt3-08-hoare)の意味から、任意の n ≥ 3 を取ると r = n + 2 ≥ 3 + 2 = 5。従って成立する。n = 3 では r = 5 で境界でも成立する。Lean の `a01` はこの全称命題を検査する。
<!-- solution-end -->

### LVT3-08-A02 最弱事前条件の計算

f(n) = n + 2、Q(r) を r ≥ 5 とする。最弱事前条件を n の不等式で表し、n = 2,3 で確認せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[最弱事前条件の特徴付け](#prop-lvt3-08-wp)から、条件は n + 2 ≥ 5 と同値。両辺から整数として 2 を引くと n ≥ 3 であり、自然数に制限してもこの同値性は保たれる。n = 2 なら 4 ≥ 5 は偽、n = 3 なら 5 ≥ 5 は真。Lean の `a02` は任意の n に対する同値を検査する。
<!-- solution-end -->

### LVT3-08-A03 逐次実行を逆向きに読む

自然数の命令 f(n) = n + 1、g(n) = 2n をこの順に実行し、最終値が 8 以上となる最弱事前条件を求めよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[逐次実行と分岐の逆向き計算](#prop-lvt3-08-seq)より、まず g の出力が 8 以上となる中間状態 m の条件は 2m ≥ 8、すなわち m ≥ 4。次に m = n + 1 を代入して n + 1 ≥ 4、従って n ≥ 3 を得る。n = 3 なら 4 → 8、n = 2 なら 3 → 6。Lean の `a03` は同値を検査する。
<!-- solution-end -->

### LVT3-08-A04 ループの途中状態

配列 [2,0,5] を左から加算する。初期累積値を 0 とし、一要素を処理するごとに処理済み列と残り列、累積値を記録せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[有限走査のループ不変量と検証条件](#def-lvt3-08-vc)の記号では、初期状態 ([], [2,0,5], 0)。2 を加えて ([2], [0,5], 2)、0 を加えて ([2,0], [5], 2)、5 を加えて ([2,0,5], [], 7)。各累積値は処理済み列の和。残り列の長さは 3,2,1,0 なので停止する。Lean の `a04` は最終値 7 を検査する。
<!-- solution-end -->

### Level B

### LVT3-08-B01 強すぎる事前条件

f(n) = n + 2、Q(r) を r ≥ 5 とする。P(n) を n ≥ 4 とした Hoare三つ組が成立する一方、P は最弱事前条件でないことを示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

n ≥ 4 なら n + 2 ≥ 6 ≥ 5 なので [Hoare三つ組](#def-lvt3-08-hoare) は成立する。[最弱事前条件](#def-lvt3-08-wp)は任意の十分条件から含意される必要がある。条件 W(n): n ≥ 3 は A02 と同じ不等式 n + 2 ≥ 5 を満たす。n = 3 で W は真だが P は偽。従って W から P への含意は成立せず、P は最弱でない。Lean の `b01` は十分性と境界での反例を検査する。
<!-- solution-end -->

### LVT3-08-B02 分岐を含む逆向き計算

自然数 n が 3 以上なら 1 を加え、それ以外なら 2 を加える。結果が 4 以上となる最弱事前条件を求めよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

[逐次実行と分岐の逆向き計算](#prop-lvt3-08-seq)を用いる。n ≥ 3 の枝では n + 1 ≥ 4 が必ず成立する。n < 3 の枝では n + 2 ≥ 4、すなわち n ≥ 2 が必要なので n = 2 に限られる。二枝を合わせると n ≥ 2。n = 0,1 では結果が 2,3 なので不足し、n = 2 では 4、n ≥ 3 では 4 以上。Lean の `b02` は分岐の全入力について同値を検査する。
<!-- solution-end -->

### LVT3-08-B03 不変量を壊す変異

加算ループの更新を a ← a + x + 1 に変更する。処理済み列の和が累積値に等しいという不変量について、初期化・保存・終了のうち、どの条件が壊れるか。入力 [2] で反例を示せ。

- Level: B

<!-- solution-start -->
#### 詳細解答

初期化では処理済み列 [] の和は 0 で、累積値 0 と一致する。保存を検査するため x = 2 とする。更新後の累積値は 0 + 2 + 1 = 3、処理済み列 [2] の和は 2 だから等しくない。[有限走査のループ不変量と検証条件](#def-lvt3-08-vc)の保存条件が偽となる。終了時に不変量が成立すると仮定すれば依然として正しい和が得られるが、変異ではその仮定を導けない。実際 [2] の出力は 3 で正しい値 2 ではない。Lean の `b03` はこの反例を検査する。
<!-- solution-end -->

### Level C

### LVT3-08-C01 一般の初期値を持つ加算ループ

初期累積値を k として、配列全体の和に k を足した値を返すことを三つの検証条件と停止性から証明せよ。空配列も含めること。

- Level: C

<!-- solution-start -->
#### 詳細解答

処理済み列 p と残り列 s を取り、元の列 L = p ++ s、累積値 a = k + sum(p) を条件 I とする。初期 p = []、s = L、a = k で、[] ++ L = L、k + sum([]) = k + 0 = k。保存では s = x :: t、次状態 p' = p ++ [x]、s' = t、a' = a + x。連結の結合性により p' ++ t = p ++ (x :: t) = L。また [配列の加算ループの正当性](#prop-lvt3-08-sum)の和の関係 sum(p ++ [x]) = sum(p) + x を使うと a' = (k + sum(p)) + x = k + (sum(p) + x) = k + sum(p')。終了条件 s = [] では p = L より a = k + sum(L)。残り列の長さは各回ちょうど1減り、最初に有限な長さであるため停止する。[有限走査の検証条件の十分性](#prop-lvt3-08-loop)から全入力で目的の値を返す。L = [] ならループは0回、直ちに k = k + 0 を返す。Lean の `c01` は同じ初期値の一般化を `vcgen` で証明した `seededLoop_correct` を適用する。
<!-- solution-end -->

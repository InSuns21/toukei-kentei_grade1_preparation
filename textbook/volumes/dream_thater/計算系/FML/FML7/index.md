# FML7 研究論文の形式化・自然言語との照合・証明監査

前提：[FML3](../FML3/index.md)、[FML4](../FML4/index.md)、[FML5](../FML5/index.md)、[FML6](../FML6/index.md)、[ACOMP6](../../ACOMP/ACOMP6/index.md)、[ACOMP7](../../ACOMP/ACOMP7/index.md)、[ACOMP8](../../ACOMP/ACOMP8/index.md)。

前講では出題側と解答側の形式的な定理を比較しました。しかし研究論文の出発点は通常、自然言語と数学記号で書かれた文章です。証明の検査が成功しても、実際に証明した命題が論文の命題より弱ければ、論文全体が証明されたことにはなりません。本講では小さな算術回路の主張を作り、紙上の証明、形式的な命題、検証の証拠を対応させます。

## 1. 論文の主張から検査対象を取り出す

次は実在の未解決問題を引用したものではなく、本講のための模擬論文の主張です。本講でいう自然数（Lean の `Nat`）は非負整数を指し、数学記号では $\mathbb N_0=\{0,1,2,\ldots\}$ と書きます。添字 n は加法ゲートの段数、x は入力値です。

「任意の非負整数 n に対して、自然数 x を入力とし、定数入力や乗法ゲートを使わず、加法ゲートをちょうど n 個用いて、すべての入力 x に対して $2^n x$ を出力する共有付き算術回路が存在する。」

[FML3の型付き算術命令列](../FML3/index.md#def-fml3-program) では、既に計算したレジスタを複数回参照できます。例えば入力をレジスタ0に置き、レジスタ1に入力と入力の和、レジスタ2にレジスタ1とレジスタ1の和を置けば、加法は2回です。値が2回使われても、レジスタ1の計算を2回行う必要はありません。

自然言語の文を次のように分解します。

| 項目 | 固定する内容 |
| --- | --- |
| 入力・添字 | n, x は自然数（0を含む） |
| 量化順序 | 各 n に対して一つの回路を作り、その回路を任意の x で評価 |
| 演算モデル | 共有可能な二入力加法ゲート、入力は無料、乗法なし |
| 結論 | ゲート数が n、評価値が $2^n x$ |
| 主張しないこと | 最小性、任意の体での形式多項式の等式、ビット計算時間 |

量化順序は [数学的主張の条件と適用範囲](../FML5/index.md#def-fml5-claim) に従って確認します。各入力 x に合わせて回路を選び直す証明ではなく、n のみで決まる回路が必要です。

## 2. 回路を明示して証明する

共有可能な回路のうち、直前の値を二つの入力端子へ接続して加算する操作だけを繰り返すものを考えます。回路の構文を入力 I と、回路 p に一つの加法ゲートを接続する D(p) で作ります。D(p) は p のコピーを二つ作るのではなく、p の一つの出力を共有します。この違いを演算数の漸化式に反映させます。g(p) は入力値に依存しないゲート数、E(p,x) は p に x を入力した出力値です。どちらも非負整数です。

<a id="def-fml7-doubling-circuit"></a>

<!-- formal-statement-start -->
### 定義（反復加算回路）

反復加算回路の集合は入力 I を含み、回路 p から D(p) を作る操作で生成される有限構文の集合とする。自然数 x における評価値 E と加法ゲート数 g を再帰的に次のように定める。

$$
g(I)=0,\qquad E(I,x)=x,
$$

$$
g(D(p))=g(p)+1,
$$

$$
E(D(p),x)=E(p,x)+E(p,x).
$$

D(p) では p の出力を共有し、p のゲートは一組だけ数える。
<!-- formal-statement-end -->

<!-- definition-example-start: def-fml7-doubling-circuit -->
**定義の確認**　$p=D(D(I))$ を取ります。I は生成規則の出発点で、D を2回適用した有限構文です。g の再帰式を内側から適用すると、

$$
g(D(I))=g(I)+1=1,\qquad
g(p)=g(D(I))+1=2.
$$

入力を $x=3$ に固定し、E の再帰式を同じ順に適用します。

$$
\begin{aligned}
E(I,3)&=3,\\
E(D(I),3)&=3+3=6,\\
E(p,3)&=6+6=12.
\end{aligned}
$$

第1段の値6を両端子へ渡すため、第2段の追加ゲートは一つだけです。生成規則、共有によるゲート数、評価値のすべてを定義どおりに確認できました。
<!-- definition-example-end -->

任意の有限構文について評価値をゲート数だけで表せれば、各段を実行しなくても出力を特定できます。

<a id="thm-fml7-doubling-evaluation"></a>

<!-- formal-statement-start -->
### 定理（反復加算回路の評価と演算数）

任意の[反復加算回路](#def-fml7-doubling-circuit) p と任意の非負整数 x について、次が成り立つ。

$$
E(p,x)=2^{g(p)}x.
$$
<!-- formal-statement-end -->

見取り図：I では指数は0です。D を一回追加すると、評価値は2倍になりゲート数は1増えるので、等式が保たれます。

<!-- proof-start -->
### 証明

[反復加算回路](#def-fml7-doubling-circuit) の生成規則について構造帰納法を行う。I に対しては g(I)=0 だから、

$$
2^{g(I)}x=2^0x=1x=x=E(I,x).
$$

回路 p で等式が成り立つと仮定する。共通因子を分配法則でくくり、指数を1増やす計算は次の通りである。

$$
\begin{aligned}
E(D(p),x)
 &=E(p,x)+E(p,x)\\
 &=2^{g(p)}x+2^{g(p)}x\\
 &=2^{g(p)}(x+x)\\
 &=2^{g(p)}(2x)\\
 &=(2^{g(p)}\cdot2)x\\
 &=2^{g(p)+1}x\\
 &=2^{g(D(p))}x.
\end{aligned}
$$

最後の等号はゲート数の再帰式による。任意の有限構文は I から有限回 D を適用して得られるので、すべての回路について等式が成立する。
<!-- proof-end -->

例えば3段なら $g=3$ で、入力5は $5\to10\to20\to40$ と変わります。計算結果は $2^3\cdot5=40$ と一致します。

元の模擬論文では回路の存在まで要求されていました。n のみから回路を作る手続き B を、B(0)=I、B(n+1)=D(B(n)) と定めます。

<a id="prop-fml7-doubling-family"></a>

<!-- formal-statement-start -->
### 命題（指定長の反復加算回路の存在）

任意の非負整数 n について、[反復加算回路](#def-fml7-doubling-circuit) の生成規則に従って B(0)=I、B(n+1)=D(B(n)) で定める回路 B(n) は、次の二条件を満たす。

$$
g(B(n))=n,
$$

$$
\forall x\in\mathbb N_0,\quad E(B(n),x)=2^n x.
$$
<!-- formal-statement-end -->

見取り図：まず n に関する帰納法でゲート数を確定し、その値を評価の定理へ代入します。回路 B(n) は x を参照していません。

<!-- proof-start -->
### 証明

[反復加算回路](#def-fml7-doubling-circuit) のゲート数の再帰式を用いる。n=0 では B(0)=I より g(B(0))=0 である。g(B(n))=n と仮定すると、

$$
g(B(n+1))=g(D(B(n)))=g(B(n))+1=n+1.
$$

従ってすべての n について g(B(n))=n が成り立つ。任意の x を取り、[反復加算回路の評価と演算数](#thm-fml7-doubling-evaluation) に p=B(n) を代入すると、

$$
E(B(n),x)=2^{g(B(n))}x=2^n x.
$$

同じ B(n) で任意の x に対して等式が成り立つので、所望の量化順序で存在が示された。
<!-- proof-end -->

「ちょうど n 個を使う回路を構成した」と「どんな回路も n 個以上必要」は違います。後者には許す全回路に対する下界証明が必要です。また演算数をビット計算時間と同一視できません。自然数の値が大きくなるほど二進表示の桁数も増えるからです。

## 3. Lean の型に対応させる

[定理ステートメント照合](../FML6/index.md#def-fml6-statement-matching) を行う前に、模擬論文の各項目に対応する型を決めます。[Challenge.lean](lab/Challenge.lean) は出題用の型と定義を保持し、[Solution.lean](lab/Solution.lean) は同じ定義と証明を保持します。

```lean
inductive Circuit where
  | input
  | double (p : Circuit)

def gates : Circuit → Nat
  | .input => 0
  | .double p => gates p + 1

def eval : Circuit → Nat → Nat
  | .input, x => x
  | .double p, x => let v := eval p x; v + v

def build : Nat → Circuit
  | 0 => .input
  | n+1 => .double (build n)
```

`Circuit` の二つの構成子は I と D に対応します。`gates p` は g(p)、`eval p x` は E(p,x)、`build n` は B(n) を表します。Lean では関数適用を空白で書くので、`eval p x` は回路 p と入力 x を順に渡すという意味です。`Nat` は $\mathbb N_0$ に対応します。`let v` は数学的な共有ゲートの値を表し、Lean の実行時間の計測値を表すものではありません。例えば `eval (.double p) x` は `eval p x` を v として v+v を返し、E(D(p),x)=E(p,x)+E(p,x) に対応します。`build` は x を引数に取らないので回路の選択が入力値に依存しません。

検査対象の型は次の三つです。

```lean
theorem value (p : Circuit) (x : Nat) :
    eval p x = 2 ^ gates p * x := ...
theorem sizeBuild (n : Nat) : gates (build n) = n := ...
theorem family (n x : Nat) :
    gates (build n) = n ∧ eval (build n) x = 2 ^ n * x := ...
```

上の省略記号は型の読解用であり、実際に実行する証明は Solution.lean にあります。`^` と `*` はここでは非負整数のべき乗と乗法で、`∧` は二つの命題の連言です。value の帰納段階では紙上と同じ順序で、帰納法の仮定による書き換え、Nat.mul_add の逆向きの分配、Nat.two_mul、Nat.pow_succ、Nat.mul_assoc を使用します。sizeBuild は n の帰納法です。family の連言の左辺は sizeBuild n、右辺は value (build n) x の右辺に sizeBuild n を代入したものです。

注意すべき点は family の量化だけを眺めると n と x の後に結論が置かれていることです。実際の存在の証人 build n が x に依存しないことを定義と型の両方から確認して、元の主張へ戻します。

## 4. 反例を使って、証明された範囲を区別する

型の照合、カーネルによる検査、論文の文章との対応は異なる問いです。

- [Mismatch.lean](lab/Mismatch.lean) は family に h : n = 0 を追加します。n=2 の場合は 2=0 の証明を渡せないため、その定理の型だけでは n=2 の結論を直接得られません。等式自体は真でも、提出された型は出題と異なります。
- [ForbiddenAxiom.lean](lab/ForbiddenAxiom.lean) は family と同じ型の externalProof を公理として宣言し、それを family の証明値にします。型は一致していても、[数学的証明の許容公理集合](../FML5/index.md#def-fml5-policy) の外に依存します。

論文が形式多項式について述べている場合には、入力の自然数での評価だけを検査することは一般には十分ではありません。[二元体での形式多項式と評価の不一致](../FML3/index.md#prop-fml3-finite-field) を振り返ると、二元体上の $X^2-X$ は係数が非零であるにもかかわらず、入力0と1の両方で0になります。評価関数の一致を形式多項式の一致と取り違えると、この区別が失われます。本講の Lean 定理の定義域は Nat であり、任意の体の多項式環の定理ではありません。

また [VP](../../ACOMP/ACOMP6/index.md#def-acomp6-vp) では固定した体の形式多項式族、変数数・次数・演算サイズの多項式上界を扱います。例えば有理数体上の多項式族 $f_n(X)=2^nX$（VP の定義に合わせて $n\geq1$）については、同じ加算構成を形式多項式環で行えば演算数 n、変数数1、次数1の上界を得ます。ここで X は評価する数値ではなく不定元です。紙上での計算は I の値 X を起点に、D を追加するたびに係数が2倍になるためです。従ってこの族が VP に入るという別の数学的結論が得られますが、上の Nat の Lean 型には多項式環も VP の定義もありません。

[Boolean和](../../ACOMP/ACOMP7/index.md#def-acomp7-boolean-sum) や [p-projection](../../ACOMP/ACOMP8/index.md#def-acomp8-p-projection) による研究主張を検査するときも、和の添字集合や置換先、族の添字とサイズの上界を形式的な型のどこで担保したかを調べます。特定の回路の形式検証だけで VP と [VNP](../../ACOMP/ACOMP7/index.md#def-acomp7-vnp) の分離を結論することはできません。

## 5. 証拠を記録して、他者が再検査できるようにする

論文のどの主張について何が分かったかを記録しましょう。[定理ステートメント照合](../FML6/index.md#def-fml6-statement-matching)、[許容公理集合](../FML5/index.md#def-fml5-policy)、[複数カーネルによる受入条件](../FML6/index.md#def-fml6-multikernel) は別々の確認項目を持ちます。それらを一つの「証明済み」の欄にまとめると、後でどの条件が未確認なのか分からなくなります。証明の依存先や自然言語との照合も含めて記録する表を用います。

<a id="def-fml7-proof-ledger"></a>

<!-- formal-statement-start -->
### 定義（証拠台帳）

検査対象の各主張について、原文の位置と意味、形式的な宣言名および参照定義、仮定と依存公理、検査に使う固定版のソース・実行手順・結果、自然言語との対応を確認した主体、未検証の範囲を対応付けた記録を証拠台帳（proof ledger）とする。各検査の成功・失敗・未実施を区別して記録する。
<!-- formal-statement-end -->

<!-- definition-example-start: def-fml7-proof-ledger -->
**定義の確認**　次は模擬論文用の台帳です。各行には主張の位置と宣言、依存、対応関係を記録します。ここでは紙上の対応だけを確認し、実行ログをまだ得ていない場合を例に取ります。型・公理・カーネルの三検査はそれぞれ未実施と記録し、ログ取得後に個別に成功または失敗へ更新します。

| 原文の主張 | 宣言名・依存 | 紙上の対応確認 | 型・公理・カーネルの状態 |
| --- | --- | --- | --- |
| 任意の p, x で評価式成立（第2節） | FML7.value、gates・eval | 自然数の構造帰納法を照合 | 未実施・未実施・未実施 |
| B(n) のゲート数 n（第2節） | FML7.sizeBuild、build・gates | n の帰納法を照合 | 未実施・未実施・未実施 |
| 任意の入力に同じ回路を使える（第1節） | FML7.family、上の二定理 | build が x を取らないことを確認 | 未実施・未実施・未実施 |

共通の環境は Lean 4.35.0、外部パッケージなし、許容公理は propext・Quot.sound・Classical.choice です。固定ソース、出題設定、実行コマンドは次節に示します。例えば value の型が一致しても、許容外公理が検出されたならその行は「型：成功、公理：失敗、カーネル：未実施」と記録します（カーネルの検査を実行していない場合）。三条件のうち一つでも失敗または未実施なら、三条件すべての受入は確認できていません。別の人による論文読解、任意の体の形式多項式での定理、回路下界、出版による査読はこの台帳の検証済み範囲に含めません。検査を行った主体の名前、コミット、実行結果は読者自身の検査時に記録します。
<!-- definition-example-end -->

[FML6の複数カーネルによる受入条件](../FML6/index.md#def-fml6-multikernel) を用いて、型・公理・検査器の結果を個別に記録します。例えばすべての形式検査が成功しても、自然言語の原文を読み間違えれば論文についての結論は保証されません。反対に形式化が未提出でも、人間の証明が偽だと決まるわけではありません。

研究報告を読む際には次の状態を区別します。

1. プレプリントの主張
2. 形式的な証明データの公開
3. 正しい出題型の照合
4. 公理・カーネルの検査
5. 別の人による数学的読解
6. 査読・出版の状態

AIによる証明探索もこの区別を変えません。

## 6. 実行による検査

[FML6の検査手順](../FML6/index.md#def-fml6-multikernel) と同じ Lean 4.35.0 固定の Comparator を使用します。Linux の非特権環境で bubblewrap を用意し、次を実行します。未信頼の入力は秘密情報を持たない隔離環境で扱います。

```bash
cd "textbook/volumes/dream_thater/計算系/FML/FML7/lab"
bash verify.sh
```

[comparator.json](lab/comparator.json) で対象の三定理を固定します。[verify.sh](lab/verify.sh) は各試行を別の一時ディレクトリで開始し、旧 .lake を利用しません。正例は lake comparator --paranoid を実行して nanoda の受理と成功メッセージを確認します。負例は単独でビルドできることを確認した後、型または公理の不一致で拒否されることをログから確認します。

| ファイル | 期待する結果 |
| --- | --- |
| Solution.lean | 三定理の型・参照定義・公理条件・独立検査が一致 |
| Mismatch.lean | family の型が異なるので拒否 |
| ForbiddenAxiom.lean | externalProof が許容外なので拒否 |

失敗が依存取得やコンパイルエラーなら、型の不一致を検出した証拠にはなりません。終了コードだけでなく該当する診断を読みます。実行ログはスクリプト冒頭の表示先に保存されます。固定版、実行結果、対象宣言名、ソースのコミットを先の[証拠台帳](#def-fml7-proof-ledger)に記入すれば、他者も同じ検査を再現できます。

## 7. 演習

### Level A

### FML7-A01 回路の評価

p=D(D(D(I)))、x=7 のとき、各段の値とゲート数を求めよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

[反復加算回路](#def-fml7-doubling-circuit) の生成順に評価する。I は入力7、ゲート数0。第1段は7+7=14、ゲート数1。第2段は14+14=28、ゲート数2。第3段は28+28=56、ゲート数3である。[評価と演算数の定理](#thm-fml7-doubling-evaluation) へ g(p)=3、x=7 を代入しても $2^3\cdot7=8\cdot7=56$ となる。
<!-- solution-end -->

### FML7-A02 量化と証人

「各 n について全 x で使える回路が存在する」と「各 n, x についてその x で使える回路が存在する」の違いを説明せよ。B(n) はどちらを満たすか。

- Level: A

<!-- solution-start -->
#### 詳細解答

前者は n を選んだ後に回路を固定し、x を自由に動かしても正しいことを要求する。後者では x を見た後で回路を選べる。前者から後者は回路を使い回すことで従うが、逆方向には x に依存する証人を一つへまとめる根拠がない。[指定長の反復加算回路の存在](#prop-fml7-doubling-family) の証人 B(n) は n だけで構成され、すべての x で評価式が成り立つため前者を満たし、従って後者も満たす。
<!-- solution-end -->

### FML7-A03 追加仮定

family の型に h : n = 0 を付けた定理を n=2、x=3 に適用しようとした。何が起こるか。

- Level: A

<!-- solution-start -->
#### 詳細解答

元の型には n=2、x=3 を渡すだけでゲート数2と評価値 $2^2\cdot3=12$ が得られる。変更型ではさらに h : 2 = 0 を要求する。2と0は異なる自然数なのでその証明は提供できない。[定理ステートメント照合](../FML6/index.md#def-fml6-statement-matching) は証明値ではなく型も検査するため、正しい等式を含んでいても変更型は拒否する。
<!-- solution-end -->

### FML7-A04 公理と証明

family の証明値を許容集合に含まれない externalProof n x に置き換えたとき、型の照合と公理条件の判定を説明せよ。

- Level: A

<!-- solution-start -->
#### 詳細解答

宣言の型と gates・eval・build の定義を保持するなら、[定理ステートメント照合](../FML6/index.md#def-fml6-statement-matching) の条件は満たす。しかし証明値が externalProof に依存し、指定集合 S に externalProof は含まれないため、依存公理集合は S の部分集合ではない。[許容公理集合](../FML5/index.md#def-fml5-policy) の条件は失敗する。型の一致を公理条件の成功に置き換えてはいけない。
<!-- solution-end -->

### Level B

### FML7-B01 共有を禁止した場合の演算数

B(n) の各 D で前段の回路を複製し、二つの式の木を別々に計算するモデルを考える。加法数 t(0)=0、t(n+1)=2t(n)+1 とする。t(n) を求め、共有を許すモデルと比較せよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

n=0 では $t(0)=0=2^0-1$ である。$t(n)=2^n-1$ と仮定すると、

$$
\begin{aligned}
t(n+1)&=2t(n)+1\\
 &=2(2^n-1)+1\\
 &=2^{n+1}-2+1=2^{n+1}-1.
\end{aligned}
$$

帰納法で $t(n)=2^n-1$ を得る。[指定長の反復加算回路の存在](#prop-fml7-doubling-family) では共有を許すのでゲート数は n である。n=3 では共有が3、複製では7。値の等しさは演算モデルの等しさを意味しない。
<!-- solution-end -->

### FML7-B02 形式多項式の範囲

有理数体上の形式多項式 $f_n(X)=2^nX$ が VP に入ることを紙上で示し、FML7.family がそのままこの結論の Lean 証明ではない理由を説明せよ。ただし VP の族の添字は $n\geq1$ とする。

- Level: B

<!-- solution-start -->
#### 詳細解答

有理数体の多項式環で入力を X とする。0段で値は X、n 段で $2^nX$ と仮定すると次段は

$$
2^nX+2^nX=2^{n+1}X.
$$

共有ゲートは各段一つなので、0段で0、n段で n 個なら次段で n+1 個となる。従って各 n の形式多項式を n 個の加法ゲートで計算できる。係数 $2^n$ は有理数体で非零なので次数は1、変数数は1であり、正整数 n に対して変数数1、次数1、演算サイズ n はすべて n 以下である。したがって A=1、k=1 を共通の上界の定数として取れる。[VP の定義](../../ACOMP/ACOMP6/index.md#def-acomp6-vp) をこの族へ適用できる。一方 FML7.family は Nat 上の評価値と自然数のゲート数の型であり、形式多項式環・有理数体・次数境界を表す型を含まない。紙上の VP の主張とは別の形式化が必要である。
<!-- solution-end -->

### FML7-B03 Boolean和を使う主張の照合

有理数体上で $g(X,Y)=X+Y$ とする。「Y を0と1で評価して足した形式多項式は $2X+1$ である」という主張を計算し、Y=0 の場合だけを証明した型が不足する理由を述べよ。

- Level: B

<!-- solution-start -->
#### 詳細解答

[Boolean和](../../ACOMP/ACOMP7/index.md#def-acomp7-boolean-sum) の定義に体 $K=\mathbb Q$、主変数 X が1個、補助変数 Y が1個の場合を代入する。Y の値だけを0と1に変え、X は不定元のまま固定する。g(X,0)=X、g(X,1)=X+1 なので、

$$
g(X,0)+g(X,1)=X+(X+1)=2X+1.
$$

Y=0 の評価だけを証明したなら右辺は X であり、Y=1 の項がない。例えば X=0 では不足した式が0、求める和が1で異なる。必要な型には両評価とその和、そして結果が形式多項式として等しいことを含める。FML7.family はこの命題を検査していない。
<!-- solution-end -->

### Level C

### FML7-C01 模擬論文の受入判定

第1節の模擬論文を対象に、ある報告が「n=3、x=4 で出力32、ゲート数3を確認した。さらに family に h : n=0 を付けた定理を検査した」と述べた。正しいかどうかを計算し、元の主張を受け入れるための台帳と負のテストを設計せよ。

- Level: C

<!-- solution-start -->
#### 詳細解答

まず B(3) の評価を [反復加算回路](#def-fml7-doubling-circuit) の再帰式で計算する。4から8、16、32となり、追加ゲートは各段一つで計3である。数値報告は正しい。しかし一つの入力での結果は全 n, x の等式ではない。変更定理は n=3 を渡すと h : 3=0 を要求するので、この型をそのまま適用できないため、正しい数値例についても結論を直接得られない。

[証拠台帳](#def-fml7-proof-ledger) を次のように組み立てる。出題型は FML7.value、FML7.sizeBuild、FML7.family とし、Circuit・gates・eval・build の定義を出題側で固定する。人による照合では n と x が Nat、build が x を取らず、gates が入力を0と数え、D ごとに1を加えることを確認する。

次に value の帰納段階では、帰納法の仮定を二つの評価値へ適用して

$$
\begin{aligned}
E(D(p),x)&=E(p,x)+E(p,x)\\
&=2^{g(p)}x+2^{g(p)}x\\
&=2^{g(p)}(x+x)\\
&=2^{g(p)}(2x)=2^{g(p)+1}x.
\end{aligned}
$$

を得る。sizeBuild については g(B(0))=0 と g(B(n+1))=g(B(n))+1=n+1 を確認する。[反復加算回路の評価と演算数](#thm-fml7-doubling-evaluation) に対応する value に p=B(n) を代入し、得た指数 g(B(n)) を sizeBuild により n に置き換える。これで [指定長の反復加算回路の存在](#prop-fml7-doubling-family) に対応する三宣言が必要な理由が分かる。

固定した出題と別環境で解答をビルドし、[複数カーネルによる受入条件](../FML6/index.md#def-fml6-multikernel) で照合する。正例 Solution では三定理の型と定義の一致、許容公理への包含、独立カーネルの受理を確認する。Mismatch は単独ビルド後、family の型に余分な h があることを診断させる。ForbiddenAxiom は型が一致しても externalProof の公理条件で拒否されることを確認する。いずれもログ・ソースのコミット・実行環境と検査した主体を記録する。

この報告だけでは元の全称主張の受入は未確認である。正例が三検査を満たし、別途自然言語の対応を確認できれば模擬論文の限定された主張に対する証拠になる。一般の多項式族、最小性、独立した人間の査読や出版については別項目として扱う。
<!-- solution-end -->

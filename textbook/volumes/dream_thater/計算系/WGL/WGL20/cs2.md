# CS2 建物属性・都市描画性能：意味のある色とdraw call

[WGL20の実在データ](index.md#def-wgl20-audit)はサンプルの一棟だけであり、利用できる属性 measuredHeight は14.5 mです。属性が存在する場合の色づけと、**属性が存在しない建物への決めつけ**を区別します。今回は大量の建物を所有していないため、属性に基づく「用途別分類の精度」や地区全体の統計を作ったとは主張しません。

このプリセットでは、同じ88三角形を**一回の建物draw call**で送る場合と、88三角形を11三角形ずつに分けて**8回の建物draw call**で送る場合を比較します。両方で頂点とGLSLの出力が同一なので、理想的には幾何画素は変わりません。これは異なる建物のインスタンス描画ではありません。[WGL16のインスタンス描画](../WGL16/index.md#def-wgl16-instance)と、単に一棟のメッシュを複数回へ分割することは別の操作です。

1. CS2初期実行では、地形1回、建物8回、水面1回、検算帯1回で**合計11回**の表示draw callが発行されます。ID用の別パスはCS1のみなのでこの回数には入りません。
2. terrain.js の scenario を BASE へ変えると、地形1回、建物1回、水面1回、帯1回の**合計4回**です。同じ地形・建物・水面であれば理想の画素は同一です。カラーの違いも生じる場合、scenario依存の fragment shader 内 u_attributeMode を統一してから比較します。
3. code欄の「実在属性14.5 m」報告と「建物形状の最大Z差」を区別します。用途コード402の具体的な利用用途名称をコード表未確認のまま断定しません。属性値が未記録だったなら「欠測」と表示し、0 mへ勝手に置き換えてはいけません。
4. WebGL2のdraw callの回数からフレームレートが必ず何倍になるかは分かりません。実際に計測する場合は、端末・ブラウザ・解像度・試行回数・温度/省電力設定を記録し、[WGL19のCPU/GPU時間区別](../WGL19/index.md#def-wgl19-audit)を守ります。

## 数値の検算

単一建物の1パス描画は88三角形 $=264$ 頂点参照です。8分割なら各11三角形 $=33$ 頂点参照で、総数 $8\times33=264$ と一致します。**幾何の総量とdraw call数の変化を別々に数えます**。建物の平均高さが14.5 mといえるわけではありません。ここにあるのは一件の measuredHeight 属性です。

**追加演習**。建物8分割のdraw call数が基礎場面4から11へ増えても、必ずフレーム所要時間が11/4倍になるとはいえない理由を述べなさい。

**詳細解答**。draw callはGPU命令の呼び出し単位ですが、フレーム時間にはJS処理、driver overhead、頂点処理、ラスタ化、GPU同期、画面更新などが含まれます。8分割でも総頂点参照264、総三角形88は同じです。描画命令部分が支配的なら呼び出し数の増加が影響し得ますが、固定費やGPU描画処理が支配的なら単純な11/4倍にはなりません。実測の平均・ばらつきと測定条件を記録すべきです。

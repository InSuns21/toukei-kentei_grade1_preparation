# CS1 小地区3D都市ビューア：座標・投影・選択ID

[WGL20の局所座標](index.md#def-wgl20-local)で建物と合成地面を同じ東北上メートル座標へ置きました。次は、その三次元の位置が画面のどのピクセルへ投影され、手前の建物として選ばれるかを確認します。[WGL15の画素からの射線](../WGL15/index.md#def-wgl15-unproject-ray)を再利用します。これはWGL20の必修とは別の発展実践です。

## 編集・実行ラボ

3タブのコード編集欄にある terrain.js / terrain.vert / terrain.frag が**実際の実行ソース**です。CS1プリセットでは、合成地盤と実在PLATEAU一棟を描く通常のカラー描画に加え、**透明水面を除外したRGBA8のID専用FBO**を作り、地面・道路・背景0、公式PLATEAU建物1、合成の周辺建物2を記録します。色による表示と選択IDは別です。専用FBOは深度付きで、建物の前に地面がある場所は地面が優先されます。IDパスは建物の表示色を変更しても選択IDが不変であるよう分離しました。

同じ表示画素について、CPU側では頂点を正射影して各三角形の重心座標を調べ、内部にある三角形のうち最前面の深度を選びます。GPUではID FBOの readPixels を使います。**GPU画素値とCPU幾何計算は別のアルゴリズム**ですが、両者が同じ座標変換設定を使うため、入力のCRSが誤っていれば双方同時に誤る可能性が残ります。そのため [WGL20本文の実測座標由来の独立チェック](index.md#def-wgl20-audit)も必要です。

1. まず初期ソースを実行し、合成街区の道路・建物9棟・仮想水面を観察します。黄土色の公式1棟と灰白色の合成8棟を区別します。最下部の凡例4点は地理空間ではないため、そこで選択するのではなく黄土色の公式建物または灰白色の合成建物をクリックします。
2. 描画canvasをクリックし、表示される **GPU ID／CPU三角形のID** を比較します。キーボードからはcanvasへフォーカスし矢印で位置を動かし、EnterまたはSpaceで選択できます。
3. terrain.js の usePlateau を false へ変更します。公式建物を消したときにID1が返れば不整合です。周囲の合成建物ID2は残ります。描画へ戻すときは初期化します。
4. Z誇張を変え、同じ画素でも投影される形が変わることを確認します。頂点元データの標高自体は変えません。
5. terrain.vert の投影式を変更した後はCPU側の投影と同じ変換でなくなるため、GPU/CPUの不一致が出得ます。この**不一致は監査の出発点**であり、CPUの計算をGPUに合わせてこっそり改変してはいけません。

## 手計算と独立監査

画素幅を $W$、高さを $H$、左下原点の画素整数添字を $(i,j)$ とすれば、画素中心の正規化デバイス座標は[WGL15の命題](../WGL15/index.md#prop-wgl15-pixel-bounds)から

$$
x_{\mathrm{ndc}}=\frac{2(i+1/2)}W-1,\qquad
y_{\mathrm{ndc}}=\frac{2(j+1/2)}H-1.
$$

正射影された三角形の頂点 $A,B,C$ と画素中心 $P$ について重心座標 $\alpha,\beta,\gamma$ がすべて非負か確認し、$z=\alpha z_A+\beta z_B+\gamma z_C$ が最も手前の三角形を選びます。GPUは三角形の辺上を[ラスタ化規則](../WGL6/index.md#def-wgl6-front-face)で割り当てるため、ちょうど輪郭にある画素はCPUの幾何学的境界と一致しない場合があります。内側の代表画素と輪郭画素を分けて報告します。

**追加演習**。建物上の画素でCPU=1、GPU=0となったとき、(a) ID FBOの深度状態 (b) device pixelへの変換 (c) 三角形の画面内外 (d) local座標の東北の符号、を順に切り分けなさい。

**詳細解答**。(a) 深度が無効なら後描き地物が選択を上書きし得ます。(b) CSS幅ではなく実際の幅 $W$ で添字を求める必要があります。(c) CPU重心座標の各符号とGPUの辺規則を比較します。(d) 最後に[局所変換](index.md#def-wgl20-local)の緯度・経度軸順と元GMLを照合します。どれかの検査が未達なら「実データの選択が正しい」と宣言しません。

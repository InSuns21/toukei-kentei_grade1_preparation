# DREAM THEATER 数学図 SVG 品質ガイド

本書は [DREAM_THEATER_AUTHORING_STANDARD.md](DREAM_THEATER_AUTHORING_STANDARD.md) §4.1.1 の実装ガイドであり、同節の数学・教育上の完成条件を緩和しない。ベクトル解析・微分幾何・力学・グラフ・可換図式など、図によって空間的関係を学ぶ箇所を対象にする。SVGソースがlintに通るだけでは完成ではない。

## 1. 生成前に図の意味と対象を設計する

1. **学習者の問いを1文で書く**：例「なぜ曲面の向きを反転すると境界の正向きが逆になるのか」。
2. **数学的な不変条件を書き出す**：座標の基点、法線と接ベクトルの関係、曲線と境界の一致、矢印の始終点、正負の向き、対応する本文の式、定性的な概念図か厳密な具体例か。
3. **必要なオブジェクトを棚卸しする**：点・線・面・流線・軸・接ベクトル・法線・短い局所ラベル。まず全体の配置とラベル位置を設計する。図内の長文説明はMarkdownへ出す。
4. **同じ現象を一つの図で理解できる配置を優先**：独立パネルを増やす前に余白、角度、補助線、引出線、非色手掛かりを調整する。意図しない重なりの回避のために作用点や幾何関係を偽らない。
5. **図と本文の責務を分ける**：図に論証や仮定を押し込まず、本文では参照箇所の前後に何を見るべきかを記す。

### 数学図に特有の反証テスト

- 「曲面らしい絵」だけで**接空間が同じ周囲空間に含まれる**ことを暗黙に仮定していないか。一般の多様体の図は局所座標モデルか埋め込みの具体例かを明示する。
- 3次元の見た目の曲がりを**内在曲率**と同一視していないか。
- `n`, `dS`, 接ベクトル、接線、ベクトル場の矢印が**正しい点と方向**に結び付いているか。
- Stokes・Gauss・Green の法線、境界向き、座標系の向きの対応は右手系・境界の誘導向きと整合しているか。
- 勾配は等位面へ垂直か。発散と回転は同一の流線パターンで無理に説明していないか。
- 図示した具体的な関数、曲線、曲面が本文の定義域、正則性、向き、特異点の有無と一致するか。

## 2. SVGの構造

- 章固有の原典を原則として `<chapter>/assets/<meaningful-name>.svg` に保持する。生成スクリプトを使う場合は再生成可能なソースも保存する。
- ルートの `xmlns="http://www.w3.org/2000/svg"`、有限で正の大きさの `viewBox`、`data-layout-lint="strict"` を指定する。
- `<title>` は短い図名、`<desc>` は**方向・位置・対応関係を文章化した説明**とする。本文の `![...](assets/....svg)` のaltも図の意味を表す。単なる「図」「SVG」「イメージ」は不可。
- `<defs>` に矢印マーカー等をまとめ、図形・ベクトル・補助線・短いラベルを意味別にグループ化する。描画順による隠れを実表示で確認する。Web開発用フローチャートの固定レイヤー順を数学図へ機械的に適用しない。
- `id` の重複、未解決 `url(#id)`・`href="#id"` を作らない。スクリプト・外部資産・`foreignObject`・イベントハンドラ・外部URLには依存しない。
- 同じ比較グループのベクトル／曲線には `data-series-group` と `data-series-label` を付け、色以外に線種、線幅、矢印・点記号などの識別を持たせる。**色は識別の補助であり唯一の根拠ではない**。
- 線や文字の交差を検査に見つけさせたくないからと `data-layout-ignore` を付けない。数学的に意味のある交差だけ `data-layout-ignore="text-overlap: <specific reason>"` として対象要素単位で記録し、人手でその意味を確認する。

## 3. 作図と検査の反復

1. SVGを生成し、`npm run validate:svg-layout:changed -- --base <sha>` と `npm run validate:svg-quality:changed -- --base <sha>` に通す。ローカル単体確認には `node scripts/validate-svg-quality.mjs --file <path.svg>` を使う。
2. 実際のブラウザ相当のレンダラーで画像化し、**通常本文幅と幅360px程度の小画面**で表示確認する。必要ならSVGを2倍表示してラベル・線幅・矢印先端を確認する。
3. モノクロ（彩度を落とした表示）で系列を追い、**文字の可読性、行き先の曖昧さ、境界/矢印の切れ、余白、陰影、z-order**を確認する。
4. 数学的な具体例なら定義・式から位置関係を手で再計算する。模式図なら模式図であることを明示し、厳密でない直感を定理として印象付けない。
5. 問題を修正して再レンダリング・再検査する。CI greenと目視は相補的であり、代替しない。

## 3.1 既存図の全件監査（非ブロッキング）

既存の教材SVGは `npm run audit:svg-quality:existing` で一括点検する。検査は `textbook/volumes/**/*.svg` に含まれる既存図を列挙し、変更図と同じ構造・参照・アクセシビリティ検査を適用する。現在 `data-layout-lint="strict"` のない旧図は移行候補として警告するが、**既存の検出結果だけでCIを失敗させない**。既存図の `strict` ラベル衝突検査は従来の `validate:svg-layout`（full実行）を併用する。

出力した構造上の指摘は候補であって、検査器のXML近似による誤検出、仕様上許される配置、Markdownの画像参照表記差異を人手で仕分けする。構文の改善、色・線種の区別、数学的妥当性、モバイルでの実レンダリングは別に確認する。既存図の一括修正は重要度で小さなPRへ分け、新規図の品質ゲートを弱めない。

## 4. 機械検査の分担と限界

| 項目 | 自動判定 | 必要な人手確認 |
| --- | --- | --- |
| XMLタグ整合（軽量検査）、危険要素、外部参照 | 新規・変更SVGをblocking | ブラウザでの正しい解釈・セキュリティ |
| `viewBox`、名前空間、`id`、参照先 | blocking | クリッピング、markerの実表示 |
| `title` / `desc` / Markdown alt | 欠落はblocking、未使用資産はwarning | 説明が図の数学的意味を正確に述べるか |
| ラベルと線分の衝突 | 既存SVG layout lintでblocking | transform、複雑path、意図的な交差、文字の実測 |
| 非色手掛かり | シリーズ注釈に基づくblocking | グループ注釈の網羅性、色覚・白黒での識別 |
| 図中文字の長文化 | warning | 短い局所ラベルへの整理 |
| 数学的な向き・作用点・座標系 | 完全自動判定しない | 本文から再計算 |
| モバイル・白黒・縮小表示 | CIだけでは合格としない | 実画像・実ブラウザで目視 |

**注意**：軽量XML検査は正式なXML parserではない。既存の衝突lintも文字幅・曲線を近似しており、複雑なtransformやpathの重なりを完全には追跡しない。検査が静かでも表示が正しい保証にはならない。CI負債を一度に増やさないため、新しい品質ゲートは変更SVGを対象に導入し、既存資産の遡及的な一律不合格化はしない。

## 5. 外部資料から取り入れた要点

- [W3C WAI: Images tips](https://www.w3.org/WAI/tutorials/images/tips/)：SVGのテキスト代替、タイトルと参照。
- [SVG 2: Document Structure](https://www.w3.org/TR/SVG/struct.html)：記述要素、role、アクセシブルな名前。
- [Google: Diagrams and figures](https://developers.google.com/style/images)：必要なときに図を追加し、本文中で解釈可能な代替説明を付ける。
- [pkt-lab/svg-diagram Skill](https://github.com/pkt-lab/svg-diagram)：配置→構造検査→実レンダリング→視覚査読→修正の反復。ただし対象は主に構造図であり数学図には数学的な反証テストを追加する。
- [ANU-HDRH draw-diagram Skill](https://github.com/ANU-HDRH/claude-goodies/blob/main/plugins/draw-diagram/_source/SKILL.md)：意味を原典として扱い、見た目だけで意味を変えない。
- [SVGO removeViewBox](https://svgo.dev/docs/plugins/removeViewBox/)：拡大縮小・表示領域の維持。最適化でviewBoxやアクセシビリティ説明を消さない。

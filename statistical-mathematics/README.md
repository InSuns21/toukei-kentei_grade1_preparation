## 詳細解答の粒度基準

統計数理では、[フィッシャー情報量・Delta法・最尤推定量の漸近効率](core/40_fisher_information_delta_mle_efficiency.md) を**代表的な粒度の参照例**とします。

これは各ファイルを同じ文字数にするという意味ではありません。問題の難しさに応じて長短はあってよい一方、採点対象または主要論点となる計算・定理適用について、初見の受験者が詳細解答だけから次の式を再現できることを要求します。

原則として、各小問では次の流れが見えるようにします。

1. **出発点**: 定義、確率密度関数・確率質量関数、尤度、期待値、目的関数、棄却確率など、何から計算を始めるか。
2. **条件・理由**: 独立性、正規性、有限分散、内部点、フルランクなど、公式・定理を本問で使える理由。
3. **途中計算**: 微分、積分、平方完成、行列積、標準化、Taylor展開など、採点対象の変形を少なくとも再現可能な段数だけ示す。
4. **結論**: 求める推定量・分布・検定統計量・確率・解釈を明示する。

3小問以上ある問題は、原則として詳細解答にも `### 1. ...` のような小問対応見出しを置きます。複数の小問を一段落にまとめて、どこで何を導いたか分からなくしないためです。

特に次は禁止します。

- 「共役なので」「中心極限定理より」「条件付き正規公式より」だけで主要な導出を終える。
- 求めること自体が設問であるモーメント母関数・確率母関数・尤度・フィッシャー情報量などを既知公式として置く。
- 「微分すると」「整理すると」「これを解くと」の1文で、採点対象となる数段の計算を隠す。
- 漸近結果で、標準化、確率収束、剰余項の次数、定理の適用条件のいずれも示さず最終分布だけを書く。

本番答案は詳細解答より圧縮してよいですが、採点基準で独立に配点する導出の核は残します。

## ディレクトリ規約

`applied-rikou-80/` と同じく、演習の正本は `core/`, `standard/`, `advanced/` の3階層です。各大問は1題1 Markdownファイルとし、ファイル名は `<100大問No.>_<snake_case_slug>.md` に統一します。

各大問は原則として次の4区分を持ちます。

1. 問題
2. 詳細解答
3. 本番答案
4. 採点基準（20点満点）

旧分野別ファイルは内容・来歴追跡のため `sources/` に退避し、日常演習では正規化済み3階層を使用します。

## 検証

リポジトリルートで次を実行します。

```bash
npm ci
npm run validate:mathstat
npm run validate:exercise-style
npm run audit:granularity
npm run audit:terminology
```

`audit:granularity` と `audit:terminology` は失敗させる検証ではなく、行間・用語を追加確認すべきファイルを優先順位付きで抽出する監査です。検出語句だけで機械的に不合格とはしません。

リポジトリ全体の検証は次です。

```bash
npm run validate
```

数式は `$...$` / `$$...$$` を使い、KaTeX strictで通る記法を正本とします。

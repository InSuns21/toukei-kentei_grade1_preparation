## ディレクトリ規約

`applied-rikou-80/` と同じく、演習の正本は `core/`, `standard/`, `advanced/` の3階層です。各大問は1題1 Markdownファイルとし、ファイル名は `<100大問No.>_<snake_case_slug>.md` に統一します。

各大問は原則として次の4区分を持ちます。

1. 問題
2. 詳細解答
3. 本番答案
4. 採点基準（20点満点）

旧分野別ファイルは内容・来歴追跡のため `sources/` に退避し、日常演習では正規化済み3階層を使用します。

## 詳細解答の粒度

「詳細解答」は公式集ではなく、初見で答案を再現できるための導出を残す。

- 問題が「求めよ・導け・示せ」と要求した式を、詳細解答の冒頭で既知公式として置かない。
- その式が採点対象なら、定義、和・積分、変数変換、微分、平方完成、正規方程式など、得点につながる途中式を示す。
- 非自明な公式を使う場合は、問題文で「用いてよい」と明示するか、詳細解答内でその場で導出する。単に「○○公式より」「既知の結果より」で飛ばさない。
- 多段の計算では、どの恒等式・独立性・極限操作を使ったか追えるようにする。`独立性を用いて期待値を取ると` の一言で複数項の期待値計算を省略しない。
- 本番答案は圧縮してよいが、採点基準に点数が割り当てられた導出の核は残す。答えだけを書いて満点扱いにしない。
- 一方、問題文が「○○定理を用いてよい」「○○を述べよ」と明示している場合は、その定理自体の証明まで要求しない。

### 定理を使うときの必須4点

答案で定理・補題・漸近結果を使う場合は、原則として次の順で書く。

1. **定理名**: 何を使うかを明示する。
2. **必要条件**: 本問に関係する条件だけを簡潔に列挙する。
3. **条件確認**: その条件が本問で成立する理由を書く。
4. **適用結果**: 定理から何が従うかを書く。

特に次は条件確認を省略しない。

- Neyman–Fisher 因子分解定理: 共通の支配測度と因子分解。
- Rao–Blackwell / Lehmann–Scheffé: 十分性、完備性、不偏性、可積分性。
- Cramér–Rao: 共通支持、微分可能性、微分と積分・和の交換、正の有限情報量。
- MLEの漸近正規性 / Wilks / Wald / Score: 真値が内部点、識別可能性、正則性、正の有限情報量。
- CLT / Slutsky / Delta法: 独立同分布・有限分散、確率収束、微分可能性など該当条件。
- Neyman–Pearson / UMP: 単純仮説か、尤度比の単調性、サイズ条件。
- Cochran / t・F・カイ二乗の正確分布: 正規性、射影の直交性、ランク、独立性。

定理名だけを書くのも、条件だけを書くのも不十分とする。**「この問題ではなぜ使えるか」までを答案の一部**とする。

この基準は Core / Standard / Advanced の全階層に適用する。

## KaTeX検証

リポジトリルートで次を実行します。

```bash
npm ci
npm run validate:mathstat
```

リポジトリ全体の数式検証は次です。

```bash
npm run validate:math
```

数式は `$...$` / `$$...$$` を使い、KaTeX strictで通る記法を正本とします。
